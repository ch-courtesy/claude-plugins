# spec 스킬 토큰 감축 — 큰 산문 섹션 references 이관·잔여 압축

## 무엇을 만들 것인가

spec 스킬의 진입점 문서 본문을 대폭 경량화하고, 산문으로 길게 풀려 있던 큰 문단들을 별도 참조 문서로 이관한다.

스킬의 외부 계약은 변경하지 않는다:
- 입력 시그니처 (task-id, milestone, --resume)
- 행동 범위 (10단계 워크플로우, 각 단계의 책임)
- 산출물 경로·브랜치 컨벤션·슬러그 도출 규칙
- 최종 상태에서 본문·참조·검증 안전장치의 조각·이론·증거가 일치해야 한다 (drift guard)

대신 변경하는 것:
- 진입점 문서의 길이·구조와 산문의 압축
- 관련 세부가 길게 흐르던 큰 섹션 셋을 별도 참조 문서로 분리
- 진입점에는 각 주제마다 짧은 요약과 명시적 참조 링크만 남김
- 산출물 일치를 검증하던 안전장치도 새 구조에 따라 검사 대상 위치가 갱신됨

## 수용 기준 (EARS)

AC1. 시스템은 진입점 문서의 본문 크기를 이전 크기 대비 약 50% 이상 줄여야 한다.

AC2. 진입점에서 길게 풀려 있던 큰 주제 셋 (상태 정합·사전 명확화 라운드·새 브랜치 생성과 커밋)은 각각 별도 참조 문서로 이관되어야 하며, 진입점에는 해당 주제마다 짧은 요약과 명시적 참조 링크만 남아 있어야 한다.

AC3. 이관된 모든 세부 설명은 절단·생략·축약 없이, 해당 참조 문서 하나만 읽으면 해당 주제를 끝까지 수행할 수 있을 만큼 자기완결적이어야 한다.

AC4. 산출물 일치를 검증하던 안전장치도 새 구조에 맞게 갱신되어 제자리에 있는 내용을 검사하도록 해야 하며, 이동 전과 같은 계약 (해석 결정적, 하위 호환 문구 부재 등)을 보장해야 한다.

AC5. 외부 계약 (입력 시그니처, 10단계 워크플로우의 존재와 순서, 산출물 경로 규칙, 브랜치 명명 규칙)은 변하지 않아야 한다.

AC6. 다른 큰 섹션 (이관 대상 외) 중 몇 개는 구조가 집약적으로 압축되어 읽기가 쉬워져야 하므로, 의미 손실 없이 단순 반복·과도한 예시·장황한 관계절을 제거해야 한다.

AC7. 진입점의 메타 헤더 설명·텍스트는 이번 변경에서 손을 대지 않고 그대로 보존한다.

## 범위

포함:
- 진입점 문서 본문 경량화
- 길게 풀려 있던 큰 주제 셋을 별도 참조 문서로 분리
- 진입점에는 각 주제마다 요약·명시적 링크만 유지
- 잔여 큰 섹션 (도입·절차 점검·승인 절차·최종 점검)의 산문 압축
- 안전장치가 검사하는 대상 위치의 갱신
- 최종 상태의 조각·이론·증거 일치 확인

비-목표:
- 입력 시그니처 변경
- 10단계 워크플로우의 단계 수·순서 재설계
- 산출물 경로 규칙·브랜치 명명 규칙 변경
- 메타 헤더 텍스트 변경
- 사용자가 볼 동작의 관찰 가능한 차이 — 하는 일·묻는 것·산출물 — 의 변경

## 검증

이 명령이 0 exit으로 끝나야 합니다:

`bash plugins/autopilot/skills/spec/references/test-spec-loop-contract.sh && [ $(wc -c < plugins/autopilot/skills/spec/SKILL.md) -le 18000 ] && grep -qE 'references/(task-state-alignment|pre-clarification|feat-branch-commit)\.md' plugins/autopilot/skills/spec/SKILL.md`

추가 논리적 행위 (PR 리뷰에서 확인):
- 이관된 세 주제 각각에 대해, 진입점에 해당 주제의 참조식 링크가 남아 있고 별도 참조 문서 안에 세부 설명이 들어 있음을 입증.
- 안전장치 실행을 명시적으로 수행해 종료 상태가 합격함을 확인. 합격이 아닌 경우 실패로 간주하고 원인을 파악·수정.
- 외부 계약의 존재 증거 (호출 시그니처, 단계 번호, 산출물 경로 관련 문구, 브랜치 명명 관련 문구)가 본문 또는 메타 헤더 어딘가에 그대로 존재함을 문구 검색으로 입증.
- 잔여 압축된 섹션이 해석 수준에서 이전과 동일한 조각을 제공하는지 수동 검토 (논리적 행위).

## 제약

1. 안전장치가 단일 출처로 삼는 한 문단 (종류: 슬러그 도출의 코드 조각)은 이관 후에도 별도 참조 문서 안에 원형의 단계 설명과 함께 존재해야 하며, 안전장치 자체가 그 새 자리를 검사하도록 함께 사용 경로를 갱신한다.

2. 외부에서 볼 때의 조작법·단계 수·산출물 경로·브랜치 명명 규칙·메타 헤더는 이번 변경의 범위를 벗어난다 (비-목표와 일치).

3. 이관된 참조 문서는 수신자가 사전 지식 없이도 주제를 끝까지 수행할 수 있을 만큼 자기완결적이어야 한다. 진입점에서 끊어 너무 압축·제거되는 항목이 없어야 한다.

4. 이번 변경은 자기 참조적으로 적용되는 변경이므로, 이 SPEC 자체는 현재 규칙으로 읽으면 되고, 새 흐름은 다음 스킬 호출부터 적용된다 (메모리 룰).

## 위험

R1. 안전장치가 계속 진입점만 검사하도록 남아 있는 상태에서 본문이 먼저 이관되면, 해석 장치가 해당 문구를 찾지 못해 종료 상태가 불합격으로 떨어진다. → 이관 커밋과 안전장치 변경 커밋을 동일 PR 내에 묶어 동시에 변경하고, 최종 상태에서 안전장치를 수동 실행해 합격 여부를 PR 리뷰 전에 입증.

R2. 이관 과정에서 임의로 문구를 압축·재서술하다가 입력자·항목 수·조건 표기 등 해석 의미가 이동 전과 달라질 수 있다. → 공식 골격 (항목 수, 조건 등급, 권한의 구체적 포괄 범위 등)은 문장 결은 그대로 보존하고, '표현만 다르지 의미는 같다'가 성립하는 수준의 변경으로 일관되게 운용.

R3. 진입점이 너무 부족한 정도로 발췌되어 수신자가 세부를 다 읽을지 판단하지 못하는 상태. → 각 주제마다 진입점에 '세 문장 이내 요약 + 명시적 참조 링크'의 최소 분량을 반드시 남긴다.

R4. self-referential 적용 시점에서 수정 중인 규칙을 엄격 적용하려 들면 현재 스킬 동작과 새 규칙이 충돌한다. → 메모리 룰과 일치하게, 이 SPEC 자체는 현재 규칙으로 읽으며 내고, 새 규칙은 다음 스킬 호출부터 적용된다는 단서를 입증 절차와 제약 수준에서 명시한다.
