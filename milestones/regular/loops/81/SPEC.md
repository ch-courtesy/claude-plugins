# 워크트리 BASE SHA 메타 도입·게이트 diff 기준을 BASE..HEAD로 전환해 머지 분기 false-positive 차단

## 무엇을 만들 것인가
자율 loop 드라이버가 워크트리를 생성하는 시점의 부모 브랜치 HEAD를 "베이스"로 영구 기록하는 메타 데이터를 도입한다. 이후 모든 객관 게이트(스코프 검사·메타 commit 격리·시크릿 누설)는 직전 commit과의 단일 diff 대신 베이스부터 현재까지의 누적 diff를 비교 대상으로 사용한다. 결과로 (a) 부모 브랜치 HEAD가 머지 commit이어도 워크트리에서 생성된 신규 변경만 게이트 대상이 되고, (b) 워커가 아무 변경이 없는 첫 이터 종료 시 false-positive halt가 사라지며, (c) 일반 commit에서 분기된 워크트리의 게이트 동작은 회귀 없다.

## 수용 기준 (EARS)
1. **이벤트**: 워크트리 생성 시 시스템은 부모 브랜치 HEAD의 commit SHA를 베이스 메타에 1회 기록한다.
2. **보편**: 시스템은 객관 게이트(스코프·메타 격리·시크릿) diff를 베이스부터 현재까지의 누적 범위로 산출한다.
3. **비원시 동작**: 부모 브랜치 HEAD가 머지 commit인 상태에서 워커가 어떤 코드 변경도 만들지 않고 첫 이터가 종료하면, 시스템은 스코프 위반 halt를 발생시키지 않는다.
4. **이벤트**: 워커가 스코프 include 밖 파일을 의도적으로 변경·commit하면 시스템은 종전과 동등하게 스코프 위반을 감지해 halt한다.
5. **보편**: 일반(비-머지) commit에서 분기된 워크트리는 본 변경 전과 동등한 게이트 동작을 보인다.
6. **비원시 동작**: 베이스 메타가 누락된 워크트리에서 시스템은 명확한 에러 메시지와 함께 halt하며 false-positive 위반을 통과시키지 않는다.

## 범위
포함:
- 워크트리 생성 시 베이스 SHA 메타 기록 로직
- 세 게이트(스코프·메타 격리·시크릿)의 diff 비교 기준을 베이스 누적 범위로 전환
- 머지 commit 케이스 회귀 테스트 추가 + 일반 commit 케이스 회귀 유지

비-목표 / 제외:
- 메타 파일 컨벤션 단일 출처화 (Issue #117로 분리)
- 베이스 갱신 시점 변경 (워크트리 생성 1회 고정 유지)
- 기존 메타 파일 5종 구조 변경

## 검증
이 명령이 0 exit으로 끝나야 합니다:
bash tests/autopilot/test-loop-sh.sh
- 머지 commit에서 분기된 워크트리가 false-positive halt 없이 첫 이터를 마친다
- 일반 commit에서 분기된 워크트리의 기존 게이트 동작이 그대로 유지된다
- 스코프 include 밖 파일을 의도적으로 건드리면 종전과 동등하게 halt한다
- 베이스 메타가 없는 워크트리에서 시스템은 명확한 에러 메시지와 함께 halt하며 false-positive 위반을 통과시키지 않는다

## 제약 (있을 때만)
- 베이스 메타는 워크트리 생성 시 1회만 기록되고 이후 변경되지 않는다 (이터 증분 의미는 누적 diff로 표현)
- 베이스 메타 자체가 객관 게이트의 검사 대상에 잡히지 않아야 한다 (자기 참조 회피)
- 본 변경 이전에 생성된 워크트리는 베이스 메타가 없는 상태로 남아 있을 수 있고, 이때는 재생성 없이 사용 시 명확한 에러로 halt한다 (AC 6)

## 위험 (있을 때만)
- 장기 worktree(수많은 이터 누적): 누적 diff 범위가 커져 게이트 검사 비용 상승 가능 — 실측 후 cap 필요 시 후속 처리
- 베이스 메타가 scope.exclude·meta_exclude에 등록 누락되면 자기 참조 위반이 발생 — AC 6번으로 감지·방어
- pre-existing 워크트리(베이스 메타 부재)는 재생성 전에는 사용 불가 — 호환성 비용 인지
