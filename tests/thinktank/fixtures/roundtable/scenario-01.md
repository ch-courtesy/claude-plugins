## 시나리오 설명

이 픽스처는 roundtable 스킬 1.2.0 정량 게이트 검증을 위한 표준 입력 시나리오다.
측정 세션을 재현할 때 이 파일의 아젠다와 로스터 구성을 그대로 사용한다.

## 아젠다 (측정 세션 입력)

**안건**: 팀 내 코드 리뷰 의무화 정책 도입 여부 결정

모든 PR에 대해 최소 2명의 동료 리뷰를 의무화하는 정책을 도입해야 하는가?

배경:
- 현재 팀 규모: 8명 개발자
- 현재 리뷰율: 약 40% (자발적)
- 최근 3개월 프로덕션 장애의 60%가 리뷰 없이 머지된 PR에서 발생
- 릴리스 사이클: 2주 스프린트

## 로스터 구성 (측정 세션 입력)

| 역할 ID | 페르소나 | 대표 관점 |
|---|---|---|
| P1 | 시니어 엔지니어 | 코드 품질·기술 부채 관리 우선 |
| P2 | 팀 리드 | 속도·생산성 균형 우선 |
| P3 | 주니어 개발자 | 학습 기회·심리적 안전 관점 |
| P4 | 반대 관점 대변인 | 의무화 정책의 부작용·오버헤드 비판 |

## 측정 목표 마커

이 시나리오로 구동된 roundtable 세션은 다음 구조화 마커를 생성해야 한다:

- `dissent-forcing-triggered: yes` — P4(반대 관점 대변인)를 통한 반대 강제 발동
- `rebuttal-exchange: N` — N ≥ 1, 상호 반박 왕복 발생
- `core-claim: ...` — 최소 1개, 합의·불합의를 좌우하는 핵심 주장
