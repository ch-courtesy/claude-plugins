## 결정 지도

### 합의된 내용
현재 자발적 리뷰율(40%, E-002)이 낮고 개선이 필요하다는 데 전원 동의. 미리뷰 PR과 프로덕션 장애 간 상관관계(E-003)가 우려할 만한 신호라는 데 동의. 형식적 승인(러버스탬프)이 되면 정책이 실패한다는 실패 조건은 전원 공통 인식.

### 핵심 이견과 가치 충돌
- 전면 2인 의무화(R1, R3 성향) vs 위험 기반 차등 적용(R2, R4 성향)

- 의무화가 저조한 리뷰율의 근본 원인(시간 부족 가능성)을 해결하는 올바른 처방인가에 대한 이견(R4가 제기)

### 공통 지지
리뷰 확대 방향성 자체, 8명이라는 팀 규모 제약을 정책 설계에 진지하게 반영해야 한다는 점.

### 정보 공백과 가정
리뷰 평균 소요시간 데이터 없음, 장애 심각도 미분류, 저조한 리뷰율의 근본 원인 불명, 인과관계 미검증(모두 증거 팩 정보 공백과 동일).

### 비가역적 결정
정책 자체는 트라이얼 후 재검토 가능해 비가역적이지 않음. 다만 정책이 형식화되어 팀 신뢰·사기가 훼손되면 그 신뢰 회복은 부분적으로 비가역적일 수 있다는 점을 전원 인지.

### 실패 조건
형식적 리뷰(러버스탬프)로 흐르면 장애 감소 없이 속도만 저하되는 것 — 전 참여자가 공통으로 지목.

- 추가 조사: 없음
- 진행자 판정: 동의(consent) 기준 충족 — 중대한 반대 없음, 제시된 조건이 처리됨(또는 실행 과제로 명시적 이관됨). documenting 단계로 이동해 합의·실행서를 작성한다.

## 최종 문서

### 팀 내 코드 리뷰 의무화 정책 도입 여부 원탁회의 합의·실행서

#### 합의 상태와 적용 범위
합의 방식: 동의(consent), 종료 기준(중대한 반대 없음 + 조건 처리됨) 충족. 적용 범위: 개발팀 전체(8명)의 PR 리뷰 프로세스. 이 회의는 제안 권한만 가지며 실제 시행에는 엔지니어링 리더십(실제 결정권자)의 최종 승인이 필요하다.

#### 최종 합의문
"코드 리뷰를 의무화하되, 원안(전 PR 최소 2인)을 그대로 적용하지 않고 위험 기반 차등 기준(전원 최소 1인 + 고위험 변경 2인)을 적용한다. 형식화(러버스탬프) 방지를 위한 리뷰 SLA와 피드백 가이드라인을 함께 도입하고, 8주(4스프린트) 트라이얼 기간 동안 정의된 지표로 평가한 뒤 정식 도입 여부와 세부 기준을 재결정한다."

#### 결정사항과 근거
1. 모든 PR에 최소 1인 리뷰를 의무화한다 — 근거: E-002(낮은 자발적 리뷰율), E-003(미리뷰 PR과 장애 발생의 상관관계)
2. 고위험 변경(프로덕션 크리티컬 경로, 인프라, 데이터베이스 마이그레이션 등)에는 최소 2인 리뷰를 의무화한다 — 근거: R1의 기술부채·품질 관점과 R2의 실행 가능성 검토(Round 1)
3. 리뷰 SLA(응답 시간 기준)와 피드백 가이드라인을 문서화해 형식적 승인과 비건설적 피드백을 방지한다 — 근거: R2의 릴리스 사이클 우려(E-004), R3의 심리적 안전 관점(Round 2)
4. 8주(4스프린트) 트라이얼 기간을 설정하고 종료 시 재평가한다 — 근거: R4의 반대 강제 논거(Round 4)와 그 해소로 확정된 지표(Round 5)

#### 조건·예외·중단 조건
- 조건: (a) "고위험 변경"의 분류 기준을 트라이얼 시작 전 문서화한다. (b) 리뷰 SLA(예: 영업일 기준 최초 피드백 응답 시한)와 피드백 가이드라인을 트라이얼 시작 전 문서화하고 팀에 공유한다.
- 예외: 긴급 핫픽스는 사후 리뷰(post-hoc review)를 허용하되, 정해진 SLA 내에 사후 리뷰를 완료한다.
- 중단 조건: 8주 트라이얼 종료 후 재평가에서 다음 중 하나라도 관찰되면 정책 수정 또는 롤백을 검토한다 — (1) 평균 리뷰 소요시간이 SLA를 지속적으로 초과, (2) 배포 지연이 스프린트 목표를 반복적으로 위협, (3) 형식적 승인(내용 없는 승인) 비율이 높게 관찰됨.

#### 실행 과제와 실제 책임자 승인 필요사항
- 고위험 변경 분류 기준 문서 작성 — 실제 책임자(팀 리드) 승인 필요
- 리뷰 SLA 및 피드백 가이드라인 문서화 — 팀 합의 후 팀 리드 승인 필요
- 8주 트라이얼 일정 및 재평가 지표(리뷰 평균 소요시간, 트라이얼 기간 중 프로덕션 장애율[리뷰 여부별], 팀 만족도 서베이) 확정 — 팀 리드 승인 필요
- 트라이얼 종료 후 재평가 회의 일정 수립 — 실제 결정권자(엔지니어링 리더십) 승인 필요
- 이 회의는 제안 권한만 가지므로, 위 실행 과제 전체는 실제 시행 전 엔지니어링 리더십의 최종 승인을 받아야 한다.

#### 성공 기준과 재검토일
- 성공 기준: 리뷰 없이 머지되는 PR 비율 감소, 프로덕션 장애 중 미리뷰 기인 비율 감소, 평균 리뷰 소요시간이 SLA 이내 유지, 팀 만족도 서베이에서 심각한 부정적 신호 없음.
- 재검토일: 트라이얼 시작 후 8주(4스프린트) 시점. 정확한 시행일과 재검토일은 실제 승인 이후 확정한다.

#### 반대·소수 의견
R4(반대 관점 대변인)는 E-003이 상관관계일 뿐 인과관계를 증명하지 않는다는 점, 8명 규모 팀에서 전면 2인 리뷰가 처리량을 급격히 낮출 수 있다는 점을 근거로 원안(전 PR 2인 의무화)에 반대했다. 위험 기반 차등 적용과 구체적 트라이얼 재평가 지표·기간·롤백 조건을 조건으로 조건부 수용으로 최종 전환했다. R4는 재평가 지표가 실제 시행 단계에서 엄격히 적용되지 않고 정책이 관성적으로 영구화될 위험을 소수 의견으로 남긴다 — 이는 실행 단계에서 지속적으로 점검되어야 한다.

#### 확인
