# skill — 노드 생산

도구가 될 수 있는 것을 감싸 입출력 계약(`node:` 블록)을 가진 스킬 하나를 만들거나 고친다. 구조 판정은 전부 `pipecheck` 바이너리에 위임한다 — 직접 판정하지 않는다.

## 판정 도구

```bash
BIN="<이 SKILL.md가 있는 디렉터리>/../../tools/pipecheck/dist/pipecheck-$(uname -s | tr A-Z a-z)-$(uname -m | sed -e 's/x86_64/amd64/' -e 's/aarch64/arm64/')"
```

판정 도구 명령은 프로젝트 루트에서 실행한다. `-project`·`-user`는 현재 프로젝트의 `.claude/skills`와 `~/.claude/skills` 경로를 준다. 없는 쪽은 아래 예시에서 그 플래그를 뺀다.

- 검증: `"$BIN" check-skill -file <임시 위치>/<이름>/SKILL.md -project .claude/skills -user ~/.claude/skills -self-scope <설치 예정 scope> -overlay <임시 위치>` — `-overlay`는 임시 위치 루트다: 같은 실행의 임시 산출물이 설치본을 대신하므로(6.1.2) `wraps` 대상을 설치본보다 먼저 거기서 찾게 한다
- 해시: `"$BIN" hash -file <임시 위치>/<이름>/SKILL.md` (워크플로 재료면 `-graph <임시 위치>/<이름>/graph.json`)
- 파급: `"$BIN" ripple -name <이름> -scope <project|user> -contract <새 계약 해시> -body <새 본문 해시> -project .claude/skills -user ~/.claude/skills` — 이름·위치를 바꿨으면 소비자가 기록한 식별자로 대조하기 위해서 `-name`·`-scope`에 수정 전 원본 설치본의 값을 넣는다

출력은 한 줄 JSON, 불통과는 exit 1. exit 2는 호출 오류 — 명령을 고쳐 같은 호출을 다시 부르는 연속 시도를 3회까지 하고, 그래도 exit 2면 그 출력과 시도한 명령을 보고하고 오류로 끝낸다. 통과하거나 다른 호출로 넘어가면 시도 횟수는 남지 않는다. 바이너리가 없거나 pipecheck 소스가 바이너리보다 새로우면 `<이 SKILL.md가 있는 디렉터리>/../../tools/pipecheck/build.sh`를 먼저 실행해 만든다. 빌드가 실패하면 그 출력을 보고한다 — 승인 화면이 열려 있으면 그 화면으로 돌아가고, 아니면 실행을 끝낸다.

사용자가 실행을 그만두면 어느 단계든 임시 위치를 지우고 진행 상태를 보고하며 끝낸다 — 수정 경로면 원본은 그대로다. 오류로 끝나는 모든 경로도 같다. `/pipeline`이 불렀으면 취소·실패를 상위에 반환하고 임시 위치는 상위가 지운다.

## 절차 체크리스트

```
- [ ] 1. 무엇을 감쌀지 받기 (도구 이름·실행 방법·인자·인증)
- [ ] 2. 이름·설명·계약 초안 확정 (사용자 확정 전 아무것도 만들지 않기)
- [ ] 3. 본문 세 절 쓰기 (임시 위치에)
- [ ] 4. check-skill 검증 루프 (최대 재작성 3회)
- [ ] 5. 파급 보고 → 승인 화면 → 설치
```

## 1. 무엇을 감쌀지 받기

도구 정보는 사용자에게 묻는 것이 유일한 경로다. 도구 이름, 실행 방법(CLI 명령·API 엔드포인트·MCP 도구), 필요한 인자, 필요한 인증의 **종류**를 받는다. `/pipeline`이 불렀으면 넘어온 초안에서 시작하고 부족한 것만 묻는다.

## 2. 초안 확정

이름·설명·입출력 계약 초안을 제시하고 사용자가 확정한다. 이름이 [references/format.md](references/format.md)의 이름 규칙을 어기면 확정 전에 되묻는다. 설치 위치 초안은 `project`로 두고 승인 화면에서 바꾼다. 확정은 셋 전부에 대한 것이다 — 설명이 빠진 확정이면 설명을 되물어 채운다. 고칠 것은 자유 서술로 받고, 해석해 되비추고, 확인받으면 초안을 고쳐 다시 보여준다. 해석이 안 되면 되묻는다. **확정 전에는 아무것도 만들지 않는다.** `description`을 자동 생성하지 않는다.

같은 `name`+`scope`가 이미 있으면 멈추고 셋 중 하나를 AskUserQuestion으로 받는다:
- **수정 전환** — 그 스킬을 대상으로 아래 "기존 스킬 수정" 경로로 넘어가되 문답·본문을 유지한다
- **다른 이름** — 이름만 바꿔 같은 자리에서 계속한다. 또 충돌하면 같은 물음을 반복한다
- **취소** — 이름 확정만 취소해 초안 화면으로 돌아간다. 문답을 버리지 않는다

선택지를 답하지 않고 물리면 취소를 고른 것과 같다.

## 3. 본문 쓰기

임시 위치에 `<이름>/SKILL.md`를 쓴다 — 단독 실행이면 `mktemp -d`로 새로 만들고, `/pipeline`이 불렀으면 넘겨받은 상위 임시 위치를 쓴다(새로 만들지 않는다). 이름이 바뀌면 임시 디렉터리를 새 이름으로 옮기고 옛 디렉터리를 지우며, 프론트매터 `name`도 새 이름으로 고친다. 형식은 [references/format.md](references/format.md)를 따른다 — 프론트매터(`name`·`description`·`node:`·어댑터면 `wraps`), 본문 `## 입력`·`## 실행`·`## 출력` 세 절.

- 인증 정보는 본문에도 계약에도 적지 않는다. 무엇이 필요한지만 적는다
- `## 실행`에 구체적 절차를 적는다 — CLI면 명령과 인자, API면 엔드포인트, MCP면 도구 이름과 파라미터
- 값을 쓰는 쪽이 확인할 것(경로 실재 등)은 그 확인을 본문에 지시로 적는다

## 4. 검증 루프

`check-skill`을 돌린다. 불통과면 **불통과 항목을, 현재 산출물·확정된 계약·모은 문답 전부와 함께** 입력으로 삼아 본문을 다시 쓴다. 불통과 원인이 확정된 이름·계약이면 본문을 다시 쓰지 않고 2로 돌아가 다시 확정받는다 — 재작성 횟수를 쓰지 않는다. **재작성은 3회까지다.** 소진하면 오류로 끝내고 마지막 불통과 항목을 보고한다 — 임시 산출물은 지우고(`/pipeline`이 불렀으면 지우지 않는다 — 삭제는 상위 전이 표가 맡는다), 수정 경로면 원본은 그대로 둔다.

`warnings`(출력 전부 선택 등)는 불통과가 아니다 — 승인 화면 주의 항목으로 넘긴다.

## 5. 파급 보고 → 승인 → 설치

`hash`로 새 계약·본문 해시를 얻고, `ripple`로 파급 보고를 계산한 뒤 승인 화면을 보여준다. 설치본이 없는 신규 제작이면 `ripple`을 돌리지 않는다 — 소비자가 아직 없다. 아래 승인 순서 3의 연쇄 재기록으로 본문 해시가 바뀔 어댑터를 재기록된 값 기준 `ripple`로 따라가 그 소비 워크플로도 파급 보고와 승인 순서 1의 문답 대상에 포함한다 — 재기록될 본문 해시는 어댑터 사본을 임시 위치의 별도 자리에 만들어 `wraps`를 새 값으로 고친 뒤 `hash`로 계산한다(설치본·임시 작업본은 안 건드린다) — 계산이 끝나면 사본을 지우고, 사본 생성·계산이 실패하면 사본과 임시 위치를 지운 뒤 그 출력을 보고하고 실행을 끝낸다. 문답의 예 답이 재컴파일로 또 낡게 할 어댑터는 문답 없이 재기록 대상에 더하고, 그 소비 워크플로만 문답에 더한다 — 더 늘지 않을 때까지 반복하고, 설치·재기록은 문답이 다 모인 뒤 시작한다. 형식과 입력 처리(3택+자유 서술, 이름·설명·설치 위치 변경, 실패 복구)는 [references/approval.md](references/approval.md)를 따른다.

승인하면 이 순서로:
1. 파급 보고에 낡은 소비 워크플로가 있으면 함께 재컴파일할지 묻는다(아니오는 낡은 채 둔다). 단독 경로의 문답 대상은 파급 보고의 낡은 소비 워크플로 전부다 — 단독 호출에는 그래프가 없어 닫힘 한정이 성립하지 않는다. 문답을 물리면 받은 답을 전부 버리고 승인 화면이다. 소비자끼리 `materials`·`wraps`로 의존하면 문답을 의존의 하위부터 상위 순으로 던지고 그 의존을 함께 표시하며, 하위를 아니오 한 — 직접 답이든 이 규칙의 자동 처리든 — 경우 그 하위에 의존하는 상위는 묻지 않고 아니오로 처리하며 그 사실을 표시하고, 의존 체인을 따라 같은 규칙을 반복한다 — 하위가 낡은 채로는 상위 재컴파일이 낡음을 고치지 못하기 때문이다
2. 임시 산출물을 설치 위치로 옮긴다 — `project`는 `.claude/skills/<이름>/`, `user`는 `~/.claude/skills/<이름>/`. 수정이면 원본을 덮어쓰고, 위치 변경이면 새 위치에 놓고 기존 위치의 원본을 지운다
3. 이 스킬을 `wraps`로 가리키는 어댑터의 `wraps`를 문답 없이 재기록한다 — 계약·본문 해시와, 이름·위치가 바뀌었으면 `name`·`scope`도 새 값으로. 재기록 값은 승인 화면 계산에 쓴 값을 그대로 쓴다. 재기록은 연쇄다 — 재기록으로 본문 해시가 바뀐 어댑터를 가리키는 어댑터도 같은 규칙으로, 더 바뀌는 것이 없을 때까지
4. 예라 답한 소비 워크플로를 `/pipeline` 재컴파일 경로로 처리한다 — 부를 때 이 실행의 임시 위치를 넘긴다. 여럿이면 `materials`·`wraps` 의존의 하위부터 상위로 처리한다 — 앞선 재컴파일·재기록의 새 해시를 뒤가 받기 위해서다. 재컴파일된 워크플로에도 3의 연쇄 재기록을 같은 규칙으로 적용한다
5. 어느 단계든 실패하면 전부 되돌린다 — 덮어쓴·지운 원본, 재기록한 wraps, 재컴파일 산출물 포함 — 그리고 실패를 보고하고 승인 화면으로 돌아간다
6. 끝나면 — 승인·거부·오류 종료 모두 — 임시 위치를 지운다

## 기존 스킬 수정

같은 절차다. 무엇을 바꿀지 받고 — 계약이 바뀌는 수정만 2로 확정하고 — 본문을 고치고(원본은 두고 임시 위치에 수정본), 계약 변경 여부와 무관하게 4~5를 돈다. 이름·설치 위치·`description`만 바꾸는 요청도 이 경로다 — 본문 변경 없이 원본을 임시 위치에 복사해 4~5를 돌고 승인 화면에서 확정한다. **수정 대상이 워크플로 스킬이면, 설치와 해시(`hash -graph graph.json`)에 쓰기 위해서 기존 `graph.json`을 임시 위치에 그대로 복사해 함께 둔다.** 본문·설치 위치·`description`은 이 경로로 고친다. **워크플로 스킬만 예외다 — 그 이름·경계 계약(`node:` — `graph.json` 경계에서 파생된다)·`graph.json`은 이 경로로 고치지 않는다.** 그래프 수정은 `/pipeline` 재컴파일이 맡는다.

## 어댑터

기존 스킬을 감싸는 것도 같은 절차다 — 원본이 이미 어댑터여도 같고, `wraps`가 체인이 된다. 계약은 감싸는 쪽이 요구하는 형태로 새로 정하고, `## 실행`에 값을 어떻게 옮기는지 서술하고, 원본 참조를 프론트매터 `wraps`에 적는다(형식은 references/format.md). **원본 파일은 안 건드린다.** `wraps`의 `contract`·`body`는 `hash`로 원본에서 얻은 현재 값을 적는다. 이 실행의 임시 산출물과 동명이지만 설치 예정 scope가 다른 설치본을 `wraps` 대상으로 쓰는 요청은 거부하고 따로 실행하게 안내한다 — `-overlay`가 이름으로 해소하기 때문에 동명은 임시 산출물 하나여야 한다.

## /pipeline 위임

`/pipeline`이 불렀으면 1~4까지만 수행하고 임시 산출물 위치를 상위에 넘긴다 — 승인은 상위 7.5 화면에 합쳐지고, 설치·임시 삭제·취소와 실패 처리는 상위 전이 표가 맡는다.

## 재귀 차단

이 실행에서 만드는 중인 워크플로 — 최상위와 중간 전부, `name`+`scope`로 판정 — 를 이 절차 안에서 다시 만들려 하면 재료 이름·설치 위치·실행 경로를 보고하며 오류로 끝낸다.
