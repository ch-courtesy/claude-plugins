# 이름·위치 변경과 동명 규칙

산출물(재료·하위 워크플로·워크플로 자신)의 이름이나 설치 위치가 바뀔 때, 그리고 같은 이름이 둘 이상 얽힐 때 읽는다.

## 이름·위치가 바뀌면

1. 임시 디렉터리를 새 이름으로 옮기고 옛 디렉터리를 지운다. 워크플로면 `graph.json`과 경계 계약 `SKILL.md`의 `name`도 새 이름으로 고친다
2. 그 산출물을 재료로 쓰는 이 실행의 그래프들을 고친다 — `materials`의 `name`·`scope`와 노드·컨테이너의 `skill` 참조를 새 값으로
3. 이름은 본문 해시 범위라(§5.8) 바뀐 산출물의 해시를 `hash`로 다시 계산하고, 그것을 기록한 이 실행 그래프들의 `materials` 해시와 그것을 감싸는 임시 어댑터 작업본의 `wraps`(`name`·`scope`·`contract`·`body`)에 새 값을 쓴다
4. `wraps`가 바뀐 어댑터도 본문 해시가 바뀌므로 3을 더 늘지 않을 때까지 반복한다

## 같은 실행에 동명 산출물은 하나다

`-overlay`가 임시 위치를 이름으로만 해소하기 때문이다 — 같은 이름이 둘이면 어느 쪽을 검사하는지 정해지지 않는다. 다음 요청은 거부하고 직전 화면을 유지하며 따로 실행하게 안내한다:

- 동명의 project·user 재료를 함께 수정하려는 요청
- 이름 변경으로 이 실행의 다른 산출물과 동명이 되는 요청
- 임시 산출물과 동명이지만 설치 예정 scope가 다른 설치본을 같은 실행의 재료·`wraps` 대상으로 함께 쓰려는 요청
