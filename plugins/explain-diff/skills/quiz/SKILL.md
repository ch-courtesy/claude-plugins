# 퀴즈 (Quiz)

직전에 설명한 변경 내용으로 중간 난이도 퀴즈 5문항을 낸다. 사용자가 전부 맞히기 전에는 정답을 공개하지 않는다.

## 출제 근거

- 같은 세션에서 explain 스킬(또는 동등한 설명)이 앞서 있으면 그 내용을 근거로 출제한다.
- 없으면 대상 변경을 먼저 파악하고(explain 스킬의 "대상 변경 확정" 규칙과 동일) 설명 없이 바로 출제한다.

## 출제 규칙

- 정확히 5문항, 4지선다 객관식.
- 중간 난이도: 변경의 실질을 이해해야 풀 수 있되, 말장난·함정은 없다.
- 문항 소재: 변경의 의도, 변경 전/후 동작 차이, 엣지 케이스, 그런 구조를 택한 이유.
- 구조화된 사용자 질문 기능으로 제시한다(턴당 문항 수 제한이 있으면 나눠서, 예: 4문항 + 1문항). 기능이 없으면 번호 목록으로 내고 답을 기다린다.

## 채점 규칙 (핵심 계약)

- **전부 맞히기 전에는 정답·해설을 공개하지 않는다.**
- 채점 후: 맞은 문항 번호만 알린다. 틀린 문항은 정답을 노출하지 않고 "무엇을 오해했는지"를 설명한다. 예: "3번 — 캐시 무효화가 쓰기 전에 일어난다고 이해하고 있다. 코드가 실제로 언제 무효화하는지 다시 보라."
- 틀린 문항만 다시 낸다(문제와 선택지는 바꾸지 않는다).
- 전부 정답이 되면 그때 전체 정답표와 해설을 공개한다.
- 사용자가 명시적으로 포기하면("정답 알려줘", "포기") 정답·해설을 공개한다. 그 전에는 힌트를 요청받아도 정답 자체는 노출하지 않는다.
