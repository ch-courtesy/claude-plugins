# 놀이터 (Playground)

방금 개발한 코드를 상호작용 가능한 단일 HTML 파일로 시각화한다. 서비스 코드는 절대 건드리지 않는다.

## 제약 (필수)

- 산출물은 **자체 완결 HTML 파일 1개**: CSS·JS 인라인, 외부 네트워크 의존성(CDN·폰트·원격 이미지) 없음.
- **서비스 코드 수정 금지**: 리포의 어떤 소스 파일도 수정·생성하지 않는다.
- 저장 위치는 버전 관리 밖: 프로젝트에 무시되는 임시 디렉터리(`.tmp/` 등)가 있으면 그 안에, 없으면 시스템 임시 디렉터리에 둔다. 파일명은 `YYYY-MM-DD-explanation-<slug>.html` — 날짜 접두사가 파일을 시간순으로 정렬해 준다.

## 대상 변경 확정

explain 스킬과 동일: 사용자 지정 → 작업 트리의 커밋 안 된 변경 → 현재 브랜치가 base 대비 앞선 커밋들 → 마지막 커밋. 판단이 갈리면 구조화된 사용자 질문 기능으로 확인한다. 페이지를 만들기 전에 주변 코드를 넓게 탐색한다.

## 페이지 구성

- 한 페이지 세로 스크롤 + 목차. 최상위 구조에 탭을 쓰지 않는다. 휴대폰에서도 읽히는 기본 반응형.
- 섹션 순서: **배경**(초심자용 깊은 배경 + 변경에 직접 관련된 좁은 배경) → **직관**(핵심 아이디어를 장난감 데이터로) → **코드 워크스루**(이해 가능한 단위로 그룹·정렬).
- 명료하고 흐름이 매끄러운 산문(Martin Kleppmann의 글처럼), 섹션 전환은 매끄럽게. 핵심 개념·정의·엣지 케이스는 콜아웃으로.

## 상호작용·다이어그램

- 정적 그림보다 조작 가능한 요소를 우선한다: 예시 입력을 바꾸면 결과가 갱신되는 데모, 데이터 흐름을 이전/다음으로 넘기는 단계 재생, 변경 전/후 토글.
- 소수의 다이어그램 패밀리를 정해 페이지 전체에서 재사용한다. 유용한 종류:
  - 앱에서 사용자가 보는 UI의 단순화 목업 — UI 변경 설명용.
  - 컴포넌트 간 데이터 흐름·통신을 보여주는 시스템 다이어그램 — **예시 데이터를 반드시 포함**.
- ASCII 다이어그램 금지 — 다이어그램은 항상 HTML 요소로 그리고, 목록은 HTML 리스트로 만든다.
- 코드 블록은 `<pre>` 태그를 쓴다. 커스텀 div를 쓰면 CSS에 `white-space: pre-wrap`이 반드시 있어야 한다 — 없으면 브라우저가 줄바꿈을 전부 한 줄로 접는다. **파일 저장 전에 HTML 소스의 각 코드 블록 CSS에 `white-space: pre` 또는 `pre-wrap`이 있는지 검사한다.**

## 완료

파일의 절대 경로를 알려준다. 런타임에 파일 렌더 기능이 있으면 렌더해 보여주고, 없으면 브라우저로 여는 명령을 안내한다.
