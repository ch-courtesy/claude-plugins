# 설명서 (Explain)

방금 바뀐 코드를 이 코드베이스가 처음인 독자에게 설명한다. 구조와 배경부터 시작하고, 코드는 맨 마지막에만 보여준다.

## 대상 변경 확정

1. 사용자가 대상(diff·커밋·브랜치·PR)을 지정하면 그것을 쓴다.
2. 지정이 없으면 순서대로 찾는다: 작업 트리의 커밋 안 된 변경 → 현재 브랜치가 base 대비 앞선 커밋들 → 마지막 커밋.
3. 후보가 여럿이라 판단이 갈리면 구조화된 사용자 질문 기능으로 확인한다.

## 사전 탐색

변경된 파일만 보지 말고 주변 코드를 넓게 탐색한다: 변경이 속한 모듈의 구조, 호출자와 피호출자, 관련 데이터 모델·설정. 독자의 사전 지식을 가정하지 않는다.

## 출력 구조 (순서 강제)

1. **배경** — 이 변경과 관련된 기존 시스템을 설명한다. 초심자용 깊은 배경(이미 익숙한 독자는 건너뛰어도 된다고 표시)을 먼저, 그다음 변경에 직접 관련된 좁은 배경.
2. **직관** — 변경의 핵심 아이디어. 세부가 아니라 본질에 집중한다. 장난감 데이터(toy data) 예시로 변경 전/후 동작을 대비해 보여준다.
3. **코드** — 맨 마지막. 변경을 이해 가능한 단위로 그룹·정렬해 상위 수준 워크스루를 한다. 파일 나열 순서가 아니라 이야기가 되는 순서로.

- 배경·직관 섹션에서 코드 조각을 미리 노출하지 않는다. 개념은 산문과 예시 데이터로 설명한다.
- 명료하고 흐름이 매끄러운 산문으로 쓴다(Martin Kleppmann의 글처럼). 섹션 사이 전환을 매끄럽게 잇는다.
- 핵심 개념·정의·중요한 엣지 케이스는 인용 블록 콜아웃으로 강조한다.

## 후속

설명을 마치면, 이해 확인은 quiz 스킬로·상호작용 시각화는 playground 스킬로 이어갈 수 있다고 한 줄로 안내한다(강요하지 않는다).
