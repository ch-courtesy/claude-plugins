# 아젠다 인터뷰와 템플릿

`AskUserQuestion`으로 한 주제씩 묻는다. 저장소·제공 자료에서 확인 가능한 사실은 먼저 조사하고 묻지 않는다. 답이 다음 질문을 바꾸는 적응형 인터뷰를 사용한다.

## 충분 조건

다음 항목이 결정되면 인터뷰를 종료한다.

- 회의 목적과 필요한 결과물
- 결정할 핵심 질문 최대 3개
- 적용 범위와 제외 범위
- 실제 결정권자와 회의의 권한
- 영향을 받는 이해관계자
- 변경 불가능한 제약과 기한
- 성공 기준과 실패 위험
- 공개 범위와 민감 정보 제한

## 아젠다 섹션 규격

회의 파일(`.roundtable/<meeting-id>.md`)의 아젠다 섹션에 다음을 기록한다.

```markdown
### <안건명> 원탁회의 아젠다

#### 기본 정보
- 회의 ID:
- 의뢰자:
- 목적:
- 목표 결과물:
- 실제 결정권자:
- 회의 권한: 자문 | 제안 | 결정
- 공개 범위:

#### 핵심 질문
1.

#### 범위
- 포함:
- 제외:

#### 이해관계자
| 대상 | 영향 | 반드시 반영할 관점 |
|---|---|---|

#### 제약과 성공 기준
- 제약:
- 성공 기준:
- 실패 시 영향:

#### 합의 방식
- 방식: 자문 | 동의 | 합의 | 의결
- 선택 근거:
- 종료 기준:
- 실제 사람의 추가 승인 필요 여부:

#### 리서치 요구
- 최신성 기준:
- 허용 정보원:
- 금지 정보원·민감 정보:

#### 승인
- 상태: draft | approved
- 승인자:
- 승인 시각:
```

아젠다 승인 전 `researching`으로 전환하지 않는다.
