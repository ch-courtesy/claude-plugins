# 중앙 리서치 프로토콜

**중앙 리서처**가 공통 증거 팩을 한 번 만들고 모든 참여자는 같은 사실 기반에서 관점만 달리 해석한다.

## 리서치 계획

회의 책임자는 승인된 아젠다에서 다음을 뽑아 회의 파일의 리서치 계획 섹션에 기록한다. 중앙 리서처는 이 계획을 임의 확장하지 않고 실행한다.

- 사실 질문과 비교할 대안
- 검증할 가정과 반증 조건
- 내부 자료·프로젝트 파일·외부 자료의 조사 범위
- 최신성·출처 신뢰도 요구
- 정보 공백과 조사 중단 조건
- 토큰·호출 예산

기본 범위는 접근 가능한 의뢰자 자료, 프로젝트 파일, 허용된 웹과 도구다. 출처 접근 권한이나 민감 정보 경계를 넘지 않는다.

## 공통 증거 팩

중앙 리서처는 증거 팩 섹션의 공통 증거 팩을 다음 형태로 작성한다.

```markdown
### 공통 증거 팩

#### 핵심 요약

#### 증거 레지스트리
| ID | 주장·정보 | 근거·출처 | 확인일 | 확인 상태 | 관련 질문 | 주의사항 |
|---|---|---|---|---|---|---|
| E-001 | | | | 확인 / 상충 / 추정 / 미확인 | | |

#### 알려진 사실
#### 상충하는 정보
#### 검증되지 않은 가정
#### 대안별 근거
#### 정보 공백
#### 출처 목록
```

## 핵심 주장 증거 임계치

합의문·결정사항이 직접 의존하는 핵심 주장은 **서로 독립인 출처 2개 이상**으로 확인해야 확인 상태를 `확인`으로 표시한다. 독립 출처가 하나뿐이면 `추정`으로 표시하고 주의사항에 단일 출처 의존을 기록한다. 핵심 주장에는 반증 시도 결과(찾은 반대 증거, 또는 반대 증거 없음과 그 탐색 방법)를 함께 기록한다.

## 참여자별 배포

각 참여자 brief에는 공통 핵심 요약, 해당 역할과 관련된 증거 ID와 필요한 본문, 반드시 검토할 상충 정보·가정, 전체 증거 팩의 위치(회의 파일 증거 팩 섹션), 추가 조사 요청 형식만 담는다. 관련 증거만 배포해 입력 토큰 중복을 줄이되, 증거 ID를 유지해 최종 문서에서 추적 가능하게 한다.

## 추가 조사

참여자는 직접 조사하지 않고 다음 요청을 제출한다.

```text
조사 질문:
필요한 이유:
관련 증거 ID:
이 정보가 결론을 바꿀 조건:
긴급도:
```

추가 조사 요청의 통합은 진행자가 수행해 중앙 리서처에게 전달하고, 조사 결과에는 새 증거 ID를 부여해 관련 참여자에게 배포한다.

## 리서치 검증자 호출 조건

- 결정이 법률·안전·재무·보안 등 고위험 영역에 해당
- 핵심 출처가 서로 상충
- 최신 정보가 결론을 좌우
- 단일 출처에 과도하게 의존
- 중앙 리서처가 핵심 질문을 미확인으로 남김

리서치 검증자는 결론을 선택하지 않는다. 출처 품질, 주장 과장, 누락, 최신성, 확인 상태만 검토한다.
