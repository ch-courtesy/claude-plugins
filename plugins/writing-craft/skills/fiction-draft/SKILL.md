# 소설 초안 작성

## 입력

`brief`에 형식·세부 장르 조합, 독자, 목표 효과, 분량, 발표 방식, 시점, 인물표, 세계 규칙, 구조 선호, 금지 요소, 기존 본문·장부, 플랫폼 조건을 받는다. `out_path`는 본문 경로다. `ledger_dir`는 선택 입력인 원소 0~1개 배열이지만 장편·웹소설에서는 필수다. 장부가 없으면 프로젝트 안의 경로를 정해 `writing-craft:story-ledger`의 `init`으로 먼저 만들고, 경로를 정할 수 없으면 요청하라.

## 1. 형식과 의도

사용자가 정한 형식과 의도를 먼저 따르라. 장편·웹소설·로맨스처럼 규모·발표 방식·세부 장르를 조합할 수 있다. [craft-core.md](references/craft-core.md)를 읽고 주 구조 하나를 선택 도구로 써라. 구조 공식을 자동 강제하지 마라.

형식에 따라 [short-story.md](references/short-story.md), [novel.md](references/novel.md), [webnovel.md](references/webnovel.md) 중 필요한 것만 읽어라. 장편 웹소설이면 두 reference를 함께 적용하라.

## 2. 전체 약속과 선택 조건

독자가 기다릴 경험, 인물의 외적 욕망·내적 장애·현재 전략·실패 비용, 결말 방향(변화·타락·신념 유지)을 짧게 정리하라. 형용사 성격표보다 선택의 조건을 정하라. 실존 작품은 장르 관습·구조를 배우는 데만 쓰고 인물·설정·문장을 복제하지 마라.

## 3. 장면 카드

`writing-craft:story-ledger`에서 이번 구간에 필요한 확정 사실·인물 상태·정보 접근권을 불러와라. 계획과 인물의 믿음을 확정 사실로 취급하지 마라. 단편에 장부가 없어도 다음 카드는 작성하라.

```text
회차·장면 ID / 시점 인물 / 화자의 발화 시점:
시간·장소 / 입장 상태:
당면 목표 / 저항 / 결과와 비용:
반응·검토·결정 / 퇴장 상태:
참조한 확정 사실 / 접근 가능한 정보 / 금지 정보:
복선 설치·재등장·회수:
```

## 4. 장면·회차 초안

카드에 따라 장면 또는 회차 단위로 써라. 목표·충돌·결과 뒤 반응과 다음 선택의 연결을 확인하되 모든 단계를 같은 길이로 출력하지 마라. 제한 시점의 정보 범위를 지키고, 전지적 화자는 선택한 규약으로 판단하라.

웹소설 분량·공백 계산·업로드 조건은 해당 플랫폼·공모전 원문의 숫자를 입력으로 받아라. 입력이 없으면 장면 단위로 쓰고 분량을 확정하지 마라. 글자 수를 반복 설명으로 채우지 마라. 플랫폼 조건을 다룰 때 [platform-policy.md](references/platform-policy.md)의 확인 카드로 원문·날짜·적용 범위를 구분하라.

## 5. 추출·대조·수정

새 사실·변화·약속 후보를 본문 위치와 함께 추출하라. 장부와 대조해 모순·중복·정보 누출을 고쳐라. `story-ledger`의 `check`로 기계 검사와 모델 점검 질문을 모두 적용하라. 초안 후보를 검사하려면 확정 장부에 섞지 말고 프로젝트 `.tmp/`의 임시 사본에서 검사하라.

장부가 없거나 1화여도 아래 세 대조는 문장 단위로 하라(스킬 사용·미사용 비교 평가에서 초안이 가장 자주 틀린 곳).

- **세계 규칙 대조**: 능력·규칙이 나오는 문장마다 규칙 원문과 맞춰라. 규칙이 알려 주는 것(예: 발화가 거짓인지)만 판정하게 하고, 알려 주지 않는 것(진심·감정·동기, 거짓인 부분이 어느 절인지)으로 넓히지 마라. 앞에서 보여 준 판정을 뒤 문장이 무효로 만들거나 반대로 해석하지 않는지, 규칙의 예외(누구 앞에서·어떤 매체에서)가 앞 장면과 충돌하지 않는지 확인하라.
- **시점 대조**: 제한 시점이면 서술 문장마다 '시점 인물이 지금 보거나 듣거나 기억할 수 있는가'를 물어라. 시점 인물이 모르는 사건·물건의 존재를 서술자가 알려 주면 누출이다.
- **기획 비밀 대조**: 브리프가 '확정하지 않는다'고 한 비밀·원인·대상은 본문에서도 장부 갱신안에서도 특정하지 마라. 갱신안에는 `planned`·`belief`로만 두고, 본문 근거 칸에 실제 문장이 없으면 `confirmed`로 올리지 마라. 장부 문장이 본문 묘사와 한 글자라도 다르면 본문에 맞춰라.

[korean-fiction.md](references/korean-fiction.md)로 호칭·높임·말투·표기를 대조하라. [revision.md](references/revision.md)의 전체 약속·결말 → 인물 선택·인과 → 시점·정보 → 장면·여파·페이싱 → 대사·묘사 → 문장 리듬 → 한국어 표기 순으로 퇴고하라.

## 6. 본문 확정과 장부 갱신안

수정한 본문을 `out_path`에 쓰고 `draft`로 반환하라. 채택 본문만 근거로 `ledger_patch`를 별도로 내라. 갱신안에는 대상 파일·ID, 변경 전후, `confirmed|planned|belief`, 근거 회차·장면·문단, 충돌·미확인 사항을 적어라. 폐기한 초안의 사실을 장부에 넣지 마라. 계획은 계획으로 남기고 본문과 갱신안을 섞지 마라.

## 금지

실존 작품의 인물·설정·문장을 복제하지 마라. 확인 안 된 플랫폼 정책을 ‘허용’으로 판정하지 마라. AI 사용 여부를 문체로 추정하지 마라.

## 공통 경고

1. 구조 공식·분량 비율·합격 점수는 검증된 표준이 아니다. 하나를 강제하지 말고 의도에 맞게 고르게 하라.
2. ‘AI 초안의 실패 신호’는 편집 가설이다. AI 작성 여부 판정에 쓰지 마라.
3. 자료가 없으면 유창한 문장으로 메우지 마라. `[경험 확인 필요]` 등 작업 표시를 남겨라.
4. 플랫폼 정책은 원문·날짜·적용 범위(일반 연재/공모전/표지/본문)를 확인한 것만 써라.
