node:
  in:
    ledger_dir: { shape: text }
    action: { shape: text, values: [init, update, check, impact] }
    patch: { shape: text, list: 1, required: false }
  out:
    report: { shape: json }

# 이야기 장부

## 입력

- `ledger_dir` — 장부 폴더.
- `action` — `init|update|check|impact` 중 하나.
- `patch` — (선택, 원소 0~1개 배열) `update`의 장부 갱신안 또는 `impact`의 변경 대상 ID.

장부는 프로젝트 폴더 아래 TOML로 둔다. 필드명·ID·참조 규약은 작업 전에 [schema.md](references/schema.md)를 읽고 그대로 따른다. 스키마가 없으면 임의 형식을 만들지 말고 누락을 보고하라. 읽기는 Python 3.11+ `tomllib`, 쓰기는 모델이 직접 한다.

| 파일 | 기록 |
|---|---|
| `bible.toml` | 설정 ID·사실·적용 조건·예외·상태·최초 근거 위치 |
| `characters.toml` | 욕망·전략·관계·말투 카드·신체·소유 상태·`alive|dead`와 근거 |
| `knowledge.toml` | 정보 ID·실제 사실·인물별 인지·독자 공개 시점·근거 |
| `timeline.toml` | 사건 ID·날짜/상대 시간·지속·장소·이동 |
| `episodes/E###.toml` | 실제 사건·선택과 비용·새로 확정·미해결·다음 계획 |
| `scenes/E###-S##.toml` | 시점·입퇴장 상태·목표·저항·결과·여파·정보 범위·설치와 회수 |
| `foreshadow.toml` | 복선의 설치·재등장·회수·폐기 위치 |

모든 사실에 `status = "confirmed" | "planned" | "belief"`를 붙여라. 계획은 이야기 속 사실이 아니고 인물의 믿음은 진실과 다를 수 있다. 실제 사실·인물의 지식·독자 공개 시점을 분리하라.

## 실행

### init

기획 카드에서 첫 장부를 만들어라. 아직 본문 근거가 없는 예정 사건은 `planned`, 인물만 믿는 내용은 `belief`로 두어라. 제공된 확정 설정은 그 입력 위치를 근거로 기록하라. 빈 장부를 꾸미려고 사실을 발명하지 마라. 생성 후 `check`를 실행하라.

### update

`fiction-draft`의 갱신안을 채택 본문과 대조하라. 회차·장면·문단 근거가 있는 새 사실·상태 변화·약속만 반영하라. 폐기 초안의 사실이나 미채택 후보를 `confirmed`에 넣지 마라. 기존 확정 사실과 충돌하면 문제 위치와 근거를 보고하고 충돌을 숨기도록 기존 기록을 덮어쓰지 마라. 변경 ID·전후 상태·근거를 보고하고 `check`를 다시 실행하라.

### check

다음 명령을 실행하라. 분량 하한과 계산 방식은 플랫폼·공모전 원문에서 받은 값만 사용하라. 분량 조건이 없으면 하한 비교를 확정하지 말고 미확인으로 보고하라.

```text
python <이 스킬>/scripts/ledger_check.py <ledger_dir> --foreshadow-limit 30 --min-chars <원문 하한> --count <공백 계산 방식> --episodes-text-dir <회차 본문 폴더>
```

`--count`의 허용값과 생략 가능한 인자는 스크립트 `--help`를 확인하라. 하한이 없으면 분량 관련 선택 인자를 생략해 나머지 검사를 수행하라. 출력은 JSON이며 error가 있으면 종료 코드 1이다. 실패를 통과로 바꾸지 마라.

기계 검사 범위는 ID 중복·참조 누락·필수 필드, 명시 날짜 선후와 사건/회차 순서, `dead` 인물의 이후 장면 참여, 같은 시점 물건 소유 중복, 회수·폐기 없이 기준 회차(기본 30)를 넘긴 복선, 회차 본문 글자 수와 입력 하한이다. 글자 수는 공백 포함·미포함을 모두 보고한다. 경고 후보는 실제 시간·회상·작품 규약과 대조하라.

스크립트가 못 잡는 다음 질문은 본문과 장부를 모델이 따로 읽고 답하라.

| 질문 | 대조 근거 |
|---|---|
| 인물이 배우거나 추론하는 과정 없이 정보를 얻었는가? | 지식 장부의 획득 위치·시점과 해당 문장 |
| 관계·압박 상황 변화 없이 말투가 바뀌었는가? | 방향별 말투 카드·이전 대사 |
| 능력에 자의적인 예외가 생겼는가? | 설정의 적용 조건·예외·사용 비용 |
| 선택을 바꿀 사건 없이 동기가 급변했는가? | 욕망·전략·직전 선택과 비용 |
| 이미 겪은 깨달음을 새 깨달음처럼 반복하는가? | 이전 회차의 인식 변화·현재 행동 |

각 지적에 **문제 문장·충돌 근거·최소 수정안**을 함께 내라. 의도된 변화나 미확인은 구분하고 기계 검사 통과를 의미적 무모순 보장으로 쓰지 마라. ‘이상 없음’에도 검사한 장부 파일 해시와 검사 범위·미확인 구간을 남겨라.

### impact

설정 변경 대상 ID를 `patch`에서 받아 그 ID를 참조하는 장면·복선·요약·시간선·지식·인물을 찾아라. 직접 참조뿐 아니라 관련 상태·조건에 의존하는 본문도 읽어라. 이미 공개한 사실과 미공개 계획을 나눠 영향 위치·충돌 근거·최소 수정안을 보고하라. 영향 분석만으로 설정을 자동 변경하지 마라.

## 출력

- `report` — action·변경/검사 파일·기계 검사 JSON·모델 지적·미확인 사항·장부 해시를 담은 JSON 객체.

모델 지적은 문제 문장·충돌 근거·최소 수정안을 보존하라. 오류가 남으면 해결된 것으로 보고하지 마라.
