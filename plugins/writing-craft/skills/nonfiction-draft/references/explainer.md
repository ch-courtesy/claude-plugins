# 설명문

출처의 설명을 작업 규칙으로 재구성한 작법 도구다. 구조·비율은 검증된 표준이 아니며 실패 신호는 AI 판별 근거가 아니다.

### 핵심: 개념과 관계의 이해

설명문은 자료를 모아놓는 데서 끝나지 않는다. 독자가 혼동하는 개념의 경계나 관계를 드러내야 한다. 교육부 2022 국어과 교육과정은 설명 대상의 특성과 독자의 배경지식·관심을 고려해 설명 방법을 선택하도록 한다. 정의·인과·분석·분류 등을 모두 넣으라는 요구는 아니다. [X1][x1]

영어권 자료의 *expository essay*는 주장을 포함하는 넓은 범주로 쓰이기도 한다. 따라서 영문 자료의 장르명을 그대로 한국어 설명문과 등치하지 않고, 여기서는 **독자의 이해 형성**을 주목적으로 삼는다. Purdue 역시 다섯 문단 구성을 유일한 공식으로 제시하지 않는다. [X2][x2]

### 설명 패턴별 구조 템플릿

| 패턴 | 적합한 독자 질문 | 구조 템플릿 | 반드시 확인할 것 |
|---|---|---|---|
| 정의 | “X가 정확히 무엇인가?” | 익숙한 용례 → 상위 범주·구별 특성 → 사례·비사례 → 경계 | 설명할 말을 그 말로 다시 설명하지 않는가 |
| 분류 | “어떤 종류가 있는가?” | 분류 목적 → 기준 → 각 유형 → 경계·예외 | 같은 단계에서 기준이 바뀌지 않는가 |
| 비교·대조 | “A와 B는 무엇이 다른가?” | 비교 목적 → 공통 기반 → 기준별 차이 → 차이의 의미 | 동일한 축으로 비교하는가 |
| 인과 | “왜 일어나는가?” | 현상 → 작동 경로 → 증거 → 다른 원인·조건 → 한계 | 시간적 선후를 원인으로 오인하지 않는가 |
| 과정 | “어떻게 작동하거나 변화하는가?” | 시작 조건 → 단계 → 각 단계의 변화 → 종료 상태·분기 | 단계 사이에 무엇이 전달·변화하는가 |

과정 설명은 원리 이해를 위한 글이다. 독자가 직접 실행해야 하는 방법 글이라면 기존 Diátaxis 지침에 따라 준비물·실행 단계·성공 확인·실패 복구를 추가한다.

여러 패턴을 섞을 때는 주된 질문을 하나 정한다. 예컨대 DNS 글은 정의를 짧게 제시한 뒤, 구성요소를 구분하고 요청 처리 과정을 설명할 수 있다. 각 설명 방법은 독자의 다음 질문을 해결하는 데 사용한다. [X6][x6]

### 예시·비유 작성 절차

**예시는 적용을 보여주고, 비유는 관계를 옮겨 보여준다.**

예를 들어 ‘분류 기준’을 설명할 때 다음은 가상 예시다.

> 메모 앱을 저장 위치에 따라 로컬형과 클라우드형으로 나눈다. 다만 두 방식을 모두 지원하는 앱도 있으므로, 이 분류는 제품 전체보다 저장 방식에 적용하는 편이 정확하다.

이 예시는 분류뿐 아니라 분류 단위와 경계까지 드러낸다. 예시 하나를 실제 시장 전체의 대표 사례로 확대하지 않는다.

비유를 쓸 때는 다음 순서로 작성한다.

> 실제 개념의 짧은 설명 → 익숙한 대상과의 대응 → 이해에 도움이 되는 점 → 대응이 깨지는 지점 → 실제 개념으로 복귀

Cloudflare의 DNS 설명은 전화번호부 비유를 사용한 뒤 서버 역할과 조회 과정으로 나아간다. 스킬은 ‘DNS는 전화번호부다’라는 비유만 남기지 말고, 실제 작동 설명이 뒤따르는지 점검해야 한다. [X6][x6]

### 흔한 실패와 신호

| 실패 | 초안에서 보이는 신호 | 수정 방법 |
|---|---|---|
| 백과사전식 나열 | 소제목은 많지만 처음 질문의 답이 안 보인다 | 질문 해결에 필요한 정보만 남긴다 |
| 순환 정의 | “효율성이란 효율적인 정도다” | 상위 범주와 구별 특성으로 다시 쓴다 |
| 기준이 섞인 분류 | 초보자용·무료·기업용을 같은 단계에 놓는다 | 사용자·가격·용도를 별도 축으로 나눈다 |
| 인과의 비약 | “A 뒤 B가 증가했다. 따라서 A 때문이다” | 작동 경로와 대안 원인의 증거를 확인한다 |
| 예시가 개념을 압도 | 이야기만 기억되고 적용 기준이 남지 않는다 | 예시 뒤에 무엇을 보여줬는지 연결한다 |
| 비유의 과잉 확장 | 비유 대상의 속성을 실제 대상에도 그대로 붙인다 | 대응 가능한 속성만 남기고 한계를 쓴다 |
| 이해한 척하는 문장 | “쉽게 말해” 뒤에 또 전문용어가 나온다 | 독자가 실제로 아는 말과 사례로 바꾼다 |
| 빈 과정 설명 | “분석→최적화→완료”지만 변화가 없다 | 각 단계의 입력·처리·출력을 구체화한다 |
