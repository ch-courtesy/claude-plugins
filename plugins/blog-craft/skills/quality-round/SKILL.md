# 블로그 글 품질 공정

글을 쓰는 방법(초안 작성, 발행, PR)은 블로그마다 다르므로 이 스킬은 정하지 않는다. 이 스킬은 **어느 블로그에서든 같은 기준으로 글을 걸러 내고 끌어올리는 공정**만 정한다. 블로그별 규칙(독자 정의, 문체, 프론트매터)은 그 저장소의 규칙 문서를 입력으로 받는다.

## 입력
- 글 파일 경로(초안 전이면 주제와 자료 폴더만)
- 저장소(또는 worktree) 경로
- 자료 폴더 경로(직접 실행·확인한 로그, 재현 파일, 측정값, 첨부 원본). 없으면 "자료 없음"으로 진행하되, 사실 주장마다 범위를 밝히게 한다
- 블로그 규칙 문서 경로(독자 정의, 글쓰기 규칙). 없으면 이 플러그인 채점표만 쓴다

## 공정

### 0. 기준선
모든 단계의 기준은 "그 분야 현업 10년차 이상 시니어가 자기 이름으로 낼 수 있는가"다. 단계마다 이 질문으로 통과를 판단하고, 애매하면 통과시키지 않는다.

### 1. 주제 관문 — `topic-gate`
- 아직 초안이 없으면 반드시, 이미 초안이 있어도 처음 이 공정을 돌리는 글이면 먼저 돌린다
- `drop` 이면 여기서 멈추고 사용자에게 보고한다. 이미 공개된 글이면 "내림"을 권한다
- `narrow` 이면 줄인 주제를 사용자에게 보여 확정받은 뒤 진행한다

### 2. 초안
블로그의 초안 방식대로 쓴다(이 스킬 밖). 쓸 때 지킬 것:
- 해결을 먼저, 원인 분석을 뒤에. 단, 원인 단정은 본문 근거 수준을 넘지 않는다(요약 표와 마무리 포함)
- 독자에게 위험한 조작을 시키면 위험 절을 따로 둔다(`post-rubric` C21)
- 단계마다 받는 곳, 성공 확인법, 흔한 실패 분기를 둔다(C22)
- 소제목은 명사형(C23)

### 3. 첨부 실행 시험 — `attachment-test`
글에 다운로드 링크나 독자가 실행할 스크립트가 있으면 돌린다. P1 이 있으면 리뷰 전에 첨부부터 고치고 다시 돌린다.

### 4. 교차 리뷰 회차 (최대 3회)
- `post-review` 를 다른 회사 모델로 병렬 실행한다. 기본 조합은 글을 쓴 모델을 뺀 `codex`, `claude`, `agy` 중 둘 이상. 셋 다 쓸 수 있으면 셋 다 쓴다(벤더마다 놓치는 것이 다르다 — 2026-11-13 세 벤더 평가에서 원본 백업 삭제 버그는 한 벤더만, 다운로드 압축 문제는 한 벤더만 찾았다)
- 리뷰어 프롬프트에 이 공정을 돌리는 쪽의 판단을 넣지 않는다. 단 범위는 알려 준다: 3단계 첨부 실행 시험을 했으면 "다운로드·첨부 실행 검증은 별도 시험이 맡았다"고 적어 관점 5를 빼게 한다(결과는 알려 주지 않는다)
- 웹 검색·다운로드가 필요한 관점(쓸모의 검색 결과 비교)은 네트워크가 되는 리뷰어에게 맡긴다. codex 읽기 전용 샌드박스는 네트워크가 막혀 있을 수 있다(2026-11-14 시험에서 codex 리뷰 지적 9건이 이 때문에 '확인 못 함'으로 기각됐다)
- `apply-findings` 로 근거를 확인해 반영한다. 리뷰어 입력 때문에 생긴 오판은 기각한다
- 반영한 것이 없으면(`clean: true`) 회차를 끝낸다. 3회째에도 남으면 남은 지적을 사용자 판단으로 넘긴다
- `usefulness` P1("다시 씀/내림")이 나오면 회차를 멈추고 사용자에게 올린다

### 5. 채점 — `post-rubric`
- 글을 쓴 모델과 다른 회사 모델 하나로 채점한다(기본 `codex`)
- 2점 미만 항목을 `apply-findings` 로 한 번 반영한다
- 0점 항목이 C12(단정 일치), C14(고유 가치), C21(독자 위험), C22(끝까지 따라 하기) 중에 있으면 반영 뒤 한 번 더 채점한다

### 6. 보고
사용자에게 한 화면으로 보고한다.
- 주제 관문 판정과 독자 한 줄
- 첨부 시험 시나리오 표(통과/실패)
- 리뷰 회차별 반영·기각·보류 수, 벤더별로 혼자 찾은 지적
- 최종 채점 총점, 절별 점수, 2점 미만 항목
- 남은 판단 거리(사용자에게 묻는 것)
발행은 사용자 승인 뒤 블로그의 발행 방식대로 한다.

## 비용
리뷰 한 회차는 외부 CLI 2~3회, 채점은 1~2회다. 사용량이 빠듯하면 리뷰어를 둘로 줄이되, 첨부 시험과 주제 관문은 줄이지 않는다 — 가장 큰 결함(쓸모없는 주제, 원본을 지우는 스크립트)은 거기서 잡힌다.
