# 갈래별 뼈대와 규칙

`SKILL.md` 1단계에서 정한 갈래 하나만 읽는다. 뼈대는 순서의 기본값이다. 이 글에서 일하지 않는 칸은 빼도 되지만, **굵게 표시한 칸**은 빼지 않는다.

## A. 문제 해결·방법 글

독자는 일하는 중이고, 지금 끝내야 한다. 가르치지 않는다. 배경 설명이 필요하면 별도 절이나 링크로 뺀다.

### 뼈대
1. **제목** — 독자가 검색창에 친 말 그대로(오류 문구 원문 + 해결 대상). 무엇을 하는지 분명하게 쓴다. 명사만 늘어놓아 무엇을 하는지 모호한 제목은 피한다(소제목은 명사형, 제목은 분명하게).
2. **첫 세 문장** — 증상을 겪는 사람, 원인 한 줄, 해결 한 줄.
3. **빠른 해결** — 조건별로 나눈다. "X라면 A를 하십시오. Y라면 B를 하십시오."
4. **단계** — 번호 목록. 아래 A1~A8.
5. **확인** — 성공했을 때 보이는 화면이나 출력 원문.
6. **안 될 때** — 갈래별 다음 단계.
7. 원인 설명 — 짧게, 단계와 섞지 않고 따로. 설명 절에서는 판단을 내린다("A가 B보다 낫다. 이유는 …").
8. **버린 대안과 이유, 한계·확인한 환경**.

### 규칙
| # | 규칙 |
|---|---|
| A1 | 한 단계에 동작 하나. 메뉴를 차례로 고르는 동작은 `파일 > 새로 만들기`처럼 한 단계로 묶는다 |
| A2 | 위치를 먼저, 동작을 나중에. "엑셀에서 `데이터 > 텍스트 나누기`를 누르십시오." 절차가 소제목으로 나뉘면 각 소제목 첫머리에 위치를 다시 적는다 |
| A3 | 목적·조건을 먼저, 동작을 나중에. "새 시트를 만들려면 …", "파일이 잠겨 있으면 먼저 닫으십시오." 단, 목적을 앞세워 필수 단계가 선택처럼 들리면 쓰지 않는다 |
| A4 | 동작 다음 문장에 결과. "실행을 누르십시오. 결과 창에 12행이 나옵니다." |
| A5 | 선택 단계는 '선택:'으로 시작한다. 괄호로 처리하지 않는다 |
| A6 | 명령 앞에 "다음 명령을 실행하십시오" 같은 소개 문장을 쓰지 않는다. 명령이 하는 일을 쓴다. '부디', '꼭 ~해 주세요' 같은 공손 군더더기도 넣지 않는다. 복잡한 단계는 동작 → 명령 → 자리표시자 설명 → 출력 → 결과(별도 문단) 순서로 쓴다 |
| A7 | 방법이 여럿이면 모두에게 통하는 가장 짧은 방법 하나를 본문에, 나머지는 별도 절에 '이럴 때만' 조건을 붙여 둔다 |
| A8 | 도구 기능 단위가 아니라 독자 목표 단위로 쓴다("VLOOKUP 함수 설명"이 아니라 "다른 시트에서 값 가져오기"). 독자 파일이 달라질 때의 분기를 둔다. 독자가 이미 아는 사소한 UI 조작('저장을 누릅니다')은 생략한다 |

### A의 변형: AI·자동화 도구로 해내는 방법
독자가 해야 하는 일을 챗봇·코딩 에이전트·오피스 내장 AI 같은 도구로 끝내는 글이다. 블로그 규칙이 이 변형을 요구하면 A 뼈대의 3~5칸을 아래로 바꾼다. 'AI로 ~하기' 검색 결과에는 AI 답을 그대로 옮긴 글이 많다. 직접 시키고 검증한 기록이 없으면 이길 수 없다.

1. **실제로 쓴 지시문 원문** — 도구 이름·버전·날짜와 함께. 독자가 그대로 붙여 넣을 수 있게 코드 블록으로.
2. **도구가 낸 결과 원문** — 화면 캡처나 출력. 편집했으면 어디를 줄였는지 밝힌다.
3. **도구가 틀린 곳과 그것을 잡는 확인 방법** — 이 칸이 이 변형의 중심이다. 예: 날짜 열을 글자로 읽어 저장한 결함과 그것을 드러내는 확인 계산. 틀린 곳을 찾지 못했으면 무엇으로 확인했는지(검산, 원본 대조)를 쓴다.
4. **고친 지시문과 완성본** — 3을 막는 지시 한 줄을 더한 지시문, 그 결과.
5. **손으로 할 때와의 차이** — 걸린 시간·단계 수를 같은 조건으로. 측정하지 않았으면 쓰지 않는다.

통과 못 하는 글: 손으로 하는 절차·함수 설명만 있는 글(좁히거나 버린다), 지시문이나 결과 원문이 없는 글, 도구 목록을 늘어놓은 글.

## B. 재미·이목 글

독자는 궁금해서 들어온다. 공유되는 지점은 '의외였던 점'이다. 궁금증은 제목에서 열되 첫 화면에서 닫는다. 핵심 정보를 감추고 클릭을 요구하면 낚시다.

### 뼈대
1. **제목** — 대상, 구체 결과, 숫자 중 두 가지 이상을 흔한 말로. 궁금증은 '무엇이 나왔나'에 걸고, 결과가 있다는 사실까지 숨기지는 않는다.
2. **첫 문단** — 결과를 먼저 말하거나 짧은 장면으로 연다. 바로 뒤에 한두 문장짜리 알맹이 문단: 무엇을 해 봤고, 무엇이 나왔고, 왜 독자에게 쓸모 있는지.
3. **해 본 조건** — 환경, 기간, 횟수, 비용.
4. **결과** — 숫자, 화면, 표. 대안과 비교한다.
5. **의외였던 점** — 예상과 다른 결과.
6. **독자가 가져갈 것** — 남에게 말할 수 있는 한 문장이나 숫자 하나, 그리고 써먹을 곳.
7. **한계**.

### 규칙
| # | 규칙 |
|---|---|
| B1 | 제목의 약속은 첫 화면(약 400자) 안에서 지킨다 |
| B2 | 제목에 과장·충격 표현을 쓰지 않는다('충격', '역대급', '절대', '무조건') |
| B3 | 제목은 쉬운 말로. 한자어 명사를 겹치거나 전문어를 쓰지 않는다. 쉬운 제목이 클릭을 더 받는다(제목 A/B 시험 3만 건 이상, 효과는 작다) |
| B4 | 감정은 사실로 일으킨다. 슬픔·분노를 일부러 만들지 않는다. 부정어 제목은 클릭을 조금 늘리지만 공유에서는 방향이 다르고 시간이 지나면 약해진다 |
| B5 | 수치는 독자가 체감하는 단위로 한 번 더 바꿔 쓴다(1.3초 → 열 번 누르면 13초). 원래 수치와 환산 수치를 둘 다 적는다 |
| B6 | '해 봤다'는 증거(촬영 화면, 실행 기록, 파일)를 본문에 둔다 |
| B7 | 유행만 보고 블로그 독자와 무관한 주제를 고르지 않는다. 고른다면 독자와 이어지는 각도를 하나 찾는다 |
| B8 | 아직 없는 답(미확정 날짜 등)을 약속하지 않는다 |
| B9 | '숫자 제목이 15% 더 좋다' 류의 방법이 확인되지 않은 마케팅 수치를 제목 기교의 근거로 쓰지 않는다 |

## C. 경험기

독자는 비슷한 결정을 앞두고 있다. 모든 문단에 "이 문단이 독자의 어떤 판단을 돕나"를 묻는다. 답이 없으면 한 줄로 줄이거나 뺀다. 작업 일지를 옮긴 글은 경험기가 아니다.

### 뼈대 (처음 상태 → 한 일 → 결과 → 판단을 나눈 것)
1. **제목** — 대상 + 결과 숫자. 예: "엑셀 양식 상품 첫 달: 조회 1,200회, 판매 3건". 과장어 없이.
2. 여는 장면 — 결정적 순간 하나를 날짜, 화면 문구 원문, 행동으로 재현한다.
3. **알맹이 문단**(1~2문장) — 결과 숫자와, 이 글이 독자의 어떤 판단을 돕는지.
4. **처음 상태(기준선)** — 수치, 기간, 측정 방법.
5. 시도들 — 시간순. 각 시도에 '가설 → 한 일 → 결과'. 결정적 순간 1~2개만 장면으로 쓰고 나머지는 요약한다.
6. **전환점** — 무엇이 판단을 바꿨는지.
7. **결과** — 전후 표. 같은 단위·같은 기간으로 비교하고, 공정하지 않은 점이 있으면 밝힌다.
8. **원인** — 기여 원인 여럿. 사람이 아니라 구조와 절차로.
9. **독자가 가져갈 판단** — 조건부로. "~라면 A, ~라면 B". 반대 결론이 맞는 조건을 한 줄 넣는다.
10. **한계와 아직 모르는 것**, (선택) 다음 행동과 기한.

### 규칙
| # | 규칙 |
|---|---|
| C1 | 장면을 합치지 않는다. 시간 순서를 바꾸지 않는다. 대사나 인용을 지어내지 않는다. 순서를 바꿨다면 바꿨다고 밝힌다 |
| C2 | 필자가 한 사람으로 존재한다. 기관 말투를 쓰지 않는다. 돌아본 판단은 긴장이 걸린 순간에 짧게 두고 본 흐름으로 돌아온다 |
| C3 | 문장은 담백하게, 동사는 능동으로 |
| C4 | 원인은 "그 시점에 가진 정보로 최선을 다했다"는 전제에서 쓴다. 사람·에이전트를 탓하는 문장을 쓰지 않는다. 시스템과 절차를 고친다 |
| C5 | 조치에는 상태(완료/진행)와 기한을 붙인다 |
| C6 | 전후 비교는 같은 단위·기간·측정 방법으로. 원래 예측과 실제를 함께 쓴다. 비교 조건이 다르면 스스로 밝힌다 |
| C7 | 내부 ID(작업 번호, 결정 번호), 내부 도구·에이전트 이름, 세션 구조를 본문에 쓰지 않는다. 독자가 쓸 수 있는 말로 바꾼다 |
| C8 | 실패담은 실패한 그대로, 숫자와 함께 쓴다. '그래도 배웠다' 류의 위로 문장으로 덮지 않는다 |
| C9 | 긴장은 막힌 지점과 예상이 틀린 지점에서 나온다. 순탄한 성공 나열은 경험기가 아니다 |
