# 분해 알고리즘 — 3 조건 + 하드 캡 + 토포 정렬

dispatch 단계 2(분해)의 휴리스틱 가이드. 본 알고리즘은 PRD 본문의 정적 분석에 기반하므로 부정확 — 게이트 ①에서 사용자가 검토·수정한다.

## 1. 단위 후보 추출

PRD 본문에서 다음 신호로 후보 도출:
- **분해 힌트 섹션**이 있으면 그 항목을 우선 후보로
- "범위.포함"의 bullet 항목 (각각 별 영역으로 자주 매핑)
- "성공 기준"의 독립 검증 가능한 항목 (별 단위로 자주 매핑)
- 헤딩 ## 또는 ### 수준이 영역을 시사하면 각 헤딩을 후보로

후보가 1개로 압축되면 abort: "PRD가 분해 불필요 — spec 스킬로 진행하세요" 안내.

## 2. 3 조건 동시 충족 검사 (단위 후보별)

### 조건 1: 단일 컨텍스트 윈도우 fit

- spec 9-step 대화로 SPEC.md 완성 가능 (≤ 1 세션)
- loop 30 iter 안에 verify 통과 가능
- 후보가 자체적으로 다시 분해를 요구하면 fail → 단위를 더 작게 쪼개거나 PRD에서 빼야

### 조건 2: 테스트 폐쇄성

- 자체 verify 명령(`pytest tests/<a>`·`bash tests/<a>.sh` 등)으로 닫히는가
- 다른 단위 산출물 없이 검증 가능한가 (의존성 ≤ 1 wave depth)
- fail이면 단위를 합치거나 의존성 명시 필요

### 조건 3: 격리성

- 다른 단위와 같은 파일을 동시 수정하지 않는가
- 같은 디렉터리를 공유하더라도 다른 파일이면 OK (파일 단위 격리)
- fail이면 단위 합치기 또는 wave를 분리 (다른 wave면 순차 실행이므로 충돌 없음)

## 3. 하드 캡 검사

| 항목 | 한도 | 위반 시 |
|---|---|---|
| 1차 분해 단위 수 | ≤ 8 | abort + PRD 자체 분해 권고 |
| 재귀 분해 깊이 | ≤ 2 | abort + 단위를 합치거나 PRD 쪼개기 |
| 최종 산출 단위 수 (재귀 합) | ≤ 20 | abort + PRD 분리 |

**재귀 분해**: 알고리즘이 1 단위를 3 조건 미충족 이유로 더 작은 단위들로 다시 쪼개는 백트래킹. 깊이 = 1차 분해 후 추가 분해 라운드 수.

## 4. 의존성 추출

각 단위 쌍에 대해:
- A의 산출물(파일·심볼·API)을 B가 입력으로 쓰는가? → A → B 의존
- A가 B의 변경을 본 후에야 동작 가능한가? → A → B 의존
- 명시적 의존성이 PRD "분해 힌트" 섹션에 있으면 우선

## 5. 토포 정렬 + wave 그룹화

- DAG 구축: 노드 = 단위, 엣지 = 의존성
- cycle 감지: DFS로 백 엣지 찾으면 cycle → abort + cycle 보고
- 토포 정렬: Kahn 알고리즘 (in-degree 0인 노드를 wave로 묶음, 제거 후 반복)
- wave = 같은 토포 레벨의 단위 집합 (parallel-safe)

## 6. 출력 형식 (게이트 ①에 제시)

```
wave 1 (parallel-safe): [child-a, child-b]
  - child-a: <한 줄> | 파일 [src/a/**] | verify [pytest tests/a]
  - child-b: <한 줄> | 파일 [src/b/**] | verify [pytest tests/b]
wave 2 (depends on wave 1): [child-c]
  - child-c: ...
```

## 7. 게이트 ①의 보정 역할

본 알고리즘은 텍스트 정적 분석이라 부정확. 다음 케이스는 사용자가 수정해야:
- 단위가 너무 크다 (실제 작업은 더 쪼개야)
- 단위가 너무 작다 (재정의·합치기)
- 의존성이 누락됐다 (사용자가 알고 알고리즘이 못 본)
- wave 분할이 잘못됐다 (같은 wave에 둘 수 있는데 분리됐거나, 반대거나)

사용자 옵션 (`AskUserQuestion`): `(a) 승인`, `(b) 분해 수정` (자연어 피드백으로 알고리즘 재실행), `(c) 취소`.
