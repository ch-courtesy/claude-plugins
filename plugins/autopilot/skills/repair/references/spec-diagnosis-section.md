# 진단 섹션 형판 (산출 SPEC 에 추가)

repair step 4 가 `../../spec/references/spec-template.md` 로 만든 SPEC 본문에 **더하는** 섹션이다. spec 템플릿 자체는 수정하지 않는다 — 산출 문서에 이 섹션 하나를 추가한다. 권장 위치는 "목적 (왜)" 다음, "완료 조건" 앞이다(원인 이해가 완료 조건의 앵커가 되도록).

아래 형판의 대괄호 자리를 진단 결과로 채운다. 모호한 항목은 그 자리에 `[NEEDS CLARIFICATION: <구체 질문>]` 마커를 남긴다.

```markdown
## 진단

### 증상
- 기대 동작: <무엇이 일어나야 하는가>
- 실제 동작: <무엇이 관찰되는가>

### 재현 맥락
- 입력·환경·시점: <어떤 조건에서 나타나는가>
- 빈도: <항상 | 간헐(조건)>
- 신호: <에러 메시지·스택·로그가 지목한 파일:줄, 있으면>

### 근본 원인 가설
- 가설: <X 가 근본 원인이다 — 정적 분석 기반 가설(확정 아님)>
- 근거(정적 증거):
  - `<파일:줄>` — <이 코드가 가설을 어떻게 뒷받침하는가>
  - `<파일:줄>` — <…>
- 대안·불확실: <배제한 다른 후보, 또는 [NEEDS CLARIFICATION: ...]>
```

## 완료 조건 연계

진단의 근본 원인 가설에서 수정의 완료 조건을 도출한다. 완료 조건은 **"해당 버그가 더 이상 관찰되지 않음 + 회귀를 막는 가드"** 를 관찰 가능·독립 검증 가능하게 인코딩한다(`../../spec/references/ears-patterns.md` 5문장 패턴). 검증을 실행하는 진입 명령은 SPEC 이 아니라 `rules/` 가 단일 출처다.
