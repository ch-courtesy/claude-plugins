# using-autopilot

autopilot이 설치된 프로젝트의 워크플로 진입점 스킬. 새 코드 변경 요청을 구현·탐색보다 **먼저** 단일 진입점 `create-task`로 라우팅한다.

## 무엇인가
세션에서 새 코드 변경 신호를 감지하면 그 작업을 태스크 등록 파이프라인으로 보내는 라우팅 규칙이다. 기능 의도든 버그·증상·실패 테스트든 모두 `autopilot:create-task`라는 단일 진입점으로 보낸다 — `create-task`의 명확화 인터뷰가 기능 의도와 버그·증상을 모두 태스크 본문(=SPEC)으로 흡수한다. 등록 이후 실행 단계(`execute-task`/`workflow-task`) 선택·안내는 `create-task`의 책임이며, 이 스킬은 거기까지의 라우팅만 강제한다. 일반적인 brainstorming-first 지침을 이 범위에서 대체한다.

이 라우팅에는 **자가개선 트리거**가 가산된다: task 스킬(`create-task`/`execute-task`/`workflow-task` 및 그 엔진) 사용 중 **비정상 동작**(잘못된 blocked·무의미한 대기·모순된 상태·예기치 못한 실패 등)을 관찰하면, 단순 우회로 끝내지 말고 자가개선 판단을 시작한다 — 적대적으로 진단해 실제 결함이면 그 수정을 `create-task`로 자기완결 스펙으로 떠 등록한다. 정당한 우회(일회성 환경 이슈·사용자 명시 지시)는 예외이며, 무한 재귀를 막기 위해 관찰된 구체적 비정상 1건에 한정한다.

## 언제 활성화되나
autopilot 설치 프로젝트의 세션 시작 시, 그리고 "X 만들어줘 / 고쳐줘 / 이 SPEC·태스크 구현 / 지침 수정" 같은 새 코드 변경 신호가 보일 때. 순수 질의응답·읽기·검색·운영 명령 등은 대상이 아니다.

## 어떻게 호출하나
```
Skill(skill="using-autopilot")
```
자세한 트리거·예외·분기·합리화 차단 규칙은 [`SKILL.md`](./SKILL.md)가 단일 출처다. 이 문서는 그 계약의 사람용 요약이며 세부는 복제하지 않는다.
