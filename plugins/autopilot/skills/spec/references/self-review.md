# SPEC self-review

SPEC 작성 후 사용자 Q&A 없이 1회 자체 검토한다. 발견 사항은 인라인 수정하거나 `[NEEDS CLARIFICATION: <구체 질문>]` 마커로 남긴다.

## 5 checks

1. Placeholder: `{{...}}`, TBD, TODO, 빈 섹션 없음.
2. Consistency: 제목, WHAT, 목적, acceptance, scope, verify가 서로 충돌하지 않음. 목적 섹션이 채워져 있고 WHAT·완료 조건과 정합하며, 검증 기준이 아닌 종속 앵커로만 쓰임. 목적이 명확한데 비어있거나 placeholder만 남으면 실패로 보되, 목적이 실제로 모호해 `[NEEDS CLARIFICATION: 왜 ...]` 마커를 남긴 경우는 계약대로 허용한다(이때 마커는 보존한다).
3. Scope: `scope.include`가 필요한 변경을 포함하고 `scope.exclude`와 충돌하지 않음. 분해 발행(N개)이면 각 문서의 `depends_on`이 실제 선행 단위 slug를 가리키고, 단일 발행이면 `depends_on` 줄이 없어야 한다.
4. Ambiguity: 두 가지로 해석 가능한 요구는 구체 질문 마커로 남김.
5. 검증 가능성: 각 완료 조건이 관찰 가능하고 독립 테스트 가능하며 구현 방법을 강제하지 않음.

마커가 남으면 loop start가 차단되므로 최종 안내에서 `--resume`을 알려야 한다.

## 적대 렌즈 (페르소나) — 가산

5축 검토에 더해 세 적대적 사고 렌즈(contrarian 반대 가정 / minimalist 최소 해법 / constraint-auditor 구속력 있는 제약)를 적용한다. 각 렌즈의 전체 정의는 SKILL.md step 6이 직접 가리키는 단일 출처에 있으며, 이 절은 그 카탈로그를 복제하지 않는다.

비용 통제를 위해 기존 규모 임계가 충족될 때만 발동한다: **초안 100줄 이상 또는 `[NEEDS CLARIFICATION]` 마커 2개 이상.** 임계 미만이면 적대 렌즈 리뷰를 수행하지 않는다.

적대 렌즈는 발동 시 5축 결과에 더해 렌즈별로 태그된 **발견만 보고**하며, 새 사용자 질의응답 라운드 없이 단일 패스로 종료한다. 발견을 SPEC에 반영(수정 또는 마커 삽입)하는 주체는 메인이다 — 위임된 보조 검토자는 SPEC을 편집하거나 마커를 삽입하지 않는다. 적대 렌즈는 5축 검토를 약화·우회하지 않고 가산한다.
