# persona 카탈로그 (적대 렌즈)

SPEC 자체 검토에 더해지는 **적대적 사고 렌즈의 단일 출처**다. 이 카탈로그는 정확히 이 한 곳에만 정의하며, 다른 autopilot 스킬(예: loop)은 렌즈 정의를 **복제하지 않고 이 문서를 참조**한다. 정의 표류를 막기 위함이다.

세 렌즈는 SPEC 초안에 대해 **발견만 보고**한다. 발견을 SPEC에 반영(수정 또는 `[NEEDS CLARIFICATION]` 마커 삽입)하는 주체는 항상 메인이다 — 렌즈(또는 위임된 보조 검토자)는 SPEC을 편집하거나 마커를 삽입하지 않는다.

이 렌즈들은 기존 다축 자체 검토(`self-review.md`)를 **약화·우회하지 않고 가산**한다. 비용 통제를 위해 기존 규모 임계가 충족될 때만 발동한다 — 임계 수치의 단일 출처는 `self-review.md`다.

## 세 적대 렌즈

### 1. contrarian — 반대 가정 검증 렌즈

SPEC이 암묵적으로 전제하는 가정을 뒤집어 본다: "이 가정이 틀렸다면? 반대 케이스에서도 수용 기준이 성립하는가?" 검증되지 않은 전제, 누락된 edge/error 경로, 낙관적 가정을 발견으로 보고한다.

### 2. minimalist — 최소 해법 렌즈

"이 의도를 충족하는 가장 작은 변경은 무엇인가?"를 묻는다. 과설계, YAGNI 위반, 수용 기준이 요구하지 않는 범위 팽창, 단순화 가능한 지점을 발견으로 보고한다.

### 3. constraint-auditor — 구속력 있는 제약 식별 렌즈

제약 절에 나열된 항목 중 **실제로 구속력 있는 제약**(어기면 인수 실패)과 단순 선호·관습을 가려낸다. 가짜 제약, 근거 없는 제약, 검증 불가능한 제약을 발견으로 보고한다.

## 발견 보고 형식

각 렌즈는 렌즈 태그와 함께 발견을 보고한다.

```text
### [contrarian] / [minimalist] / [constraint-auditor]
- [위치] <발견> — <이유>
```

메인은 보고된 발견을 검토해 수정하거나 `[NEEDS CLARIFICATION]` 마커로 남긴다. 적대 렌즈 리뷰는 자체 검토 단계에서 단일 패스로 종료하며 새 사용자 질의응답 라운드를 열지 않는다.
