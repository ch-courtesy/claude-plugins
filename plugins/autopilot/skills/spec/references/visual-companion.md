# visual companion (시각 컴패니언)

spec 명확화 인터뷰의 **옵트인 보조 기능**이자 그 **메커니즘 단일 출처**다. SKILL.md는 계약(언제 제안·언제 켜고·산출물 위계)만 담고, 렌더링 방식·임시 파일 위치·폐기 절차 같은 메커니즘 세부는 이 한 곳에만 둔다(중복 금지).

컴패니언은 화면·레이아웃·구조처럼 글보다 그림으로 볼 때 더 잘 판단되는 질문에서, 사용자에게 **경량 정적 시각 미리보기(목업·구조 도식)**를 곁들여 인터뷰 판단을 돕는다. 컴패니언은 인터뷰 보조 도구일 뿐이며, 사용자의 선택·결정은 spec의 기존 명확화 질문으로 확정되어 SPEC 문서의 확정 텍스트(완료 조건·제약)에 캡처된다.

## 자기완결 모듈

이 컴패니언은 spec 본체(SKILL.md 계약)와 분리된 **자기완결 모듈**이다 — 나중에 다른 스킬(brainstorm·review 등)이 재사용할 수 있도록 spec 인터뷰 흐름에 의존하지 않는 계약으로 둔다. 단 현재 배선 대상은 spec 인터뷰뿐이며, 별도 최상위 스킬(`visual-spec`/`visual-companion`)로 분리하지 않는다.

## 활성화 경계 (언제 제안하나)

- **사람 대화 경로 한정.** 사용자가 화면을 보고 응답할 수 있는 대화형 맥락에서만 제안한다.
- **비활성 조건**: 상위 자율 오케스트레이터가 spec을 호출한 맥락(SKILL.md step 7의 자율 맥락과 동일 신호), 또는 사용자가 화면을 열 수 없는 비대화·헤드리스 맥락이면 **컴패니언을 제안하지 않고** 텍스트 인터뷰만 진행한다.
- **제안 트리거**: 인터뷰에 시각적 주제(화면·레이아웃·구조)가 예상될 때만 제안한다. 시각적 주제가 보이지 않으면 제안 자체를 하지 않는다.

## 제안 형태 (옵트인)

- 컴패니언 사용 여부를 **다른 내용과 섞지 않은 단독 메시지로 1회** 묻는다 — 인터뷰 질문이나 다른 결정과 한 호출에 묶지 않는다.
- 전달 매체는 `AskUserQuestion`(추천 답을 첫 선택지로). 자유 텍스트 질문 종결구 금지.
- 사용자가 **거부하거나 제안 자체가 없으면** 시각물 없이 텍스트 인터뷰만으로 진행한다. 제안은 반복하지 않는다(1회 한정).

## 켜진 동안 (질문별 시각/텍스트 판단)

컴패니언이 켜져도 모든 질문에 시각물을 붙이지 않는다. 질문마다 "글보다 그림이 더 나은가"를 메인이 판단해:

- 시각이 도움이 되는 질문(화면 배치·구조 비교 등)에서만 시각물을 보여준다.
- 나머지 질문은 평소대로 텍스트로 묻는다.

## 정적 렌더링 (어떻게 보여주나)

라이브 서버·실시간 통신·브라우저 클릭 수집 없이 **정적 시각물만** 사용한다.

- **터미널 텍스트 도식**: ASCII/박스 드로잉으로 화면 목업·구조 트리를 인터뷰 메시지 안에 직접 그린다(추가 파일·도구 불필요, 환경 도달성 최상).
- **정적 파일 열기**: 더 풍부한 미리보기가 필요하면 임시 디렉토리에 정적 파일(예: 단일 HTML/마크다운/이미지)을 만들고 그 경로를 사용자에게 알려 사용자가 직접 연다.

금지: 라이브 HTTP 서버·WebSocket·실시간 통신·브라우저 클릭 events 수집·events 파일. brainstorming Visual Companion의 라이브 서버·frame-template 류 코드를 포팅하지 않는다.

### 임시 파일 위치

정적 파일 방식을 쓸 때는 저장소 밖 임시 영역(예: `mktemp -d`로 만든 OS 임시 디렉토리)에 둔다. SPEC 디렉토리(`docs/specs/...`)나 저장소 작업 트리 안에 시각물을 만들지 않는다 — 임시 파일 위생은 `rules/workspace/temp-files.md`를 따른다.

## 산출물 위계 (무엇이 권위인가)

- 권위 산출물은 SPEC.md의 확정 텍스트(완료 조건·제약)뿐이다.
- 시각물을 보여준 질문이라도 **사용자의 최종 선택은 spec의 기존 명확화 질문(`AskUserQuestion`)으로 받아** SPEC 문서의 확정 텍스트에 반영한다.
- 시각물 자체는 **인수 기준이 아니다** — 보여준 목업·도식은 검증 대상이 아니며 SPEC의 완료 조건이 되지 않는다.

## 폐기 (인터뷰가 끝나면)

- 인터뷰가 끝나면 컴패니언이 만든 시각물·임시 파일은 **폐기**한다 — SPEC 디렉토리·저장소에 남기지 않는다.
- 컴패니언은 task·이슈·브랜치·원격 등 **어떤 외부 상태도 만들지 않는다.** spec의 "외부 상태 무생성 / SPEC 문서만 산출" 계약을 그대로 보존한다.
- 정적 파일을 임시 디렉토리에 만들었으면 인터뷰 종료 시 그 임시 디렉토리를 삭제한다(`rules/workspace/temp-files.md`).

## 트레이드오프

경량 정적 렌더는 brainstorming의 실시간 클릭-선택 UX(인터랙티브 목업의 즉시성)를 제공하지 못한다 — 선택은 기존 명확화 질문으로 받으므로 이는 의도된 트레이드오프다. 옵트인 + 질문별 판단으로 기본 텍스트 경로를 그대로 유지해, 시각이 불필요한 작업에서는 인터뷰가 종전과 동일하게 진행된다.
