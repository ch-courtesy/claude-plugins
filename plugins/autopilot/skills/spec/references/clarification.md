# clarification methodology

명확화 라운드의 **단일 방법론 출처**. step 3 명확화 라운드가 이 한 곳을 가리킨다 — 방법론을 다른 파일에 복제하지 않는다.

평면 질문 목록(목적·성공기준·제약·위험)을 한 번에 나열하지 않는다. **결정 트리(decision tree)를 따라 내려가는 적응적 인터뷰**다. 전달 매체는 항상 `AskUserQuestion`(구조화 질문) — 자유 텍스트 질문 종결구 금지.

## 네 원칙

### 1. 집요함 (relentless)

공유 이해에 도달할 때까지 캐묻는다. 모호한 답·암묵 가정은 되짚어 좁힌다. 단 무한 grilling 금지 — "충분" 종결 조건:

- 미해결 결정이 없다 (SPEC 모든 섹션을 모호성 없이 채울 수 있다)
- 사용자가 명시적으로 충분/중단
- 마일스톤 규모로 판정 (범위 분해 게이트에서 분해/PRD 승격 제안)

종결 시 남은 미세 항목은 캐묻기를 멈추고 `[NEEDS CLARIFICATION: <질문>]` 마커로 SPEC에 위임한다.

### 2. 결정 트리 (decision-tree)

한 번에 한 질문. 결정 간 의존성을 따라 내려가며, **선행 답이 후속 질문을 가지치기(prune)한다.** 예: "새 모듈 신설이냐 기존 확장이냐"의 답이 "어느 파일을 손대나" 질문지를 좁히거나 통째로 제거한다. 서로 의존하는 결정을 한 번에 쏟지 않고, 상위 결정부터 해소해 하위 질문을 조정한다.

### 3. 추천 답 (recommended-answer)

매 질문에 추천 답과 한 줄 근거를 함께 제시하되, **추천 답을 구조화 질문의 첫 선택지**로 둔다(레이블 끝에 "(추천)" 표기). 근거는 관찰된 코드·룰·선례 같은 사실에 둔다 — 근거 없는 추천 금지. 사용자는 추천을 수락하거나 다른 선택지를 고른다.

### 4. 코드 우선 (codebase-first)

한 질문이 **코드 탐색(codebase exploration)만으로 답할 수 있으면 사용자에게 묻지 않고 직접 탐색해 해소한다.** 탐색으로 확정한 사실은 추천 답의 근거로 인용한다. 코드로 답이 안 나오거나, 가치 판단·우선순위·미래 의도가 필요한 결정만 사용자에게 묻는다.

**step 1(컨텍스트 탐색)과의 역할 경계**: step 1은 인터뷰 진입 *전* SPEC 전반을 위한 1회 일괄 탐색(테스트 컨벤션·룰·구조 요약)이다. 코드 우선은 인터뷰 *중* 특정 질문이 떠올랐을 때의 표적 탐색(그 질문 한정)이다. 시점·범위가 다르다 — 같은 탐색을 중복 수행하지 않고, step 1 요약을 먼저 활용한 뒤 부족분만 표적 탐색한다.
