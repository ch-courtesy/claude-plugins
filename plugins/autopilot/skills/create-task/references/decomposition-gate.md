# 범위 분해 게이트 (create-task 자체 소유)

한 번의 인터뷰에서 태스크를 **몇 개** 발행할지만 결정한다. 추천 실행 경로는 가르지 않는다.

## 다중 발행 신호 (둘 이상 해당이면 분해 후보)

- **접속사 다중** — "그리고", "또한"으로 독립적 동작이 여러 개 묶여 있다.
- **명사 영역 다양성** — 서로 다른 서브시스템·모듈·계층을 건드린다(예: 파서 + UI + 저장).
- **파일 트리 분산** — 변경이 명백히 분리된 디렉토리들에 흩어진다.
- **완료 기준 분리** — 수용 기준이 서로 독립적인 묶음으로 갈린다.

## 규칙

- 신호가 충분하면 **독립 서브시스템마다 1개 태스크**를 발행하고, 선후 관계가 있으면 `depends_on`으로 연결한다.
- 신호가 약하면 **정확히 1개** 태스크로 발행한다(과분해 금지 — 카파시 단순함 우선).
- 한 태스크는 "한 에이전트가 한 세션에 끝낼 수 있는 분량"을 넘지 않게 자른다.
- 분해는 발행 개수만 정한다 — 실행은 항상 `execute-task`/`workflow-task`가 한다.
