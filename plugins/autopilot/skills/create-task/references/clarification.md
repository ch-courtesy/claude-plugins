# 명확화 인터뷰 방법론 (create-task 자체 소유)

태스크 본문을 자기완결적으로 뜨기 위한 인터뷰 방법이다. 플러그인 자기완결 — 외부 스킬·`rules/`를 참조하지 않는다.

## 깔때기형 단일 흐름

- 사용자가 처음 한 말을 되짚는 데서 시작해, 직전 답에서 다음 질문이 파생되며 점점 깊이 파고든다.
- 고정 카테고리 목록을 나열해 묻지 않는다. 아래 **내부 커버리지 체크리스트**는 사용자에게 보이지 않는, 인터뷰가
  충분히 짚었는지 점검하는 내부 도구일 뿐이다.

## 내부 커버리지 체크리스트

- **목적(왜)** — 이 변경이 달성하려는 결과/동기.
- **성공 기준(무엇이 끝)** — 관찰 가능·독립 테스트 가능한 완료 조건.
- **제약** — 기술 스택·경계·하면 안 되는 것.
- **위험** — 실패 모드·부작용·되돌리기 어려움.

## 방법

- 전달 매체는 `AskUserQuestion`(한 번에 한 주제, 추천 답을 첫 선택지로). 자유 텍스트 질문 종결구 금지.
- **집요함** — 모호하면 한 번 더 좁혀 묻는다. "대충 알겠다"로 넘어가지 않는다.
- **추천 답** — 합리적 기본값을 첫 선택지로 제시해 결정 비용을 낮춘다.
- **코드 우선** — 기존 코드·구조에서 답이 보이면 묻기 전에 먼저 확인한다(step 1 컨텍스트 탐색).
- **종결** — 커버리지 체크리스트 4영역이 모호성 없이 잡히면 충분으로 보고 본문 작성으로 넘어간다. 사용자가
  "충분"을 선언하면 즉시 종결하고 남은 항목은 `[NEEDS CLARIFICATION]` 마커로 남긴다.

검증 진입 명령·테스트 화이트리스트 같은 구현-검증 관심사는 묻지 않는다(실행 스킬의 몫).
