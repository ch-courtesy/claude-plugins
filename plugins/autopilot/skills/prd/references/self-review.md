# PRD 자체 검토 체크리스트

prd 스킬은 PRD.md 작성 직후 (단계 7) 또는 `--import` 모드의 시작점에서 다음 5항목을 자체 점검합니다. 발견 시 인라인 수정 또는 `[NEEDS CLARIFICATION: <질문>]` 마커만 — 재루프 없음, 사용자 Q&A 없음. 마커는 단계 8/9 사용자 최종 검토에서 일괄 해결.

## 1. Placeholder 스캔

다음 패턴이 PRD.md에 남아 있으면 안 됨:
- `{{...}}` 미치환 placeholder
- `TBD`, `TODO`, `FIXME`, `XXX`
- 빈 섹션 (헤더만 있고 본문 없음 — 제약·위험·분해 힌트 제외)

발견 시: 인라인으로 채울 수 있으면 채우고, 모호하면 `[NEEDS CLARIFICATION: <구체 질문>]` 마커.

## 2. 내부 모순 검사

다음 모순 패턴 자동 검사:
- "문제"가 X를 명시했는데 "성공 기준"에 X 관련 기준 없음
- "범위.포함"과 "범위.비-목표"가 같은 경로·기능 영역을 모두 포함
- "성공 기준"에 "제약"이 금지하는 항목이 등장
- "목표"가 "위험"에 적힌 dead-end를 다시 제안

발견 시: `[NEEDS CLARIFICATION: 모순 — A: <한쪽 표현> / B: <다른쪽 표현>, 어느 쪽이 정답?]` 마커.

## 3. 범위 검사 (decomposable)

PRD는 본래 다중 task로 분해될 큰 단위를 정의한다. 다음 신호로 분해 가능성 검토:
- "범위.포함"이 명확히 분리되는 영역 2개 이상 나열 가능?
- "성공 기준"이 독립적으로 검증 가능한 항목 3개 이상?
- "분해 힌트"가 비어 있어도 dispatch가 추출할 신호가 본문에 충분한가?

문제 신호:
- **너무 큼**: 분해 후보가 명백히 8개를 초과할 듯 — dispatch 1차 분해 캡 초과 위험. `[NEEDS CLARIFICATION: 범위가 분해 한계(8 단위)를 초과할 가능성. PRD를 두 milestone으로 쪼개야 하나?]`
- **너무 작음**: 분해 가능 신호가 1개 영역 미만 — 이건 PRD가 아니라 SPEC이어야. `[NEEDS CLARIFICATION: 단일 영역으로 보임. spec 스킬을 쓰는 게 맞나?]`

## 4. 모호성 검사

다음 어휘는 모호 신호:
- "적절한", "충분한", "합리적인", "필요한 만큼" — *얼마나*가 안 정해짐
- "유저 친화적", "직관적", "심플하게" — 측정 불가
- "또는 비슷한", "등등", "기타" — 열거 미완

발견 시: 구체화 (수치·기준·예시) 또는 `[NEEDS CLARIFICATION: <구체 질문>]`.

## 5. 마커 잔존 검사

이전 라운드에서 박힌 `[NEEDS CLARIFICATION` 마커가 단계 6 작성 후에도 남아 있는지 최종 검사. 단계 9 안내에 영향.

- 0개: 단계 8 사용자 검토 후 dispatch 안내
- 1개 이상: 단계 9에서 `--resume` 안내 후 정상 종료 차단

## 검토 출력 형식

자체 검토 후 사용자에게:
- 0개 발견: "자체 검토 통과. 사용자 최종 검토로 진행합니다."
- 1개 이상: "자체 검토에서 N개 항목 인라인 수정·N개 마커 박음. 변경된 PRD.md를 사용자 최종 검토하세요."
- `--import` 모드: "외부 PRD 자체 검토 완료. N개 마커 박음. 해결: --resume"
