# 자체 검토 5축 (feature 자체 소유)

태스크 본문을 등록 전에 점검한다. 발견은 수정하거나 `[NEEDS CLARIFICATION]` 마커로 남기되, 새 Q&A 라운드나
재루프는 하지 않는다(단일 패스).

1. **placeholder** — 채우지 않은 자리·예시값·TODO가 남아 있지 않은가.
2. **모순** — 목표·제안·완료 기준 사이에 서로 어긋나는 진술이 없는가.
3. **범위** — 요청 범위를 넘는 기능·추상화가 섞이지 않았는가(외과적·최소). 반대로 빠진 핵심이 없는가.
4. **모호성** — 해석이 둘 이상 가능한 표현이 없는가. 있으면 좁히거나 마커.
5. **검증 가능성** — 완료 기준이 관찰 가능·독립 테스트 가능한가. "잘 동작한다" 같은 비검증 표현 금지.
6. **scope.include** — frontmatter `scope.include` 가 비어 있지 않고, 식별한 변경 대상을 합리적으로 덮는가
   (과좁으면 정당한 변경이 halt 되므로 불명확할 땐 보수적으로 넓게). 특히 완료 조건이 테스트(회귀 가드)를
   요구하면 그 테스트 경로가 `scope.include` 에 포함됐는가(누락 시 loop 이 RED 테스트를 scope 밖이라 halt).

## 규모 임계 시 적대 렌즈(가산)

본문이 크거나 위험이 높으면 세 렌즈를 가산 점검한다(발견만 보고, 수정은 본 흐름이):

- **반대 가정** — 핵심 가정이 틀렸다면? 무너지는 지점은?
- **최소 해법** — 더 단순한 방법으로 같은 완료 기준을 달성할 수 있는가?
- **구속력 있는 제약** — 누락된 비기능 제약(보안·성능·호환)이 완료를 좌우하지 않는가?
