# 태스크 본문(=SPEC) 구조 (feature 자체 소유)

태스크 본문이 설계의 단일 출처다. 별도 SPEC 파일을 만들지 않는다. 본문 섹션 순서(고정) — 백엔드 공통이며
정규 정의는 플러그인 `task-backend/contract.md`와 일치한다.

```markdown
## 목표
측정·확인 가능한 결과 상태를 1~3문장으로. WHAT(무엇을 이룰지)만 — 기술 스택·파일 경로 같은 HOW는 제약으로.

## 배경
문제·상황·리스크를 처음 보는 사람도 이해할 만큼.

## 제안
접근·구현 순서·도구·대안과 선택 이유를 실행 가능하게.

## 검증 계획
완료 기준을 어떻게 확인하는지(테스트·관찰 지표·수동 단계). 진입 명령 자체는 적지 않는다.

## 완료 기준 (Definition of Done)
- [ ] 관찰 가능·독립 테스트 가능한 조건
- [ ] ...
```

## 작성 규칙

- **WHAT/HOW 방어선** — 목표·완료 기준에는 "무엇"만. 기술 선택·경로·라이브러리 같은 "어떻게"는 제안/제약에.
- **완료 기준**은 각 항목이 관찰 가능하고 독립적으로 테스트 가능해야 한다(실행 스킬이 이걸로 검증).
- 미해결 항목은 `[NEEDS CLARIFICATION: <구체 질문>]` 마커로 남긴다 — 마커가 있으면 무인 실행이 차단된다.
- 본문은 자기완결이어야 한다 — 실행 스킬이 본문만 읽고 중간 질문 없이 구현할 수 있을 만큼.
