# fix

**무엇** — 버그·증상·실패 신호를 **정적 분석으로 진단**해 자기완결적 **태스크 본문**(진단 섹션 포함)으로
뜨는 **작성자(authoring) 스킬**. 본문이 곧 SPEC이며 별도 SPEC 파일은 만들지 않는다.

**언제** — 'X 버그/에러', '테스트가 실패해' 신호에서 코드·로그를 읽어 근본 원인을 가설로 좁혀, 무인 실행
가능한 수정 태스크로 떠 등록하고 싶을 때. 사용자 직접 호출과, `workflow-task` 드레인자가 자율 주행 중 버그
신호를 감지해 중앙에서 호출하는 두 경로가 있다.

**어떻게** — 작성만 책임진다. 정적 분석으로 본문을 떠서 **등록 프리미티브 `create-task`** 에 넘기면,
등록·백엔드 준비·등록-후 상태 전이(완성→backlog / 미해결→in_design)는 `create-task`가 소유한다. 미해결
마커가 남은 본문은 `feature` 인터뷰 재개로 사람과 함께 이어 완성한다.

**짝** — `feature`(대화형 인터뷰 작성자)의 정적분석 형제. (SPEC-파일 계열 `repair`는 그대로 보존 — fix는 그
진단 방법론을 참고하되 별도 스킬.)

**호출** — `Skill(skill="fix", args="<버그/증상/실패 신호>")`.

**자기완결** — 컨슈밍 프로젝트 `rules/`나 다른 스킬(spec·repair 등)의 참조에 의존하지 않는다. 진단 방법론은
`references/`가, 작성자 공용 참조(본문 템플릿·자체 검토·완료 조건 패턴)는 플러그인 공용
`plugins/autopilot/lib/references/`가 단일 출처. 상세는 `SKILL.md`를 따른다.
