# 자체 검토 (작성자 공용 — feature·fix)

태스크 본문을 등록 전에 점검한다. 플러그인 자기완결 — 외부 스킬·`rules/`를 참조하지 않는다. 발견은 수정하거나
`[NEEDS CLARIFICATION]` 마커로 남기되, 새 Q&A 라운드나 재루프는 하지 않는다(단일 패스).

## 6축 점검

1. **placeholder** — 채우지 않은 자리·예시값·TODO가 남아 있지 않은가.
2. **모순** — 목표·제안·(fix: 진단)·완료 기준 사이에 서로 어긋나는 진술이 없는가.
3. **범위** — 요청 범위를 넘는 기능·추상화가 섞이지 않았는가(외과적·최소). 반대로 빠진 핵심이 없는가.
4. **모호성** — 해석이 둘 이상 가능한 표현이 없는가. 있으면 좁히거나 마커.
5. **검증 가능성** — 완료 기준이 관찰 가능·독립 테스트 가능한가. "잘 동작한다" 같은 비검증 표현 금지.
6. **scope.include** — frontmatter `scope.include` 가 비어 있지 않고, 식별한 변경 대상을 합리적으로 덮는가
   (과좁으면 정당한 변경이 halt 되므로 불명확할 땐 보수적으로 넓게). 특히 완료 조건이 테스트(회귀 가드)를
   요구하면 그 테스트 경로가 `scope.include` 에 포함됐는가(누락 시 loop 이 RED 테스트를 scope 밖이라 halt).
   또한 `scope.include`에 기존 테스트 파일 경로가 있으면 `test_sweep_paths`에도 선언됐는가(누락 시 loop의
   테스트 약화 게이트 HALT).

## 진단 섹션 전용 점검 (fix 전용)

- **가설 프레이밍** — 근본 원인이 확정이 아닌 가설로 적혔는가.
- **증거** — 가설을 뒷받침하는 `파일:줄` 증거가 실렸는가(누락 시 마커).
- **정적 한정** — 실행·재현·디버거 부착을 가정한 진술이 섞이지 않았는가(정적 분석 위반 금지).
- **완료 기준 연계** — 완료 기준이 "버그 미관찰 + 회귀 가드"를 인코딩하는가.

## 규모 임계 시 적대 렌즈 (가산)

본문이 크거나 위험이 높으면 세 적대 렌즈(contrarian·minimalist·constraint-auditor)를 가산 점검한다 — 렌즈
정의의 단일 출처는 `personas.md`(같은 디렉터리)이며 복제하지 않고 참조한다. 렌즈는 **발견만 보고**하고 수정은
본 흐름이 한다. fix 에서 위임이 필요하면 fix `references/agent-prompts.md`의 `fix-body-reviewer`를 쓴다.
