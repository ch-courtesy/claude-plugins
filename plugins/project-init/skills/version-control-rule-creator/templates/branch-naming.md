          ## type 접두사

          - 기능 추가 작업은 `feature/`(또는 `feat/`)를 씁니다. 그 외 표준 type: `fix/`(버그 수정), `chore/`(잡무·설정), `docs/`(문서), `refactor/`(동작 불변 정리), `test/`(테스트).

          ## 표기: 소문자 kebab-case

          브랜치 이름의 요약 부분은 **소문자 kebab-case**로 적습니다.

          - 단어는 하이픈(`-`)으로 잇고, 공백·대문자·언더스코어(`_`)·연속 하이픈은 쓰지 않습니다.

          ## 이슈/티켓 ID

          브랜치 이름에 관련 **이슈·티켓 ID**를 포함해 작업 항목과 브랜치를 연결합니다.

          - 형식: `<type>/<id>-<요약>`(예: `feature/123-login-rate-limit`) 또는 추적 시스템 키를 그대로(예: `feature/PROJ-123-...`).
          - ID는 추적 시스템의 식별자를 그대로 옮겨 적어, 브랜치에서 원본 작업 항목을 바로 찾을 수 있게 합니다.

          ## 길이·금지문자

          브랜치 이름은 짧고 도구 안전한 문자만 씁니다.

          - 길이는 간결하게 유지합니다(예: 50자 이내). 요약은 작업을 알아볼 수 있는 최소한으로 적습니다.
          - ASCII 영문·숫자·하이픈·슬래시(type 구분자) 외의 문자(공백·유니코드·`~^:?*[` 등)는 쓰지 않습니다 — git 레퍼런스 규칙과 도구 호환성을 지킵니다.
          - 마침표로 끝나거나 `.lock`으로 끝나는 이름, `..`·`@{`를 포함하는 이름은 git이 거부하므로 쓰지 않습니다.
