# 완료 게이트 지침

개발 워크플로(설계 → 구현 → 리뷰 → 반복 → **완료**)의 **완료 단계 게이트**를 정하는 규칙입니다. 이 지침은 워크플로 "척추(spine)"의 마지막 전이 — 리뷰가 통과 게이트를 넘으면 완료 단계로 전이하고, 그 단계에서 변경 통합(머지)과 머지 후 정리가 수행된다 — 에 대한 **흐름·전이 조건·책임 위임선의 단일 출처**입니다.

## 적용 범위

이 지침은 **완료 단계로의 전이와 그 단계가 위임하는 책임 경계**에만 적용됩니다.

- **규정하는 것**: 리뷰 통과 게이트의 조건(무엇이 충족되면 게이트를 넘는가), 게이트 통과 시 완료 단계로의 전이, 그리고 완료 단계에서 일어나는 변경 통합·머지 후 정리·작업 상태 전이의 **위임 경계**(누가 책임지는가).
- **규정하지 않는 것(위임)**: 변경 통합·머지의 기계적 절차는 **version-control** 카테고리, 작업 상태 전이는 **context** 카테고리, 빌드·버전은 **engineering** 카테고리가 단일 출처로 정의합니다. 이 지침은 그 책임들을 중복 정의하지 않습니다.
- 머지·정리의 *방법*(base sync·push·변경 제안 생성·승인·머지·cleanup 명령이나 절차)은 이 지침의 범위가 아닙니다 — 여기서는 오직 **언제 완료로 전이하고 어디에 위임하는가**만 정합니다.

## 게이트 정의 (필수 규칙)

**리뷰 통과 게이트를 넘은 변경만 완료 단계로 전이한다.**

- **게이트 조건**: 변경이 리뷰 단계의 통과 기준을 만족해야(미해결 차단 의견이 없고 합의된 승인선을 넘어야) 게이트를 넘습니다. 게이트를 넘지 못한 변경은 완료 단계로 전이하지 않고 반복(리뷰 → 수정 → 재리뷰) 단계에 머뭅니다.
- **전이**: 게이트를 넘으면 워크플로는 완료 단계로 전이합니다. 완료 단계는 워크플로 척추의 마지막 단계이며, 여기서 변경 통합(머지)과 머지 후 정리가 수행됩니다.
- **단계 책임의 위임**: 완료 단계가 수행하는 일은 모두 직교 축에 위임됩니다 — 변경 통합·머지는 **version-control**, 작업 상태 전이(예: 작업을 완료로 표시)는 **context**, 빌드·버전 범프는 **engineering** 카테고리가 단일 출처입니다. 이 지침은 그 절차를 담지 않고 어느 단계에서 누구에게 위임되는지의 **경계만** 고정합니다.

게이트의 *의도*는 자기완결로 읽힙니다: **리뷰 통과 = 완료로 가는 단일 관문**이고, 관문 뒤의 기계적 작업은 본 지침이 아니라 위 축들이 정의합니다. 타깃 프로젝트에 version-control·context 카테고리 룰이 아직 없더라도, 이 게이트가 "무엇을 통과시키고 어디로 전이하는가"는 위 정의만으로 충분히 읽힙니다.

## 위반 발견 시

리뷰 통과 게이트를 넘지 않은 변경이 완료 단계로 전이했거나, 완료 단계의 머지·정리·상태 전이 절차가 본 지침 본문에 직접 규정되어(version-control·context·engineering 위임을 우회해) 중복 정의된 것을 발견하면 즉시 멈추고 정상화합니다 — 게이트 미통과 변경은 반복 단계로 되돌리고, 중복 정의된 기계적 절차는 해당 카테고리 단일 출처로 위임을 환원합니다. 다음 작업으로 미루지 않습니다.
