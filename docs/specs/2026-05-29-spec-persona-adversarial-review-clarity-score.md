# spec 스킬: persona adversarial review + clarity score

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

autopilot `spec` 스킬에 두 가지 가산 기능을 추가한다. 두 기능 모두 기존 동작·계약을 대체하지 않고 보강하며, 새 런타임·엔진·의존성을 도입하지 않는다.

1. **페르소나 기반 적대적 리뷰 (spec측).** 자체 검토 단계에 세 가지 적대적 사고 렌즈를 추가한다 — *반대 가정을 검증하는 렌즈*, *최소 해법을 묻는 렌즈*, *실제로 구속력 있는 제약만 가려내는 렌즈*. 이 렌즈들은 기존 자체 검토의 규모 임계(초안이 일정 길이 이상이거나 미해결 마커가 일정 수 이상)가 충족될 때만 발동해 비용을 통제한다. 렌즈는 SPEC 초안에 대해 **발견만 보고**하고, 발견을 SPEC에 반영(수정 또는 미해결 마커 삽입)하는 주체는 항상 메인이다. 페르소나 정의는 단일 출처 문서로 두고, 다른 스킬이 복제 없이 참조할 수 있게 한다.

2. **정량 clarity 점수 (spec측).** 명확화 인터뷰가 잠정 종결에 이르렀을 때, 목적·제약·성공기준(필요 시 범위·위험)의 명확도를 메인 에이전트의 추론으로 산정한 경량 점수를 사용자에게 차원별로 제시한다. 점수가 권장 임계 미만이면 구조화된 선택지로 추가 명확화 라운드를 권고하되, 이는 **소프트 권고**일 뿐이며 SPEC 작성을 차단하거나 자동 게이트가 되지 않는다. 점수는 기존 미해결 마커 시스템과 그 마커에 의한 자율 실행 차단을 **보완할 뿐 대체하지 않는다**.

## 수용 기준 (EARS)
<!-- EARS 5패턴과 언어 규칙은 references/ears-patterns.md. 각 기준은 관찰 가능하고 독립 검증 가능해야 함. -->

**페르소나 적대적 리뷰**

- When SPEC 초안이 기존 자체 검토의 규모 임계(초안 길이 상한 또는 미해결 마커 수 임계)를 충족하면, 시스템은 기존 다축 자체 검토 결과에 더해 세 적대 렌즈별로 태그된 발견 항목을 산출해야 한다.
- While SPEC 초안이 그 규모 임계 미만인 동안, 시스템은 적대 렌즈 리뷰를 수행하지 않아야 한다.
- When 적대 렌즈가 발견 항목을 산출하면, 그 발견을 SPEC 초안에 반영(수정 또는 미해결 마커 삽입)하는 주체는 메인이어야 하며, 위임된 보조 검토자는 SPEC을 편집하거나 마커를 삽입하지 않아야 한다.
- While 적대 렌즈 리뷰가 자체 검토 단계에서 수행되는 동안, 시스템은 새 사용자 질의응답 라운드를 열지 않고 단일 패스로 종료해야 한다.
- The 페르소나 카탈로그는 정확히 한 곳에 정의되어야 하며, 다른 autopilot 스킬은 그 정의를 복제하지 않고 참조해야 한다.
- The 적대 렌즈 리뷰는 기존 다축 자체 검토를 약화하거나 우회하지 않고 그것에 가산되어야 한다.

**정량 clarity 점수**

- When 명확화 인터뷰가 잠정 종결 상태에 도달하면, 시스템은 차원별(목적·제약·성공기준) clarity 리드아웃을 사용자에게 제시해야 한다.
- If clarity 점수가 권장 임계 미만이면, 시스템은 구조화된 선택지를 통해 추가 명확화 라운드를 권고해야 하며 자유 텍스트 질문으로 권고하지 않아야 한다.
- When 사용자가 추가 명확화를 거부하거나 충분함을 선언하면, 시스템은 점수와 무관하게 SPEC 문서 작성으로 진행하고 미해결 항목을 기존 미해결 마커로 남겨야 한다.
- The clarity 점수는 소프트 권고여야 하며 SPEC 작성을 차단하거나 자동 게이트로 동작하지 않아야 한다.
- The clarity 점수는 기존 미해결 마커 시스템과 그 마커에 의한 자율 실행 차단을 보완해야 하며 대체하지 않아야 한다.
- The clarity 점수는 메인 에이전트의 추론만으로 산정 가능해야 하며 새 엔진·의존성·런타임을 요구하지 않아야 한다.
- The clarity 점수의 차원과 권장 임계는 단일 스킬 참조 문서에 정의되어야 한다.

**불변(가산성 보장)**

- The 기존 미해결 마커 동작과 마커 해결 재개 흐름은 본 변경 후에도 동일하게 유지되어야 한다.

## 범위
포함:
- autopilot `spec` 스킬의 페르소나 카탈로그(신규 단일 출처 참조 문서)
- autopilot `spec` 스킬의 자체 검토 정의에 적대 렌즈 절 추가(기존 규모 임계로 발동)
- autopilot `spec` 스킬의 보조 자체 검토 위임 양식에 적대 렌즈 질문 추가(발견만 보고, 편집·마커 삽입 금지)
- autopilot `spec` 스킬의 clarity 점수 정의(신규 단일 출처 참조 문서: 차원·척도·메인 추론 산정·권장 소프트 임계·보완 규칙)
- autopilot `spec` 스킬의 명확화 종결 단계에 clarity 점수 산정·제시·소프트 권고 추가
- autopilot `spec` 스킬 진입 문서의 단계 설명·참조 표 갱신
- autopilot `spec` 스킬의 보조 위임 양식에 존재하는 단계 번호 오기 정정(실제 단계 수와 일치)
- 위 변경에 대응하는 spec 스킬 계약·설치 테스트의 가산 assert

비-목표 / 제외:
- loop 스킬측 페르소나 검증·lateral 회복(별도 SPEC)
- 무거운 Ouroboros 차용(SPEC 자가진화, event-sourcing replay, 모델·비용 티어링, 다중모델 합의 게이트)
- 점수를 자동 차단 게이트로 만드는 것 / 미해결 마커 시스템 대체
- 검증 진입 명령(테스트·lint·빌드)의 SPEC 내 선언

## 검증

이 SPEC의 인수 바는 위 **수용 기준 (EARS)**이다. 각 기준이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약 (있을 때만)
- 철학 불변: 경량·무인프라(SQLite/데몬 없음), 사람 게이트, 워커에게 SPEC 불변, Claude Code 네이티브(스킬 마크다운 + subagent 위임). 새 런타임·엔진·의존성 금지.
- 보조 검토자는 발견만 보고하고 메인이 결정·반영한다(중첩 dispatch 금지).
- 페르소나 카탈로그는 단일 출처로 두고 loop 스킬이 복제 없이 참조한다(이 SPEC이 카탈로그의 저작 주체).
- 본 변경은 `plugins/` 워치 디렉터리를 건드리므로, 기본 브랜치 머지 시 같은 머지에서 `plugins/autopilot/.claude-plugin/plugin.json`과 `.claude-plugin/marketplace.json`의 autopilot 버전을 0.7.0 → 0.8.0(MINOR, 가산·하위호환)으로 동반 상향해야 한다. 버저닝 규칙의 단일 출처는 `rules/engineering/versioning.md`다.

## 위험 (있을 때만)
- 적대 렌즈가 항상 켜지면 비용·지연이 증가한다 → 기존 규모 임계로만 발동해 완화.
- clarity 점수가 하드 게이트로 오해·구현되면 사람 게이트 철학을 침해한다 → 소프트 권고·마커 보완임을 참조 문서와 수용 기준에 명시해 완화.
- 페르소나 정의 중복은 표류를 부른다 → 단일 출처 + 참조로 완화.
