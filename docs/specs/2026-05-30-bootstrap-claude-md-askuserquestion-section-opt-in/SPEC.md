# bootstrap CLAUDE.md AskUserQuestion section opt-in

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
bootstrap 스킬이 새 프로젝트의 `CLAUDE.md`를 **신규 생성**할 때, 그 안의 **"Claude 상호작용 규칙"(AskUserQuestion 사용 지침) 섹션을 포함할지 사용자가 선택**할 수 있게 한다.

현재 bootstrap은 이 섹션과 "카테고리별 지침" 섹션을 모두 담은 고정 템플릿을 무조건 루트에 복사한다. 변경 후에는 CLAUDE.md를 새로 만드는 단계에서 포함 여부를 한 번 묻고, 그 답에 따라 생성되는 CLAUDE.md의 구성이 달라진다:

- **포함 선택** → "Claude 상호작용 규칙" 섹션 + "카테고리별 지침" 섹션을 모두 담은 CLAUDE.md.
- **제외 선택** → "Claude 상호작용 규칙" 섹션을 **전혀 담지 않고** "카테고리별 지침" 섹션만 담은 CLAUDE.md.

"카테고리별 지침" 섹션은 두 경우 모두 항상 포함되는 핵심이다. 포함 여부 선택지는 어느 쪽도 추천으로 표시하지 않고 중립적으로 제시한다. 이 질문은 CLAUDE.md를 새로 만드는 경우에만 노출하며, 루트에 이미 CLAUDE.md가 있으면 묻지 않는다.

## 수용 기준 (EARS)
<!-- EARS 5패턴과 언어 규칙은 references/ears-patterns.md. 각 기준은 관찰 가능하고 독립 검증 가능해야 함. -->
- WHEN bootstrap이 루트에 `CLAUDE.md`가 없어 이를 새로 생성하는 단계에 진입하면, 스킬은 "Claude 상호작용 규칙"(AskUserQuestion 지침) 섹션의 포함 여부를 `AskUserQuestion`으로 사용자에게 물어야 한다.
- WHEN 사용자가 포함을 선택하면, 스킬은 "Claude 상호작용 규칙" 섹션과 "카테고리별 지침" 섹션을 **모두** 담은 `CLAUDE.md`를 루트에 생성해야 한다.
- WHEN 사용자가 제외를 선택하면, 스킬은 "Claude 상호작용 규칙" 섹션을 **전혀 담지 않고** "카테고리별 지침" 섹션만 담은 `CLAUDE.md`를 루트에 생성해야 한다.
- WHERE 포함 여부 선택지를 제시할 때, 스킬은 포함·제외 두 선택지를 어느 쪽도 추천(Recommended)으로 표시하지 않고 중립적으로 제시해야 한다.
- IF 루트에 이미 `CLAUDE.md`가 존재하면, 스킬은 포함 여부를 묻지 않고 기존 `CLAUDE.md`를 덮어쓰지 않아야 한다.
- WHEN 제외 선택으로 `CLAUDE.md`가 생성되면, 생성된 파일은 AskUserQuestion 사용을 규정하는 "Claude 상호작용 규칙" 섹션의 본문·헤딩을 어떤 형태로도(주석·접힘 포함) 포함하지 않아야 한다.
- WHILE 두 선택 경로 어느 쪽이든, 생성된 `CLAUDE.md`는 "카테고리별 지침" 섹션을 항상 포함해야 한다.

## 범위
포함:
- bootstrap 스킬의 `CLAUDE.md` 신규 생성 절차(현재 SKILL.md의 step 2)와, 그 절차가 사용하는 CLAUDE.md 템플릿/자산의 구성.
- "Claude 상호작용 규칙" 섹션 포함 여부를 묻고 그 답에 따라 생성 결과를 분기하는 동작.

비-목표 / 제외:
- `rules/` 생성 흐름 및 다른 형제 `*-rule-creator` 스킬.
- 이 저장소 자신의 루트 `CLAUDE.md`(제품 코드가 아닌 본 repo 운영 문서)의 내용 변경.
- git 브랜치·commit·원격 동기화 등 파일 생성 외 작업.
- "카테고리별 지침" 등 다른 섹션을 선택적으로 만드는 일반화(이번 변경은 상호작용 규칙 섹션 한정).

## 검증
<!-- 검증 기준의 단일 출처는 위 "수용 기준 (EARS)"다. 검증을 실행하는 진입 명령(테스트·lint·빌드)은 SPEC이 선언하지 않는다. -->
이 SPEC의 인수 바는 위 **수용 기준 (EARS)**이다. 각 기준이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약
- 변경 대상은 bootstrap 스킬(SKILL.md 절차 및 그것이 사용하는 CLAUDE.md 템플릿/자산)에 한정한다. 다른 스킬·`rules/`는 건드리지 않는다.
- 포함 여부 선택은 반드시 `AskUserQuestion`으로 받는다. 자유 텍스트 끝에 질문을 붙이지 않는다(본 저장소 CLAUDE.md 상호작용 규칙 준수).
- 기존 파일을 절대 덮어쓰지 않는 bootstrap의 기존 규칙을 유지한다.
- 포함 선택 시 생성되는 CLAUDE.md의 "Claude 상호작용 규칙" 섹션 내용은 현행 템플릿과 의미상 동등해야 한다(선택지 추가가 기존 포함-경로 산출물을 약화시키지 않는다).

## 위험
- 상호작용 규칙 섹션을 별도 자산으로 분리해 조립하는 방식을 택할 경우, 기본 자산과 상호작용 규칙 자산의 내용이 시간이 지나며 표류(drift)할 수 있다 — 두 경로의 산출물이 일관되도록 단일 출처를 유지할 것.
