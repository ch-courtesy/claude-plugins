# bootstrap optional sections single multiSelect

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
bootstrap 스킬이 새 `CLAUDE.md`에 끼워 넣는 **두 선택적 콘텐츠 블록**(카파시 65줄 룰, "Claude 상호작용 규칙" 섹션)의 포함 여부를, 지금처럼 서로 다른 단계의 개별 single-select 질문 2개로 묻지 않고, **하나의 multiSelect 질문**으로 통합한다. 이 통합 질문은 `CLAUDE.md`를 이번 흐름에서 **새로 생성하는 경우에만** 한 번 묻고, 두 항목은 모두 기본 포함(권장)으로 제시한다. 조립되는 `CLAUDE.md`의 본문 내용·섹션 순서는 그대로 유지하며, 변경은 질문 UX(두 질문 → 한 multiSelect)에 한정된다.

## 완료 조건
<!-- 5문장 패턴(항상 / …할 때 / …인 동안 / …이면(오류) / …기능이 켜지면)과 언어 규칙은 references/ears-patterns.md. 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->
- 항상, `CLAUDE.md`를 이번 흐름에서 새로 생성할 때 bootstrap은 두 선택적 섹션(카파시 룰·상호작용 규칙)의 포함 여부를 **정확히 하나의 `AskUserQuestion` multiSelect 질문**으로 묻고, 같은 흐름에서 이를 별개의 질문 2개로 나누지 않는다.
- 항상, 그 통합 multiSelect 질문은 매 초기화 흐름에서 **최대 한 번만** 호출된다.
- 항상, 그 통합 multiSelect 질문은 두 선택지(카파시 룰 / 상호작용 규칙)를 모두 **기본 포함(권장)**으로 제시한다.
- 루트에 `CLAUDE.md`가 이미 있어 이번 흐름에서 새로 생성하지 않을 때, bootstrap은 이 통합 multiSelect 질문을 **하지 않는다**.
- 사용자가 통합 질문에서 카파시 룰 항목을 선택하면, 생성되는 `CLAUDE.md`의 **최상단**에 동봉 카파시 자산 본문이 그대로 붙는다. 선택하지 않으면 카파시 룰 텍스트가 어떤 형태로도(주석·접힘 포함) 들어가지 않는다.
- 사용자가 통합 질문에서 상호작용 규칙 항목을 선택하면, 베이스 템플릿의 `# CLAUDE.md` 제목 바로 아래·"카테고리별 지침" 섹션보다 **앞**에 상호작용 규칙 섹션 본문이 삽입된다. 선택하지 않으면 그 섹션의 본문·헤딩이 어떤 형태로도 들어가지 않는다.
- 항상, 사용자의 선택과 무관하게 "카테고리별 지침" 섹션은 포함되고, 조립 순서는 `[카파시 룰(선택 시)] → [상호작용 규칙(선택 시)] → [카테고리별 지침]`을 유지한다.

## 범위
포함:
- `plugins/project-init/skills/bootstrap/SKILL.md`의 2단계(카파시 룰 질문)와 3단계(상호작용 규칙 섹션 질문) 흐름을, 새 `CLAUDE.md` 생성 경로에서 한 번 호출되는 단일 multiSelect 질문으로 재구성.

비-목표 / 제외:
- 동봉 자산 파일(`assets/karpathy-rules.ko.md`, `assets/interaction-rules.ko.md`)과 베이스 템플릿(`skills/bootstrap/CLAUDE.md`)의 **본문 내용**은 변경하지 않는다(단일 출처 유지).
- 4단계 카테고리 선택 질문(`*-rule-creator` 도출·전체/일부/없음 게이트·multiSelect)은 변경하지 않는다.
- 조립된 `CLAUDE.md`의 출력 구조·섹션 순서·문구는 변경하지 않는다(질문 UX만 변경).
- 다른 스킬·`rules/`·CI 변경 없음.

이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약 (있을 때만)
- `AskUserQuestion`의 multiSelect는 **사전 체크(pre-checked) 상태를 표현하는 스키마가 없다.** 따라서 "두 항목 모두 기본 체크"는 두 선택지를 모두 "(권장)"으로 라벨링하고 설명에서 기본 포함 의도를 명시하는 방식으로 구현한다 — 도구가 실제로 항목을 미리 체크해 주지는 않는다.
- 이 변경으로 카파시 룰의 기존 기본값(`추가 안 함 (Recommended)`, opt-in)이 **기본 포함(권장)**으로 바뀐다. 상호작용 규칙은 기존 "중립"에서 "기본 포함(권장)"으로 바뀐다.
- 두 섹션의 본문은 각각 단일 출처 자산에만 존재한다는 기존 불변식을 유지한다.
- 통합 질문은 `CLAUDE.md`를 이번 흐름에서 새로 생성하는 경로에서만 호출한다(기존에 카파시 질문이 흐름 맨 앞에서 무조건 한 번 묻던 동작은 제거된다).

## 위험 (있을 때만)
- 도구 한계로 "기본 체크"가 라벨/설명 수준의 권장 표현으로만 구현되어, 사용자가 아무것도 선택하지 않으면 두 블록 모두 미포함된다 — 의도한 default-on과 picker 동작 사이에 간극이 있다.
- 카파시 룰 기본값이 off→권장(on 의도)으로 바뀌어 기존 사용자 기대와 달라질 수 있다.
