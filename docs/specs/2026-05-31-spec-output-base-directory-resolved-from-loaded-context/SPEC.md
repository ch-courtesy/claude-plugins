# spec output base directory resolved from loaded context

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
spec 스킬이 SPEC 문서를 저장하는 **디렉토리 경로**를, 하드코딩된 고정값이 아니라 **이미 로드된 프로젝트 지침에 선언된 spec 경로**를 우선 따르도록 바꾼다.

- 프로젝트 지침에 spec 경로 선언이 있으면 그 선언을 따라 SPEC을 저장한다.
- 선언이 없으면 기본값 `docs/specs/<작성일>-<제목 slug>/`을 사용한다.
- 어느 경우에도 **고정 불변식**은 단 하나다: 각 SPEC은 **자신의 전용 디렉토리**를 가지며 본문은 그 디렉토리 안의 **`SPEC.md`** 파일로 존재한다(베이스 디렉토리 바로 아래의 맨몸 파일이 아니다). 외부 선언은 그 디렉토리의 **위치(베이스)와 per-spec 디렉토리 네이밍까지** 바꿀 수 있다.

또한 이 경로 해석 규칙(외부 선언 우선, 없으면 기본값)과 기본값 표현이 **한 곳에서 관리**되고, SPEC 경로를 소비하는 다른 룰·스킬은 그 단일 출처를 참조해 같은 경로 규칙을 따르도록 한다(이미 단일 출처를 참조 중이거나 SPEC 경로를 입력으로 받는 소비자는 바꾸지 않는다).

## 완료 조건
<!-- 5문장 패턴(항상 / …할 때 / …인 동안 / …이면(오류) / …기능이 켜지면). 각 조건은 관찰 가능·독립 검증 가능. -->

1. **항상**: 시스템은 SPEC 본문을 **per-spec 전용 디렉토리 안의 `SPEC.md`** 파일로 저장해야 한다 — 경로 선언 유무·값과 무관하게, 베이스 디렉토리 바로 아래의 단일 파일로 두지 않는다.

2. **…할 때**: 이미 로드된 프로젝트 지침에 spec 경로 선언이 있을 때, 시스템은 그 선언을 따라 SPEC 디렉토리의 위치(베이스)와 per-spec 디렉토리 네이밍을 결정해 저장해야 한다.

3. **…이면**: 로드된 프로젝트 지침에 spec 경로 선언이 없으면, 시스템은 `docs/specs/<작성일(YYYY-MM-DD)>-<제목 slug>/SPEC.md`를 사용해야 한다.

4. **…할 때**: 외부 선언이 경로를 지정할 때, 시스템은 베이스 디렉토리뿐 아니라 per-spec 디렉토리 네이밍(`<날짜>-<slug>`)까지 그 선언대로 대체해야 하며, 고정 불변식(per-spec 디렉토리 + 그 안의 `SPEC.md`)만 보존해야 한다.

5. **…할 때**: 저장 대상 디렉토리가 아직 존재하지 않을 때, 시스템은 그 디렉토리를 만들 수 있어야 한다 — 기본값(`docs/specs/...`)이 아닌 경로에 대해서도 디렉토리 생성이 권한 때문에 차단되어 실패하지 않아야 한다.

6. **항상**: spec 경로 해석 규칙(외부 선언 우선, 없으면 기본값)과 기본값 표현은 단일 출처 한 곳에서만 정의되어야 하며, spec 스킬 문서 등 다른 위치는 이 규칙을 중복 정의하지 않고 그 단일 출처를 참조해야 한다.

7. **…할 때**: `--resume`이 기존 SPEC 문서 경로를 인자로 받을 때, 시스템은 경로가 기본값 형태이든 외부 선언값 형태이든 해당 경로의 문서를 그 자리에서 갱신해야 하며, 특정 베이스·네이밍을 가정해 거부하지 않아야 한다.

8. **…이면(오류)**: 기본 네이밍을 쓰는 경우 제목에서 파생한 slug가 비면, 시스템은 fallback 디렉토리를 만들지 않고 중단하고 제목 수정을 요청해야 한다(기존 동작 보존).

## 범위
포함:
- spec 스킬의 SPEC 저장 경로 해석 동작(외부 선언 우선 — 베이스·per-spec 네이밍 포함, 없으면 `docs/specs/<날짜>-<slug>/`).
- 경로 해석 규칙·기본값의 단일 출처화, 그리고 spec 스킬 문서(산출 경로 서술·`--resume` 서술·소개 설명)가 그 단일 출처를 참조하도록 갱신.
- 기본값이 아닌 경로에서도 디렉토리 생성이 동작하도록 보장.

비-목표 / 제외:
- 고정 불변식 변경: per-spec 디렉토리 + 그 안의 `SPEC.md` 본문 구조는 바꾸지 않는다.
- 기존에 작성된 SPEC 문서의 이전·마이그레이션.
- SPEC 경로를 입력으로 받아 그 하위에 아티팩트(워크트리·락·신호·실행 메타)를 두는 소비자(dispatch·loop·conductor) 동작 변경 — 이들은 경로가 바뀌어도 입력받은 SPEC 디렉토리를 따라 자동 정합되므로 손대지 않는다(loop의 status·테스트에 등장하는 `docs/specs`는 예시·픽스처일 뿐 동작 경로가 아니다).
- 외부 선언을 위한 신규 설정 파일·로딩 메커니즘 신설. 이미 세션에 로드되는 프로젝트 지침(`CLAUDE.md`·`rules/`)에 기재되는 선언만 사용한다.
- project-init 계열이 대상 프로젝트에 생성하는 규칙 문서로의 기본 선언 전파(별도 후속 작업).

<!-- 검증 기준의 단일 출처는 위 "완료 조건"이다. 진입 명령은 SPEC이 선언하지 않는다. -->
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령(테스트·lint·빌드)은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약
- 경로 해석 규칙(외부 선언 우선, 없으면 `docs/specs/<날짜>-<slug>/`)의 단일 출처는 `rules/engineering/branch-and-slug.md`이며, 기본 선언을 이 규칙 문서에 미리 기재한다 — 즉 기본 경로도 별도 하드코딩이 아니라 이 단일 출처의 선언으로 표현한다.
- 외부 선언을 인식하는 형식은 사람이 읽고 grep 가능한 **약속된 키 한 줄**(예: `spec-path:` 또는 동급의 약속된 키)로 한정하며, 자유 텍스트를 해석해 추론하지 않는다. 선언은 per-spec 디렉토리까지 포함하는 경로를 표현할 수 있어야 한다.
- 외부 선언 탐색 대상은 세션 시작 시 이미 로드되는 프로젝트 지침(`CLAUDE.md` 및 `rules/`)으로 한정한다.
- 선언이 여러 곳에 있으면 `CLAUDE.md`의 선언이 `rules/`의 선언보다 우선한다.
- spec 스킬 문서의 산출 경로 서술·`--resume` 서술·소개 설명은 `docs/specs`를 단정적 고정값으로 적지 않고 "선언된 경로(기본 `docs/specs/<날짜>-<slug>/`)" 의미로 바꾸되 단일 출처를 가리킨다.
- 디렉토리 생성 권한은 경로가 기본값이 아닐 때도 생성이 가능하도록 일반화한다. 최소성은 **경로가 아니라 연산 차원**에서 성립한다 — `mkdir -p` 디렉토리 생성 연산으로만 한정하고(파일 쓰기·삭제 등 다른 명령은 이 권한으로 수행되지 않는다), 경로는 외부 선언으로 임의 지정될 수 있으므로(완료 조건 5) 경로 범위로는 제한하지 않는다.
- 고정 불변식: 각 SPEC은 자신의 디렉토리를 갖고 본문은 그 안의 `SPEC.md`다.

## 위험
- 디렉토리 생성 권한이 임의 경로 mkdir을 허용하면 경로 표면이 넓어진다 — 다만 권한을 `mkdir -p` 디렉토리 생성 연산으로만 한정(파일 내용 변조 불가)하고, 외부 선언이 임의 베이스를 지정할 수 있다는 요구(완료 조건 5)와 양립시키기 위해 경로가 아닌 연산 차원에서 최소화한다.
- 외부 선언을 자유 텍스트로 해석하면 오탐 위험이 크다 — 약속된 키 한 줄 형식으로만 인식해 막는다.
- per-spec 네이밍까지 외부 선언이 바꿀 수 있으므로, 선언이 per-spec 디렉토리를 유일하게 만들지 못하는 형식(예: 고정 문자열)이면 서로 다른 SPEC이 같은 디렉토리를 공유해 충돌할 수 있다 — 기본 네이밍(`<날짜>-<slug>`)은 유일성을 보장하며, 외부 선언 시 유일성은 선언자의 책임으로 둔다.
- project-init이 생성하는 대상 프로젝트의 규칙 문서에 기본 선언이 전파되지 않으면, 설치 프로젝트는 선언이 없어 기본값으로만 동작한다(동작은 정상이나 사용자 가시성↓). 전파는 별도 후속(project-init) 작업으로 둔다.
- SPEC 경로를 입력으로 받지 않고 `docs/specs`를 독립적으로 가정하는 소비자가 새로 생기면 경로 변경 시 어긋난다 — 현 조사상 핵심 소비자는 SPEC 디렉토리를 입력으로 받아 그 하위에 아티팩트를 두므로 자동 정합된다.
