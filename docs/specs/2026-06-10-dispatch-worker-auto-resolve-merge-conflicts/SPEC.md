# dispatch 워커 머지 충돌 자동 해결

## 무엇을 만들 것인가
dispatch per-SPEC 워커가 통합·머지 과정에서 타겟 브랜치 전진으로 머지 충돌을 만나면, 즉시 사람에게 에스컬레이션하지 않고 **자동으로 충돌을 해결**한 뒤 진행하도록 만든다. 충돌이 나는 두 지점 모두를 다룬다: ① base sync 단계의 타겟 브랜치 rebase, ② 최종 ff-only 머지 단계(타겟이 그새 전진해 ff가 깨지는 경우). 타겟이 해결 도중 또 전진하는 레이스에 대비해 유한 횟수 재동기화·재시도한다.

자동 해결은 **넓게** 시도하되(버전 줄뿐 아니라 일반 충돌도), 해결 결과가 거짓 green이 되지 않도록 **해결 후 검증 게이트**로 가둔다 — 자동 해결 후 그 SPEC의 검증(완료 조건/결정적 selftest)을 재실행해 통과할 때만 진행하고, 통과하지 못하면 머지하지 않고 에스컬레이션한다.

## 목적 (왜)
dispatch run 도중 origin/main이 다른 잡들의 동시 머지로 빠르게 전진하면(특히 plugins/ 변경의 plugin.json 버전 연쇄 범프), 워커의 base가 stale해져 base sync rebase·최종 ff 머지가 반복적으로 충돌하고, 현재는 그때마다 사람 위임으로 종착해 자동 파이프라인이 끊긴다. 흔한 충돌(버전 줄)은 결정적으로 해소 가능하므로, 워커가 스스로 해결해 자율 완료율을 높인다.

## 완료 조건
- **…할 때**: 워커의 base sync(타겟 브랜치 rebase)에서 머지 충돌이 발생하면, 워커는 `rebase --abort` 후 즉시 에스컬레이션하는 대신 자동 해결을 시도한다.
- **…할 때**: 최종 ff-only 머지가 타겟 전진으로 ff 불가가 되면, 워커는 갱신된 타겟으로 non-force 재동기화 후 자동 해결을 시도해 다시 ff 머지를 시도한다.
- **…인 동안**: 충돌이 plugin.json 버전 줄이면, 해소 버전은 **현재 타겟 버전 위에 작업 브랜치가 적용한 범프 레벨(MAJOR/MINOR/PATCH)을 재적용**한 값으로 정해, 항상 타겟 버전보다 엄격히 크고 작업 브랜치의 범프 의도를 보존한다.
- **…인 동안**: 충돌이 버전 줄이 아닌 일반 변경이면, 자동 해결 전략을 적용하되 **해결 직후 그 SPEC의 검증(완료 조건/결정적 selftest)을 재실행**한다 — 통과하면 진행, 실패하면 머지하지 않고 에스컬레이션한다(거짓 green 금지).
- **…할 때**: 자동 해결·재동기화 도중 타겟 브랜치가 또 전진하면(레이스), 유한 횟수(기본 한도) 재fetch·재동기화·재시도하고, 한도를 초과하면 에스컬레이션한다.
- **…이면(오류)**: 자동 해결이 충돌을 안전하게 닫지 못하거나 검증 게이트를 통과하지 못하면, 머지 없이 에스컬레이션한다 — 부분 해결을 머지하지 않는다.
- **항상**: 자동 해결 경로는 force push·force merge·force rebase를 어떤 단계에서도 사용하지 않는다.
- **항상**: 자동 해결이 수행되면 무엇을(어느 파일·충돌) 어떻게(버전 재적용/전략/재시도 횟수) 해소했는지 로그로 표면화한다(조용한 해결 금지).
- **항상**: 결정적 헬퍼의 자동 해결 로직은 실제 원격·머지 없이 mock 인터페이스 기반 selftest로 독립 검증 가능하다.

## 범위
포함:
- `integration.sh` `in_base_sync`: rebase 충돌 자동 해결 + 레이스 재시도.
- `merge.sh` finish(ff 머지): 타겟 전진 시 non-force 재동기화·자동 해결·재시도.
- 버전 충돌 해소의 결정적 산식(타겟 위 범프 재적용) — 기존 `mg_json_version` 등 버전 헬퍼 재사용.
- 자동 해결 후 검증 게이트(일반 충돌 경로).
- 워커 계약 `subagent-prompt.md`: 충돌 시 자동 해결 위임·검증 게이트·에스컬레이션 경계 명문화.
- `plugin.json` 버전 범프(plugins/ 워치 변경).

비-목표 / 제외:
- PR 리뷰 지적(코드 리뷰 must_adopt) 반영 루프 — 별개 메커니즘(`review-loop.sh`), 본 SPEC 무관.
- direct 서브모드의 리뷰·머지 의미 변경(충돌 자동 해결은 공용 base sync/merge 경로에 적용되되 서브모드 분기 자체는 바꾸지 않음).
- force 사용·dispatch 결정적 스케줄링(준비도·동시성) 변경.
- 자동 해결 전략의 외부 주입 일반화(현 주입 인터페이스 확장)는 필요 최소만.

## 검증
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약
- 자동 해결·재동기화·재시도는 **non-force**만 사용한다(기존 dispatch 불변식). ff-only 머지 게이트·버전 범프 게이트·승인 게이트는 그대로 통과한다.
- 버전 해소 산식은 `rules/engineering/versioning.md`를 실행자(`merge.sh` 버전 헬퍼)로 따르며, 버전 SoT(plugin.json) 단일 출처를 깨지 않는다.
- 자동 해결과 에스컬레이션의 경계(어떤 충돌을 닫고 어떤 것을 사람에게 넘길지)는 결정적 헬퍼와 워커 계약(`subagent-prompt.md`)이 단일 출처로 정의한다 — 두 곳이 어긋나지 않게 한다.
- 레이스 재시도 한도는 기존 `DISPATCH_*` 주입 관례로 조정 가능한 상수로 둔다(무한 루프 금지).

## 위험
- **"넓게" 자동 해결의 오해소 위험**: 코드 의미 충돌을 ours/theirs/union 등으로 기계 해소하면 타겟의 변경을 유실하거나 깨진 코드를 만들 수 있다. → 완료 조건의 **해결 후 검증 게이트**(완료 조건/selftest 재실행, 실패 시 에스컬레이션)로 거짓 green을 차단해 완화한다. 검증이 약한 변경(검증 커버리지 밖)에서는 자동 해결이 통과해도 의미 손상이 남을 수 있으므로, 워커 계약에 "검증으로 닫히지 않는 충돌은 보수적으로 에스컬레이션" 경계를 명시한다.
- **레이스 무한화**: 타겟이 계속 전진하면 재시도가 끝나지 않을 수 있다 → 유한 재시도 한도 + 초과 시 에스컬레이션.
- **두 지점(rebase/ff-merge) 로직 중복**: base sync와 최종 머지의 자동 해결이 갈라지면 정책 불일치 → 결정적 헬퍼의 공용 해소 경로로 단일화.
