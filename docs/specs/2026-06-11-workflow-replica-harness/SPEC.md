# Workflow Replica Harness

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

Claude Code의 내장 **dynamic Workflow(멀티에이전트 오케스트레이션) 도구가 미가용인 환경에서도**, 그 도구가 제공하는 오케스트레이션 동작을 **독립적으로(standalone) 재현**하는 범용 워크플로 실행 하니스를 만든다. 하니스는 임의의 의존성 그래프(DAG)를 받아, 각 노드를 **그 의존성이 끝나는 즉시** 동시성 상한 안에서 실행하고(스트리밍 fan-out), 노드 결과를 후속 노드로 전달하며, 실패를 이행적으로 격리하고, 중단된 실행을 재개(resume)한다.

작성자는 **명령형 워크플로 스크립트**로 워크플로를 표현한다. 노드(워커)는 두 층위로 표현될 수 있다: ① 임의의 외부 명령/콜러블(범용 — LLM 비의존), ② LLM 서브에이전트 호출 어댑터(프롬프트 처리 + 선택적 구조화 스키마 반환)로, 후자는 내장 dynamic Workflow의 에이전트 노드와 동형이다.

이 하니스는 기존 오케스트레이션 스킬(예: dispatch)에 **의존하지 않는** 독립 구성요소다. 다른 스킬이 이후 이 하니스를 드라이버로 채택할 수 있도록, 호출 인터페이스는 자기완결적이어야 한다.

## 목적 (왜)
<!-- 완료 조건의 종속 앵커일 뿐 검증 기준이 아니다. -->

내장 dynamic Workflow 런타임은 Claude Code 본체에 컴파일되어 있어 그 도구가 막힌(opt-in 게이트 미충족·미가용) 환경에서는 스트리밍 병렬 오케스트레이션을 쓸 수 없고, 기존 대체 경로는 스트리밍을 잃거나(웨이브 배리어) 외부 재호출 신호에 의존한다. 그런 환경에서도 동일한 오케스트레이션 동작을 **외부 서비스·특수 런타임 없이** 확보하기 위해, 공개 문서로 규정된 동작 계약을 표준 실행 환경 위에 직접 재구현한다.

## 완료 조건
<!-- 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->

1. **항상**: 하니스는 임의의 비순환 의존성 그래프를 입력으로 받아 모든 노드를 실행하고, 각 노드는 자신의 **모든 의존성이 끝난 직후** 시작되어야 한다 — 의존 관계가 없는 더 느린 노드의 완료를 기다리지 않아야 한다(웨이브 배리어 없음). (검증: 의존성이 불균등한 그래프에서, 한 노드가 자신과 무관한 더 느린 노드보다 먼저 시작·완료됨이 실행 타임라인으로 관찰된다.)

2. **항상**: 동시에 실행 중인 노드 수는 설정된 동시성 상한을 넘지 않아야 한다. (검증: 상한 N으로 실행할 때 동시 실행 수의 최댓값이 N 이하임이 관찰된다.)

3. **한 노드가 실패하면**, 하니스는 그 노드의 이행적(직·간접) 의존자만 실행하지 않고 건너뛰며, 그 노드와 의존 관계가 없는 가지는 끝까지 실행해야 한다. (검증: 실패 노드의 다운스트림은 실행되지 않고, 무관한 노드는 완료됨이 결과 요약으로 관찰된다.)

4. **중단된 실행을 같은 입력으로 재개하면**, 하니스는 이전에 성공적으로 끝난 노드를 다시 실행하지 않고 그 결과를 그대로 사용해야 하며, 미완료·실패 노드만 다시 시도해야 한다. (검증: 첫 실행 후 재개 실행에서 완료 노드가 재실행 없이 표시되고, 재개의 실행 노드 집합이 미완료분으로 한정됨이 관찰된다.)

5. **한 노드가 결과값을 반환하면**, 그 값은 해당 노드에 의존하는 후속 노드/단계로 전달되어야 한다. (검증: 후속 노드가 선행 노드의 반환값을 입력으로 받아 동작함이 관찰된다.)

6. **의존성 그래프에 순환이 있으면**, 하니스는 어떤 노드도 실행하지 않고 순환을 구성하는 노드를 보고하며 오류로 종료해야 한다. (검증: 순환이 포함된 입력에 대해 실행이 시작되지 않고 순환 경로가 보고된다.)

7. **항상**: 작성자는 명령형 워크플로 스크립트로 워크플로를 표현할 수 있어야 하며, 그 스크립트는 한 단계의 결과에 따라 다음에 실행할 노드가 정해지는 **런타임 결정 그래프**도 표현할 수 있어야 한다. (검증: 선행 노드의 출력값으로 후속 노드 집합이 달라지는 스크립트가 의도대로 실행됨이 관찰된다.)

8. **에이전트 노드로 표현된 작업이 실행되면**, 하니스는 LLM 서브에이전트를 띄워 프롬프트를 처리하고, 구조화 스키마가 주어진 경우 그 스키마로 검증된 구조화 결과를 반환해야 하며, 검증에 실패하면 정정된 결과를 다시 요구해야 한다. (검증: 스키마가 주어진 에이전트 노드가 스키마에 맞는 객체를 반환하고, 불일치 시 재시도가 일어남이 관찰된다.)

9. **임의의 외부 명령으로 표현된 노드가 실행되면**, 하니스는 LLM에 의존하지 않고 그 명령을 워커로 실행하고 종료 상태로 성공/실패를 판정해야 한다. (검증: LLM 호출이 전혀 없는 순수 명령 노드만으로 구성된 그래프가 완주됨이 관찰된다.)

10. **내장 dynamic Workflow 도구가 미가용인 동안**, 위 모든 조건은 외부 서비스나 특수 런타임 없이(표준 실행 환경만으로) 충족되어야 한다. (검증: Workflow 도구 없이 표준 환경에서 위 조건들이 모두 통과함이 관찰된다.)

## 범위
포함:
- 임의 DAG의 스트리밍 fan-out 스케줄러(준비도 기반, 동시성 상한, 순환 검출).
- 실패 이행 격리, 노드 결과값 전달, 저널 기반 resume.
- 명령형 작성 인터페이스(에이전트/파이프라인/병렬/단계 표현)와 런타임 결정 그래프 지원.
- 두 워커 층위: 범용 외부 명령 노드 + LLM 에이전트 노드(선택적 구조화 스키마 반환).
- 자기완결적 호출 인터페이스(다른 스킬이 드라이버로 채택 가능).

비-목표 / 제외:
- **토큰 예산(budget) 회계·상한**: 내장 dynamic Workflow의 토큰 기준 budget은 이 단위의 비-목표다. 동시성/노드 수 상한으로 폭주를 막되, 토큰 누적 상한 재현은 후속으로 미룬다.
- **워크플로 중첩(workflow-in-workflow)·워크트리 격리 노드·진행 TUI**: 내장 도구의 부가 기능은 이 단위 범위 밖이며, 완전 동등(100%)은 이 단위 + 후속 단위들로 도달한다.
- **표준 실행 환경 자체가 없는 극한 환경 대응(예: 별도 셸 전용 티어)**: 이 단위 범위 밖.
- dispatch 등 기존 스킬의 변경.
- `rules/**`, `milestones/**`, `CLAUDE.md` 변경.

## 제약
- **구현 언어·런타임(확정)**: Python 3.9+로 구현하고 **표준 라이브러리만** 사용한다(외부 패키지 설치 금지). 스케줄 코어는 표준 라이브러리의 위상정렬·비동기·하위 프로세스·직렬화 기능(`graphlib`의 위상정렬 스트리밍 API, `asyncio`, `subprocess`, `json`)으로 구성한다. python3 인터프리터 가용을 전제하며, 이는 이 프로젝트의 통제·검증 환경에서 가용함이 확인된 전제다.
- **clean-room**: 비공개·유출된 Claude Code 소스를 참조·복제하지 않는다. 공개 동작 문서(내장 Workflow 도구 공개 사양)와 호환 라이선스 OSS(MIT 등)만 참조한다.
- **독립성**: dispatch 등 기존 스킬·그 내부 헬퍼에 의존하지 않는다. 다른 스킬이 이후 드라이버로 채택할 수 있도록 호출 인터페이스는 자기완결적이어야 한다.
- **스케줄 결정성(워커 출력과 분리)**: 재현성은 **스케줄러의 판정**에 한정한다 — 동일한 그래프·동일한 저널·동일한 노드 결과가 주어지면 어떤 노드를 언제 시작·스킵하는지가 동일해야 한다. LLM 에이전트 노드의 출력값 자체는 비결정적일 수 있으며 이는 스케줄 결정성의 대상이 아니다. 시각·난수 같은 비결정 요소는 스케줄 판정에 끌어들이지 않는다.

## 위험
- **인터프리터 전제**: python3가 없는 극한 환경에서는 동작하지 않는다(완료 조건 10은 python3 가용 전제 위에서 성립). python3도 없는 환경을 위한 별도 셸 전용 티어는 후속 단위로 분리한다.
- **에이전트 노드 외부 의존**: LLM 에이전트 노드는 로컬 LLM 호출 경로의 가용·인증에 의존한다. 헤드리스/막힌 환경에서 대화형 인증 자원이 부재할 수 있다(공개 문서가 동일 한계를 경고). 범용 명령 노드 경로는 이 의존이 없다.
- **저널 무효화 기준**: resume의 "성공적으로 끝난 노드" 식별 키를 어떻게 정의하느냐에 따라 노드 정의가 바뀌었는데 캐시가 재사용되는 stale 위험이 있다. 완료 조건 4는 이 키 정의가 관찰 가능한 재실행/스킵 동작으로 드러나도록 요구한다.
