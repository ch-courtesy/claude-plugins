# 칸반 상태 카드 뷰

## 무엇을 만들 것인가

활성 데이터소스의 태스크들을 **상태 컬럼으로 나열하지 않고**, 각 태스크를 하나의 카드로 보여주는 뷰를 만든다. 각 카드는 그 태스크가 지금 어떤 상태인지를 카드 위의 상태 라벨로 드러낸다. 카드들은 컬럼이 아니라 단일 그리드/목록으로 배치된다. 뷰는 활성 데이터소스에서 태스크 목록을 읽어와 렌더하고, 사용자가 새로고침하면 다시 읽는다. 카드는 읽기 전용이며, 클릭하면 그 태스크의 상세(원본)를 연다.

## 목적 (왜)

"어떤 이슈가 지금 어떤 상태인가"를 컬럼 분류가 아니라 카드 단위로 한눈에 파악하기 위해서다. 컬럼형 칸반은 상태별 분류에 초점이 있지만, 여기서는 개별 이슈의 현재 상태를 카드에 직접 드러내는 것이 목표다.

## 완료 조건

- 뷰가 열릴 때, 시스템은 활성 데이터소스에서 태스크 목록을 읽어 각 태스크를 하나의 카드로 렌더해야 한다.
- 시스템은 카드들을 상태별 컬럼으로 묶지 않고 단일 그리드/목록으로 배치해야 한다.
- 시스템은 각 카드에 그 태스크의 백엔드 원본 상태 라벨을 표시해야 한다.
- 시스템은 각 카드에 그 태스크의 제목(과 식별자)을 표시해야 한다.
- 카드를 클릭할 때, 시스템은 그 태스크의 상세(원본 파일 또는 원격 URL)를 열어야 한다.
- 사용자가 새로고침할 때, 시스템은 활성 데이터소스를 다시 읽어 카드 집합을 갱신해야 한다.
- 활성 데이터소스가 없거나 읽기에 실패하면, 시스템은 빈 그리드 대신 그 상태(미구성/실패)를 뷰에 관찰 가능하게 표시해야 한다.
- 태스크가 0개이면, 시스템은 "태스크 없음"을 빈 그리드와 구분되게 표시해야 한다.

## 범위

포함:
- 활성 데이터소스의 태스크를 카드 그리드/목록으로 렌더하는 뷰.
- 카드의 제목·식별자·원본 상태 라벨 표시.
- 카드 클릭 시 상세 열기(데이터소스 계약의 상세 열기 호출).
- 새로고침 동작.
- 미구성·읽기 실패·빈 목록 상태 표시.

비-목표 / 제외:
- 상태별 컬럼 칸반 레이아웃(의도적으로 만들지 않음).
- 카드에서 상태·필드 편집(쓰기) — v1 비목표.
- 드래그앤드롭, 필터·검색·정렬 고급 기능 — v1 비목표.
- 데이터소스 읽기/상세/생성 로직 자체(별도 SPEC: 골격·데이터소스 추상화가 단일 출처).

## 검증

이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약

- 데이터 접근은 직접 백엔드를 호출하지 않고 골격 SPEC이 제공하는 데이터소스 계약만 사용한다.
- 상태 라벨은 정규화 없이 백엔드 원본 문자열을 그대로 표시한다.
- v1 상호작용은 읽기 전용 + 상세 열기로 한정한다.

## 위험

- 백엔드 원본 상태 문자열의 종류가 많고 제각각이라, 라벨만으로는 시각적 일관성(색·정렬)이 약할 수 있다. v1은 일관성보다 원본 충실도를 우선한다.
