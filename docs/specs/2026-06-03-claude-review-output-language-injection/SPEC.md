# Claude 리뷰 워크플로 출력 언어 지시 주입

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

Claude PR 리뷰 GitHub Actions 워크플로가 리뷰 산출물의 자연어 필드(summary, 각 finding의 title·body·suggestion)를 **지정한 출력 언어(기본 한국어)로 작성하도록 강제**한다.

현재 이 워크플로는 모델에게 출력 언어를 명시적으로 지시하지 않는다. 프롬프트 본문이 한국어로 쓰여 있긴 하나 "자연어 필드를 무슨 언어로 쓰라"는 지시가 없어, 모델이 자연어 필드를 영어로 출력하는 일이 실제로 발생한다(라이브 증거: PR #293에서 Claude 리뷰 summary가 영어, 같은 PR의 Codex 리뷰는 한국어). 대응 Codex 워크플로는 출력 언어를 명시 지시하고 untrusted 입력 뒤에서 한 번 더 재강조해 이 문제를 이미 막고 있다. 본 변경은 Claude 워크플로에 같은 보장을 부여한다 — 출력 언어를 명시 지시하고, untrusted PR 입력(metadata·comments·diff) 뒤에서 다시 한 번 강제(재강조)해 프롬프트 인젝션으로 지시가 흐려지지 않게 한다.

출력 언어는 구성 가능해야 하며 기본값은 한국어다. 구조 회귀 테스트도 이 지시·재강조의 존재를 정적으로 검증해 향후 누락 시 즉시 드러나게 한다.

## 완료 조건
<!-- 5문장 패턴(항상 / …할 때 / …인 동안 / …이면(오류) / …기능이 켜지면)과 언어 규칙은 references/ears-patterns.md. 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->

1. Claude 리뷰 워크플로가 모델에 전달할 프롬프트를 조립할 때, 항상 리뷰 산출물의 자연어 필드(summary, 각 finding의 title·body·suggestion)를 지정 출력 언어로 작성하라는 **명시적 출력 언어 지시**를 프롬프트에 포함한다.

2. Claude 리뷰 워크플로가 프롬프트를 조립할 때, untrusted PR 입력(metadata·comments·diff)이 모두 끝난 **뒤**에 출력 언어를 다시 강제하는 **재강조 지시**(다른 언어로 작성 금지를 포함)를 프롬프트의 마지막 부분에 포함한다.

3. 출력 언어 값이 별도로 지정되지 않은 동안, 워크플로는 출력 언어를 **한국어**로 적용한다(기본값).

4. 출력 언어가 리포지터리 변수로 지정되면, 출력 언어 지시와 재강조 지시 양쪽이 그 지정 값을 사용한다(하드코딩된 단일 언어에 고정되지 않는다).

5. Claude 리뷰 워크플로 구조 테스트가 실행될 때, 워크플로 파일에 출력 언어 지시·재강조 지시·출력 언어 구성 변수 사용이 모두 존재하는지 정적으로 검증하며, 셋 중 하나라도 빠지면 테스트가 실패한다.

## 범위
포함:
- `.github/workflows/claude-review.yml` — 프롬프트 조립 단계에 출력 언어 지시 주입, untrusted 입력 뒤 재강조 주입, 출력 언어 구성 변수(기본 한국어) 추가.
- `tests/claude/test-claude-review-workflow.sh` — 위 지시·재강조·구성 변수 존재를 정적 검증하는 체크 추가(대응 Codex 테스트의 언어 검증과 동등 수준).

비-목표 / 제외:
- inline thread resolve 실패(GitHub App 설치 토큰 도입) — 별도 작업으로 처리하며 본 SPEC 범위 밖.
- Codex 리뷰 워크플로·프롬프트·결과 스키마 변경.
- 리뷰 판정 로직(verdict·findings·may_approve 산정), inline-only 정책, idempotency·fingerprint 동작 변경.
- 하드코딩 boilerplate 헤더(`## Claude PR 리뷰` 등)나 inline 코멘트의 `**Suggestion:**` 라벨 현지화.
- 프롬프트 파일(`.github/prompts/claude-pr-review.ko.md`) 자체의 본문 재작성.

## 제약 (있을 때만)
- **Codex 패턴 미러링**: 출력 언어 주입 구조는 `codex-review.yml`이 이미 쓰는 패턴(프롬프트 본문 뒤 출력 언어 블록 + untrusted diff 뒤 재강조 블록)과 동일한 형태로 맞춘다. 두 워크플로의 언어 강제 방식이 갈라지지 않게 한다.
- **구성 변수**: 출력 언어는 리포지터리 변수로 구성 가능해야 하고 미지정 시 한국어로 폴백한다(Codex의 `CODEX_REVIEW_LANG`에 대응하는 별도 변수, 기본 `Korean`). 장기 비밀이나 코드 상수 단일 고정 방식은 쓰지 않는다.
- **재강조 위치**: 재강조 지시는 반드시 모든 untrusted PR 입력 뒤에 와야 한다(앞에 두면 untrusted diff가 지시를 뒤에서 덮어 흐릴 수 있음).
- **기존 동작 보존**: 프롬프트의 기존 출력 형식 지시(스키마 만족 JSON 객체 하나만 출력), untrusted 입력 경계 문구, 체크아웃 자격증명 제거 등 기존 단계는 보존한다.

## 위험 (있을 때만)
- 워크플로 파일을 수정하는 PR은 변조 방지 가드로 인해 그 PR 안에서 변경된 워크플로가 자기 자신을 실행·검증하지 못할 수 있다(머지 후 다음 리뷰 실행부터 효력). 따라서 완료 검증은 구조 테스트(정적)와 머지 후 후속 PR의 실제 리뷰 언어 관찰로 나뉜다.
