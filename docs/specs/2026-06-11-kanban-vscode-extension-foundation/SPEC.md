# 칸반 상태 VSCode 확장 — 골격과 데이터소스 추상화

## 무엇을 만들 것인가

VSCode 확장의 기본 골격과, 프로젝트별로 달라지는 태스크 저장소를 단일 인터페이스 뒤로 감추는 **데이터소스 추상화 계층**을 만든다. 추상화는 세 가지 구체 어댑터를 제공한다: ① 로컬 파일(`docs/specs/` 아래 SPEC 파일), ② Beads, ③ GitHub Projects/Issues. 각 어댑터는 공통 계약을 따라 "태스크 목록 읽기", "단일 태스크 상세 열기", "본문을 가진 새 태스크 생성" 세 가지 능력을 노출한다. 한 태스크는 식별자·제목·상태 라벨·본문·원본 위치(파일 경로 또는 URL)를 갖는다. 상태는 정규화하지 않고 **백엔드가 보고한 원본 상태 문자열을 그대로** 라벨로 싣는다.

확장은 워크스페이스마다 어떤 어댑터가 활성인지를 결정한다(설정 또는 워크스페이스 신호 기반). 활성 어댑터 하나가 카드 뷰(별도 SPEC)와 태스크 추가 흐름(별도 SPEC)의 단일 데이터 공급원이 된다.

## 목적 (왜)

태스크의 현재 상태 확인과 새 태스크 추가를 편집기 밖으로 나가지 않고 하기 위해, 저장소가 무엇이든(파일·Beads·GitHub) 위쪽 UI가 동일하게 동작하도록 데이터 접근을 한 계약 뒤로 통일한다. 이 계층이 없으면 카드 뷰와 추가 흐름이 백엔드별 분기로 오염된다.

## 완료 조건

- 시스템은 식별자·제목·상태 라벨·본문·원본 위치 필드를 가진 단일 태스크 표현과, 목록 읽기·상세 열기·태스크 생성 세 능력을 선언하는 데이터소스 계약을 제공해야 한다.
- 파일 어댑터로 목록을 읽을 때, 시스템은 대상 디렉터리의 각 SPEC 파일을 하나의 태스크로 반환하고 그 파일에서 파생한 상태 라벨을 원본 그대로 실어야 한다.
- Beads 어댑터로 목록을 읽을 때, 시스템은 Beads가 보고한 각 이슈를 하나의 태스크로 반환하고 Beads의 상태 문자열을 원본 그대로 라벨로 실어야 한다.
- GitHub 어댑터로 목록을 읽을 때, 시스템은 대상 프로젝트/이슈를 하나씩 태스크로 반환하고 그 프로젝트의 "Status" 단일선택 필드 값을 상태 라벨로 원본 그대로 실어야 한다.
- 어떤 어댑터든 상세 열기를 요청하면, 시스템은 그 태스크의 원본(파일은 편집기에서, 원격 이슈는 해당 URL)을 열어야 한다.
- 어떤 어댑터든 본문을 가진 새 태스크 생성을 요청하면, 시스템은 그 본문으로 활성 백엔드에 새 항목을 만들고 새로 만들어진 태스크의 식별자를 반환해야 한다.
- 활성 어댑터를 결정할 수 없으면, 시스템은 어떤 백엔드도 구성되지 않았음을 알리는 관찰 가능한 오류 상태를 노출해야 한다.
- 어댑터가 외부 호출(원격·CLI)에 실패하면, 시스템은 빈 목록을 정상으로 위장하지 않고 실패를 구분되는 상태로 노출해야 한다.

## 범위

포함:
- VSCode 확장 활성화 진입점과 패키지 매니페스트(명령·기여점 등록의 최소 골격).
- 데이터소스 계약 인터페이스와 단일 태스크 표현 타입.
- 세 어댑터(Files / Beads / GitHub Projects·Issues) 각각의 목록 읽기·상세 열기·태스크 생성 구현.
- 워크스페이스별 활성 어댑터 선택(설정 또는 신호 기반).

비-목표 / 제외:
- 카드 뷰 UI(별도 SPEC: 상태 카드 뷰).
- Claude Code 인터뷰 동적 폼과 그 결과로 태스크를 만드는 추가 흐름의 UI(별도 SPEC: 인터뷰 동적 폼·태스크 생성). 단, 본 SPEC이 노출하는 "태스크 생성" 능력을 그 흐름이 호출한다.
- 상태 변경 쓰기(카드에서 상태 바꾸기) — v1 비목표.
- 여러 백엔드 동시 집계 — v1은 활성 어댑터 하나.

## 검증

이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약

- 구현 타깃은 이 모노레포가 아니라 **별도의 새 VSCode 확장 저장소**다. 본 SPEC은 그 저장소의 설계 산출물이며, `scope.include` 경로는 그 저장소 기준의 의도된 레이아웃이다.
- VSCode 확장으로 패키징·배포 가능해야 한다.
- 상태는 정규화 없이 백엔드 원본 문자열 패스스루.
- Beads 연동은 Beads가 제공하는 접근 경로(예: `bd` CLI 또는 그 데이터)를 사용한다. 구체 호출 방식은 구현이 정한다.
- GitHub 연동은 GitHub 인증 토큰을 요구한다.

## 위험

- 세 백엔드의 상태·필드 모델이 달라, 단일 태스크 표현이 일부 백엔드 고유 메타데이터를 손실할 수 있다. 원본 위치 필드로 상세 열기를 보장해 완화한다.
- GitHub Projects(v2)는 상태가 컬럼이 아닌 커스텀 필드로 모델링된다. v1은 프로젝트의 "Status" 단일선택 필드를 상태로 고정 채택한다 — 그 필드가 없는 프로젝트에서는 상태 라벨이 비게 되며, 어댑터는 이를 빈 라벨로 위장하지 않고 구분 가능하게 처리해야 한다.
- Beads의 설치·접근 전제(로컬 바이너리 유무)가 환경마다 달라 어댑터 가용성이 갈릴 수 있다.
