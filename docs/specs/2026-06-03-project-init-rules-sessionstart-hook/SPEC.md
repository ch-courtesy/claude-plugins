# project-init rules 인덱스 SessionStart hook + 읽기 모델 재구성

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
project-init이 부트스트랩하는 프로젝트에서 "카테고리별 지침(`rules/`)" 읽기 모델을 **이름-먼저 / 내용-just-in-time**으로 바꾸고, 세션 시작 시 `rules/` 인덱스를 결정론적으로 주입한다. 세 가지를 만든다:

1. **rules 인덱스 SessionStart hook** — project-init 플러그인에 SessionStart hook을 신설해, 세션 시작 시 해당 프로젝트의 `rules/` 트리를 훑어 **각 룰 파일의 경로 + 한 줄 목적(파일 첫 H1 제목)** 목록을 컨텍스트에 주입한다. `rules/`가 없으면 조용히 아무것도 하지 않는다.
2. **생성 CLAUDE.md 템플릿 재구성** — project-init이 생성하는 CLAUDE.md의 "카테고리별 지침" 베이스 템플릿을, "세션 시작 시엔 인덱스로 파일 이름·목적만 파악(전체 내용 선읽기 안 함) → 관련 작업 직전에 해당 파일 내용을 읽고 따른다"로 바꾼다. 그 위에 **벤더-중립 게이트 카브아웃**(세션 시작 시 주입된 워크플로 진입 규칙이 "먼저 진입 분기를 제시하라"고 요구하면, 새 코드 변경 신호에서는 그 분기 제시가 카테고리 내용 읽기보다 먼저다 — 분기 제시는 "작업 시작"이 아니다)을 가산한다.
3. **이 레포 CLAUDE.md 반영** — 위 읽기 모델·카브아웃을 이 레포의 루트 `CLAUDE.md`에도 동일하게 적용한다(project-init이 이 레포에 설치돼 있어 hook이 여기서도 발동).

## 목적 (왜)
<!-- 이 변경을 왜 하는가(목표·동기)를 1–3문장으로. -->
"작업 전 모든 `rules/`를 읽기"는 카테고리로 나눈 의미를 없애고 매 세션 비용을 키운다 — 이름만 먼저 알고 내용은 필요할 때 읽는 게 분리의 취지에 맞다. 그리고 "이름 파악"은 항상 일어나야 하는 결정론적 단계이므로, 모델 판단에 맡기지 않고 hook 주입으로 보장하면 신뢰성이 오른다(내용 읽기의 just-in-time 판단만 모델에 남긴다).

## 완료 조건
<!-- 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->
- 항상 project-init 플러그인은 SessionStart에서 발동하는 hook을 가지며, 그 hook은 대상 프로젝트의 `rules/` 트리에서 각 룰 파일의 경로와 한 줄 목적(첫 H1)을 추출해 인덱스로 주입한다.
- 대상 프로젝트에 `rules/` 디렉토리가 없으면, 그 hook은 오류 없이(0 종료) 아무것도 주입하지 않는다.
- 항상 project-init이 생성하는 CLAUDE.md의 "카테고리별 지침"은 세션 시작 시 인덱스로 파일 이름·목적만 파악하고, 각 파일의 내용은 관련 작업을 시작하기 직전에 읽도록 명시한다(전체 내용 선읽기를 요구하지 않는다).
- 항상 그 생성 CLAUDE.md는 세션 시작 시 주입된 워크플로 진입 분기가 새 코드 변경 신호에서 카테고리 내용 읽기를 포함한 어떤 탐색보다 먼저 제시됨을 — **특정 플러그인·스킬 이름 없이 일반어로** — 명시한다.
- 항상 이 레포의 루트 `CLAUDE.md`의 "카테고리별 지침"도 위 두 조건(이름-먼저/내용-just-in-time, 중립 게이트 카브아웃)을 동일하게 반영한다.
- project-init이 생성·주입하는 모든 문구는 벤더 중립이다 — 특정 플러그인·스킬 이름이나 도구 마커 접두사를 포함하지 않는다.

## 범위
포함:
- `plugins/project-init/` — SessionStart hook 신설(hook 선언 + 스크립트), 생성 CLAUDE.md 베이스 템플릿(`skills/bootstrap/CLAUDE.md`) 재구성
- 루트 `CLAUDE.md` — 동일 읽기 모델·중립 카브아웃 반영

비-목표 / 제외:
- autopilot `using-autopilot/SKILL.md`의 게이트-skip 문구 수정(→ 별도 SPEC)
- per-prompt 재주입 메커니즘(인덱스 주입은 세션당 1회)
- 기존 룰 파일 내용·구조 변경, 새 룰 카테고리 추가
- rule-creator 형제 스킬의 산출 로직 변경

## 검증
<!-- 검증 기준의 단일 출처는 위 "완료 조건"이다. -->
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다. (보조: hook은 `rules/` 있는 프로젝트·없는 프로젝트 두 경우로 실행해 인덱스 주입/무동작을 관찰하고, project-init `skills/*/tests/` 컨벤션에 맞춘 테스트로 보강한다.)

## 제약
- hook은 project-init 플러그인 소유다 — autopilot 등 다른 플러그인 hook을 건드리지 않는다. hook 선언·스크립트 컨벤션은 기존 패턴(`${CLAUDE_PLUGIN_ROOT}` 호출, `rules/` 없으면 `exit 0` 무동작)을 따른다.
- 인덱스 주입 내용·생성 CLAUDE.md·루트 CLAUDE.md 문구는 **벤더 중립**: 특정 플러그인·스킬 이름(autopilot·using-autopilot·spec·fsd 등)·도구 마커 접두사를 포함하지 않는다.
- "이름-먼저/내용-just-in-time" 재구성은 기존 카테고리별 지침의 강제력(위반=중대 결함, 관련 파일 내용을 작업 직전 반드시 읽고 따름)을 약화하지 않는다 — 선읽기 제거는 가산적 개선이다.
- `plugins/`는 버전 워치 디렉토리다(`rules/engineering/versioning.md`) → project-init 변경은 같은 머지 안에서 `plugin.json`(버전 SoT) SemVer 범프 + 루트 `marketplace.json` 미러 갱신을 동반해야 한다. 신규 기능이므로 1.0.0 이전(`0.y.z`)에서 MINOR 자리로 끊는다.

## 위험
- 인덱스 주입이 또 하나의 SessionStart 컨텍스트 블록을 더한다 — 룰 수가 많은 프로젝트에서 노이즈가 될 수 있어, 경로+한 줄 목적의 간결한 목록으로 제한한다(전체 내용 주입 금지).
- 게이트 카브아웃 문구가 "작업 전 rules/ 먼저"라는 기존 강제와 어긋나 보일 수 있다 — "분기 제시는 탐색·작업이 아니다"라는 카브아웃으로 정합시키고, 내용 읽기는 경로 선택 후로 명확히 미룬다.
- 생성 템플릿과 이 레포 CLAUDE.md의 문구가 어긋나면 혼란 — 두 위치의 읽기 모델·카브아웃 표현을 일치시킨다.
