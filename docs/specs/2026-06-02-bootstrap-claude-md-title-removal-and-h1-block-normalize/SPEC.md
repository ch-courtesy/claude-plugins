# bootstrap CLAUDE.md title removal and H1 block normalize

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
project-init `bootstrap` 스킬이 생성하는 `CLAUDE.md`에서, 파일명과 중복되는 `# CLAUDE.md` 최상위 제목을 없앤다. 대신 항상 포함되는 "카테고리별 지침" 섹션을 문서의 최상위 제목(H1)으로 승격해, 생성물의 안정적 최상위 제목이 되도록 한다.

조립되는 선택적 블록들도 같은 원칙으로 정규화한다 — 카파시 65줄 룰·상호작용 규칙·카테고리별 지침 세 블록이 각각 형제 관계의 최상위 제목(H1)으로 시작해 서로의 경계가 제목 레벨만으로 드러나게 한다. 카파시 자산은 이미 최상위 제목으로 시작하므로 그대로 두고, 상호작용 규칙 자산만 최상위 제목으로 끌어올리며 그 하위 제목들도 한 단계씩 함께 올려 상대 계층을 보존한다.

이 제목 레벨 변경에 맞춰, bootstrap `SKILL.md`의 조립 절차 서술도 정합하게 고친다 — 기존 서술은 사라지는 `# CLAUDE.md` 제목을 삽입 기준점으로 참조하므로, 그 기준점 대신 "각 블록은 형제 최상위 제목으로 경계가 드러난다"는 표현으로 갱신한다.

## 완료 조건
<!-- 5문장 패턴(항상 / …할 때 / …인 동안 / …이면(오류) / …기능이 켜지면)과 언어 규칙은 references/ears-patterns.md. 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->
- 항상 bootstrap 베이스 템플릿 파일(`plugins/project-init/skills/bootstrap/CLAUDE.md`)에 `# CLAUDE.md` 제목 줄이 존재하지 않는다.
- 항상 그 베이스 템플릿의 "카테고리별 지침" 섹션이 최상위 제목(`# 카테고리별 지침`)으로 시작하고, 그 아래 본문(`rules/` 안내 문단과 불릿 목록)은 문구 변경 없이 보존된다.
- 항상 상호작용 규칙 자산(`plugins/project-init/skills/bootstrap/assets/interaction-rules.ko.md`)의 최상단 제목이 최상위 제목(`# Claude 상호작용 규칙`)이고, 그 하위 제목들이 원래보다 한 단계씩 올라가(예: 원래 `### …` → `## …`) 상대 계층이 보존된다.
- bootstrap이 카파시 룰과 상호작용 규칙을 **둘 다 선택하지 않고** `CLAUDE.md`를 새로 생성할 때, 생성된 파일의 유일한 최상위 제목은 `# 카테고리별 지침`이다.
- bootstrap이 카파시 룰 또는 상호작용 규칙을 **하나 이상 선택해** `CLAUDE.md`를 새로 생성할 때, 포함된 각 조립 블록(카파시 룰·상호작용 규칙·카테고리별 지침)이 각각 형제 관계의 최상위 제목으로 시작해 블록 경계가 제목 레벨만으로 드러난다.
- 항상 bootstrap `SKILL.md` 3단계의 조립 서술이 `# CLAUDE.md` 제목을 삽입/조립 기준점으로 참조하지 않으며, 조립 순서(카파시 룰 → 상호작용 규칙 → 카테고리별 지침)와 "각 블록은 형제 최상위 제목으로 경계가 드러난다"는 설명이 실제 자산 제목 레벨과 정합한다.

## 범위
포함:
- bootstrap 베이스 템플릿 `plugins/project-init/skills/bootstrap/CLAUDE.md`의 `# CLAUDE.md` 제거 및 카테고리별 지침 제목 H2→H1 승격
- 상호작용 규칙 자산 `plugins/project-init/skills/bootstrap/assets/interaction-rules.ko.md`의 전체 제목 계층 한 단계 승격(최상단 H2→H1, 그 하위도 동반 승격)
- bootstrap `SKILL.md` 3단계 조립 절차 서술의 기준점·경계 표현 갱신

비-목표 / 제외:
- 카파시 룰 자산(`assets/karpathy-rules.ko.md`) — 이미 최상위 제목으로 시작하므로 변경하지 않음
- 베이스 템플릿 "카테고리별 지침" 본문 문구의 의미 변경(제목 레벨 외의 텍스트 수정)
- 프로젝트 루트의 통치 `CLAUDE.md` 및 다른 형제 스킬·`rules/` 파일
- `plugin.json` 버전 범프 — 변경 제안 통합 시점에 통합자가 SemVer로 수행(이 단위는 `plugins/` 파일만 수정)

## 검증
<!-- 검증 기준의 단일 출처는 위 "완료 조건"이다. 검증을 실행하는 진입 명령(테스트·lint·빌드)은 SPEC이 선언하지 않는다. -->
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약 (있을 때만)
- 변경 파일은 `plugins/project-init/skills/bootstrap/` 하위로 한정한다: 베이스 템플릿 `CLAUDE.md`, 자산 `assets/interaction-rules.ko.md`, `SKILL.md`. 이 베이스 템플릿 `CLAUDE.md`는 프로젝트 루트의 통치 `CLAUDE.md`가 아니라 스킬 자산이므로, scope의 `CLAUDE.md` 제외(루트 파일 대상)와 무관하게 in-scope다.
- "카테고리별 지침" 본문(문단·불릿)은 의미를 바꾸지 않고 제목 레벨만 H2→H1으로 올린다.
- 상호작용 규칙 자산은 최상단 제목만 올리는 게 아니라 자산 내부 제목 계층 전체를 한 단계씩 올려, 최상위 H1 아래에서 제목 레벨이 건너뛰지 않도록 한다(H1 → H2 → H3 순서 보존).
- 선택하지 않은 선택적 블록은 생성 `CLAUDE.md`에 어떤 형태로도(주석·접힘 포함) 넣지 않는다는 기존 bootstrap 규칙을 유지한다.
- 세 영역(카파시·상호작용·카테고리별)의 내용은 각각 한 파일에만 존재한다는 단일 출처 원칙을 유지한다.

## 위험 (있을 때만)
- 상호작용 규칙 자산의 하위 제목 동반 승격(`###`→`##`)을 누락하면 H1 바로 아래 H3가 와 계층이 건너뛰어진다 — 최상단뿐 아니라 자산 내부 모든 제목을 점검한다.
- `SKILL.md` 3단계는 `# CLAUDE.md` 제목 문구를 상호작용 삽입 위치·카파시 경계 설명 등 여러 군데에서 참조할 수 있다 — 모든 참조를 빠짐없이 갱신해야 서술과 실제 조립 결과가 어긋나지 않는다.
