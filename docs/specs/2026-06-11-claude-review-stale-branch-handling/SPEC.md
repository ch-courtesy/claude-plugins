# Claude Review Workflow Stale Branch Handling

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

Claude PR 리뷰 GitHub 워크플로가, **PR이 리뷰 워크플로 파일 자체를 수정하지 않았는데 단지 기본 브랜치(base)보다 뒤처져(stale) 그 파일이 현재 base 버전과 달라진 경우**에도 하드 실패하지 않고 Claude 리뷰를 정상 수행하도록 한다. 이때 리뷰는 base 브랜치의 신뢰된 워크플로를 기준으로 실행하되, 리뷰 대상은 여전히 그 PR의 변경(diff)이어야 한다.

PR이 리뷰 워크플로 파일을 **실제로 수정한** 경우는 기존 동작(권한 리뷰를 수행하지 않고 중립/생략 결과를 남김)을 그대로 유지한다 — 그 경우는 보안상 신뢰 경계가 달라지기 때문이다.

## 목적 (왜)
<!-- 완료 조건의 종속 앵커일 뿐 검증 기준이 아니다. -->

리뷰 액션의 App 토큰 검증은 "PR head의 워크플로 파일이 현재 기본 브랜치와 byte 동일"할 것을 요구하는데, 이는 "PR이 워크플로를 수정함"과 "PR이 뒤처져 base가 그 파일을 나중에 바꿈"을 구분하지 못한다. 그래서 base가 리뷰 워크플로를 갱신하면, 그 파일을 건드리지도 않은 옛 PR들이 동기화 전까지 모두 리뷰가 빨갛게 실패한다. 워크플로를 수정하지 않은 PR은 base 기준으로 안전하게 리뷰할 수 있으므로, 그 경우 실패 대신 정상 리뷰가 되게 한다.

## 완료 조건
<!-- 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->

1. **PR이 리뷰 워크플로 파일을 수정하지 않았는데 그 파일이 현재 base 브랜치 버전과 다를 때(stale)**, 워크플로는 하드 실패하지 않고 base 브랜치 기준으로 Claude 리뷰를 수행하여 판정을 산출해야 한다 — 리뷰가 다루는 변경은 여전히 그 PR의 diff여야 한다. (검증: base보다 뒤처졌고 워크플로를 건드리지 않은 PR에서 Claude 리뷰가 실패하지 않고 그 PR의 변경에 대한 판정이 게시됨이 관찰된다.)

2. **PR이 리뷰 워크플로 파일을 수정했을 때**, 기존 동작(권한 리뷰를 수행하지 않고 중립/생략 결과를 남김)이 유지되어야 한다. (검증: 워크플로 파일을 바꾼 PR에서 권한 리뷰가 수행되지 않고 생략 결과가 남음이 관찰된다.)

3. **PR head의 리뷰 워크플로 파일이 현재 base 버전과 동일할 때**, 평소대로 Claude 리뷰가 수행되어야 한다. (검증: 최신 상태의 일반 PR에서 리뷰가 정상 수행됨이 관찰된다.)

4. **항상**: 리뷰 워크플로 파일이 base와 다르다는 사유만으로 PR 체크가 실패(빨간 상태)하지 않아야 하며, 리뷰가 실제로 수행되지 않았는데 승인 판정(거짓 green)을 만들어서도 안 된다. (검증: stale PR에서 체크가 실패도 거짓 승인도 아닌, 정상 리뷰 결과 또는 명시적 중립 결과로 끝남이 관찰된다.)

## 범위
포함:
- Claude 리뷰 워크플로에서 "stale 이지만 워크플로 미수정" 경우를 감지해 base 기준으로 리뷰를 수행하는 분기.
- "워크플로 수정함" 경우의 기존 생략 경로 보존.

비-목표 / 제외:
- Codex 리뷰 워크플로(별도 파일)와 그 동작.
- 리뷰 액션(`claude-code-action`) 자체의 수정 — 외부 액션이며 범위 밖.
- 리뷰 판정 로직·프롬프트·청크 분할 등 리뷰 내용 자체의 변경.
- `rules/**`, `milestones/**`, `CLAUDE.md` 변경.

## 제약
- **대상 파일**: `.github/workflows/claude-review.yml` 한 파일만 변경한다.
- **"수정함" 판정 재사용**: PR이 리뷰 워크플로를 *수정했는지*는 기존 감지(PR 분기점 대비 PR head의 그 파일 변경 여부)를 재사용한다 — 수정함 → 기존 생략 경로.
- **stale-미수정 처리**: 워크플로를 수정하지 않았지만 base와 달라진 경우, Claude 리뷰 단계를 **base 브랜치 sha 기준으로 실행**해 리뷰 액션의 워크플로-파일 검증이 기본 브랜치와 동일하게 통과하도록 한다. 단 리뷰가 다루는 diff는 여전히 그 PR의 변경이어야 한다(리뷰는 PR 번호로 변경을 읽는다).
- **구현 베이스**: 현재 `origin/main`의 `claude-review.yml` 위에서 변경한다(로컬 기본 브랜치가 뒤처져 있으면 `origin/main` 기준). 이 수정은 기본 브랜치에 있어야 이후 PR들에 적용된다.
- **버전 규칙**: 버전업 강제 워치 디렉토리는 `plugins`이며 `.github/` 변경은 그 대상이 아니다(`rules/engineering/versioning.md`).

## 위험
- **리뷰 대상 보존**: base sha로 실행하더라도 리뷰가 base 코드가 아니라 *그 PR의 변경*을 대상으로 함을 보장해야 한다. 리뷰 액션이 PR 번호/API로 diff를 읽는지 확인하고, 잘못 구현하면 엉뚱하게 base를 리뷰하게 된다.
- **검증 ref 가정**: 리뷰 액션의 OAuth 검증이 실제로 어떤 ref의 워크플로 파일을 보는지(head/merge/checkout)에 따라 "base sha 실행"으로 통과하는지가 갈린다. 구현 중 실제 PR에서 통과를 확인한다. 만약 base-sha 경로로도 검증 통과가 불가능하면, 하드 실패 회피를 위해 기존 생략 경로로 폴백한다(완료 조건 4의 "빨간 실패 없음"은 그 경우에도 보존, 단 완료 조건 1의 "리뷰 수행"은 후속으로 분리).
- **수정-PR 경계 유지**: stale 처리를 넓히되 PR이 *실제로* 워크플로를 수정한 경우까지 base 기준으로 리뷰해 신뢰 경계를 무너뜨리지 않아야 한다(완료 조건 2 보존).
