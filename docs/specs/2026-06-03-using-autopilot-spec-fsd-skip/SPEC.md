# using-autopilot spec/fsd 게이트 누락(skip) 차단

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->
새 세션에서 코드-변경 요청이 들어와도 `using-autopilot`의 spec/fsd 분기(AskUserQuestion)가 첫 턴에 누락되는 문제를, 스킬 본문 문구 수정만으로 막는다. 실제 누락을 일으키는 세 가지 합리화 구멍을 명시적으로 차단한다:

- **"먼저 파악/이해하고" 반사** — 기존 코드를 이해해야 한다는 필요가 분기 라우팅의 예외가 아니며, 그 탐색은 분기 *이후* spec의 컨텍스트 단계에서 수행됨을 분명히 한다.
- **"SPEC 구현" 오인** — `<경로>/SPEC.md 구현`류 요청을 "읽기/검증(예외)"이 아니라 코드-변경 신호로 분류하게 한다.
- **문서·지침 편집 오분류** — 지침/문서의 축약·압축·수정·삭제도 "지침 작성/동작 수정" 코드-변경 신호이며 "코드 변경 아님"으로 합리화할 수 없음을 분명히 한다.

(rules/ 읽기 모델·게이트 우선순위의 CLAUDE.md 정리와 rules 인덱스 주입 hook은 별도 SPEC인 project-init 단위에서 다룬다 — 본 단위는 autopilot 스킬 본문에 한정.)

## 목적 (왜)
<!-- 이 변경을 왜 하는가(목표·동기)를 1–3문장으로. -->
과거 73개 세션 분석에서 코드-변경으로 연 50개 세션 중 16개(약 32%)가 **첫 턴에** 분기를 누락했고, 누락은 주입이 가장 신선한 시점에 발생했다 — 따라서 원인은 컨텍스트 희석이 아니라 첫 턴의 모델 합리화이며, 재주입이 아니라 합리화 구멍을 막는 문구 수정이 올바른 해법이다. 게이트가 신뢰성 있게 발동해야 autopilot의 spec-first 파이프라인이 실제로 진입점 역할을 한다.

## 완료 조건
<!-- 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->
- 항상 `using-autopilot` 스킬 본문은 "기존 코드를 먼저 이해·파악해야 한다"는 필요가 분기 라우팅의 예외가 **아니며**, 그 탐색은 분기 이후 spec의 컨텍스트 단계에서 수행된다고 명시한다.
- 요청이 `<경로>/SPEC.md 구현`처럼 기존 SPEC 파일 경로의 구현·구현 확인일 때, 스킬 본문은 이를 코드-변경 신호로 분류(읽기/검증 예외 아님)하도록 명시한다.
- 요청이 지침·문서의 편집·압축·축약·수정·삭제일 때, 스킬 본문은 이를 코드-변경 신호로 분류하도록 명시하여 "코드 변경 아님" 합리화를 차단한다.
- 항상 본 변경은 새 hook(UserPromptSubmit 등)·per-prompt 재주입 메커니즘을 추가하지 않는다 — `plugins/autopilot/hooks/hooks.json`은 SessionStart×2 + PreCompact 구성 그대로다.
- 정당한 예외(순수 질의응답·코드 읽기·검색·단순 디버깅·운영 명령)를 게이트로 끌어오면 오류다 — 기존 예외절의 정당한 예외는 보존된다.

## 범위

비-목표 / 제외:

## 검증
<!-- 검증 기준의 단일 출처는 위 "완료 조건"이다. -->
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다. (보조: 모델-층 행동이라 결정론적 단위 테스트가 없다 — 문구 존재·명료성으로 완료 조건을 관찰하고, 실효 확인은 세 실패 시나리오 재현으로 한다.)

## 제약
- 수정 파일은 정확히 하나: `plugins/autopilot/skills/using-autopilot/SKILL.md`. 그 외 파일은 건드리지 않는다.
- 순수 문서 편집 — 실행 코드·셸 스크립트 변경 없음.
- `plugins/`는 버전 워치 디렉토리다(`rules/engineering/versioning.md`) → SKILL.md 변경은 같은 머지 안에서 `plugin.json`(버전 SoT) SemVer 범프 + 루트 `marketplace.json` 미러 갱신을 동반해야 한다. 1.0.0 이전(`0.y.z`)이므로 MINOR 또는 PATCH 자리로 끊는다.
- 기존 예외절의 정당한 예외와 트리거 목록의 의미를 보존하며, 구멍 차단 문구는 가산만 한다(기존 규칙 약화·삭제 금지).

## 위험
- 모델-층 행동 변경이라 결정론적으로 검증하기 어렵다 — 완료 조건을 문구 명료성으로 관찰하고 실패 시나리오 재현으로 보강한다.
- 예외절을 과도하게 좁히면 정당한 디버깅·Q&A까지 게이트로 끌려와 마찰이 늘 수 있다 — 마지막 완료 조건(정당한 예외 보존)으로 방어한다.
