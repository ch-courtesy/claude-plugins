# dispatch integrate-by-default + no-forge direct merge

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

`autopilot:dispatch`의 통합(리뷰·머지) 모드를 **옵트인에서 기본 동작으로** 전환한다. 지금까지는 `--integrate` 플래그나 `APPROVER` 환경변수가 있어야만 dispatch가 구현 결과를 대상 브랜치로 머지했고, 없으면 결과가 격리 워크트리에만 남았다. 변경 후에는 별도 플래그 없이도 dispatch가 각 SPEC의 구현 완료 후 결과를 대상 브랜치로 자동 머지한다.

머지 방식은 환경에 따라 두 갈래다. forge가 구성된 환경(forge CLI 사용 가능 + 분리된 승인 신원 설정)에서는 기존 풀 파이프라인(작업 브랜치 push → 승인 요청(PR) → 리뷰 → 승인 → 머지)을 그대로 따른다. forge가 구성되지 않은 환경에서는 승인 요청·리뷰·승인 의례 없이 작업 결과를 대상 브랜치로 직접 머지한다. 두 갈래 모두 fast-forward 전용 머지만 쓰고 버전 범프 게이트를 통과해야 한다.

새 명시적 비활성화 수단을 제공해, 기본 켜짐을 끄고 "구현만 하고 머지하지 않는" 기존 동작을 복원할 수 있게 한다.

## 목적 (왜)
<!-- 이 변경을 왜 하는가(목표·동기)를 1–3문장으로. -->

사용자가 dispatch를 호출할 때마다 머지를 따로 켜지 않고도 "구현되면 대상 브랜치에 반영된다"가 기본 기대가 되도록 하기 위함이다. forge가 없는 가벼운 환경에서도 결과가 워크트리에 갇히지 않고 대상 브랜치로 흐르게 해, dispatch 한 번으로 의도가 끝까지 닫히도록 한다.

## 완료 조건
<!-- 각 조건은 관찰 가능하고 독립 검증 가능해야 함. -->

1. 항상 `dispatch start`는 별도 플래그 없이 통합(머지) 모드가 활성인 상태로 시작한다.
2. forge가 구성된(forge CLI 사용 가능하고 분리된 승인 신원이 설정된) 환경에서 한 SPEC의 구현이 완료(loop DONE)되면, 작업 브랜치 push → 승인 요청 생성/재사용 → 리뷰 판정 → 분리 승인 신원의 승인 → fast-forward 머지를 거쳐 그 SPEC이 `done`(=머지됨)으로 전이한다.
3. forge가 구성되지 않은 환경에서 한 SPEC의 구현이 완료되면, 승인 요청·리뷰·승인 단계 없이 그 SPEC의 작업 브랜치를 대상 브랜치로 fast-forward 직접 머지하고 `done`으로 전이한다.
4. `--no-integrate`로 시작하면, 통합·머지·승인 요청 없이 구현 완료(loop DONE)가 곧 `done`이며 대상 브랜치는 변경되지 않는다.
5. 머지될 변경이 버전 워치 디렉토리(`plugins/**`)를 건드리는데 패키지 매니페스트 버전 범프가 없으면(오류 조건), 직접 머지 경로든 풀 파이프라인 경로든 머지를 차단하고 차단 사실을 기록한다.
6. 항상 모든 머지·동기화 경로는 fast-forward 전용 머지만 사용하고 force(강제) push·history 재작성 rebase push를 어떤 경로에서도 쓰지 않는다.
7. `--resume`로 재개하면, 최초 시작 때 결정된 모드(통합 켜짐/`--no-integrate` 꺼짐)와 서브모드(forge/직접)가 동일하게 유지된다.
8. dispatch 스킬의 단위 self-test(스케줄러·머지·통합·리뷰 모듈)가 모두 통과(exit 0)하며, 위 1~6의 분기(기본 켜짐, `--no-integrate` 레거시 무호출, forge 미구성 시 직접 머지, forge 구성 시 풀 파이프라인 순서, 버전 게이트 차단, force 미사용)를 mock 인터페이스로 검증한다.

## 범위
포함:
- dispatch 스킬의 통합 모드 활성화 기본값 전환과 명시적 비활성화 수단(`--no-integrate`).
- forge 미구성 환경에서의 직접 머지 서브모드(리뷰·승인 없이 fast-forward 대상 브랜치 머지, 버전 게이트 유지).
- 위 동작을 검증하는 self-test 확장.
- dispatch 스킬 정의 문서(`SKILL.md`)를 새 기본 동작·서브모드·비활성화 수단에 맞게 정합.
- 이 변경에 따른 패키지 버전 범프와 그 미러 정합.

비-목표 / 제외:
- forge 미구성 직접 머지 직전에 적대적 리뷰(반대 가정·최소 해법·구속력 있는 제약 렌즈)를 끼우는 자동 폴백. 이번에는 그 자리에 리뷰 없는 직접 머지가 들어가고, 적대적 리뷰 삽입은 별도 후속 작업으로 미룬다.
- 리뷰 생산자(4-lens)의 적대 렌즈 통합·확장.
- 이벤트 구동(CI 워크플로) 자동 머지.

## 검증
<!-- 검증 기준의 단일 출처는 위 "완료 조건"이다. -->
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약
- 변경 표면은 `plugins/autopilot/skills/dispatch/references/`(`dispatch.sh`·`merge.sh`·필요 시 `integration.sh`)와 `SKILL.md`, 그리고 버전 매니페스트에 한정한다.
- 통합 활성 판정은 기본값을 켜짐으로 두되 `--no-integrate`로 끌 수 있어야 하고, 모드·서브모드는 `--resume`에서 sticky하도록 run 디렉토리 마커로 보존한다.
- forge 구성 판정은 기존 컨벤션(분리 승인 신원 환경변수 존재 + forge CLI 사용 가능)을 재사용한다.
- 직접 머지 서브모드는 기존 머지 헬퍼(버전 범프 게이트·fast-forward 머지·완료 전이·작업공간 정리 위임)를 재사용하되 승인 게이트만 우회한다. 작업 브랜치 식별과 loop 종료신호 판정은 기존 통합 모듈의 헬퍼를 재사용해 산식을 중복하지 않는다.
- force(강제) push·rebase 재작성·머지 커밋 생성을 어떤 경로에서도 쓰지 않는다(fast-forward 전용).
- 모든 외부 인터페이스(loop·git·forge·리뷰 생산자)는 주입 가능한 명령 변수로 유지해 self-test가 실제 PR·머지 없이 독립 검증 가능해야 한다.
- `plugins/**`(버전 워치 디렉토리)를 건드리는 변경이므로, **같은 변경 안에서** 패키지 매니페스트 버전 단일 출처와 그 마켓플레이스 미러 버전을 함께 올리고 두 값을 일치시킨다.

## 위험
- 기본 켜짐 + forge 미구성 직접 머지는 로컬 환경에서 dispatch가 구현 결과를 리뷰 없이 대상 브랜치로 머지함을 의미한다. 완화: 버전 범프 게이트·fast-forward 전용·force 금지 불변식과 `--no-integrate` 옵트아웃을 가드레일로 둔다. 리뷰 부재의 근본 완화(적대적 리뷰)는 명시적으로 후속 작업으로 분리한다.
- 기존 `--integrate`·승인 신원 경로의 회귀. 완화: 풀 파이프라인 순서를 검증하는 self-test 회귀 케이스를 유지·추가한다.
