# autopilot 대화형 세션 compaction handoff hook

## 무엇을 만들 것인가
autopilot에, 대화형 Claude Code 세션이 자동 컴팩션을 넘어 작업 컨텍스트를 보존하도록 하는 핸드오프 메커니즘을 추가한다. 컴팩션이 일어나기 직전에 현재 진행 상태를 구조화된 핸드오프 문서로 떠 두고, 다음 세션 시작 시 그 내용을 컨텍스트로 자동 복원한다. 대상은 사람이 함께 도는 **대화형 세션**(특히 conductor/dispatch 오케스트레이션을 운전하는 세션)이며, loop의 헤드리스 이터레이션(매 이터가 새 `claude --print` 프로세스이고 `.loop/notes.md`로 이미 인계하는 모델)은 대상이 아니다.

## 목적 (왜)
장시간 대화형 작업에서 자동 컴팩션이 진행 상황·결정·다음 단계 컨텍스트를 소실시키면, 컴팩션 이후 작업이 표류하거나 이미 한 일을 반복한다. 컴팩션 경계를 넘어 핵심 상태를 보존해 세션 연속성을 확보하는 것이 목적이다.

## 완료 조건
- 대화형 세션에서 자동 컴팩션이 시작되기 직전일 때, 시스템은 현재 작업 상태(작업·완료한 것·현재 상태·보존할 제약·만진 파일·미해결 질문·다음 단계)를 구조화된 핸드오프 문서로 디스크에 기록해야 한다.
- 핸드오프 문서가 존재하는 상태에서 새 세션이 시작될 때, 시스템은 그 문서 내용을 세션 컨텍스트로 자동 주입해야 한다.
- 핸드오프 문서 생성이 실패하거나 시간 초과되면, 시스템은 세션과 컴팩션을 막지 않고 통과시키며 실패 사실을 관찰 가능하게 남겨야 한다.
- loop의 헤드리스 이터레이션(새 `claude --print` 프로세스) 실행 중인 동안, 시스템은 이 세션 핸드오프 동작을 적용하지 않아야 한다.
- 기존 SessionStart 라우팅 주입(using-autopilot)이 동작하는 동안, 시스템은 핸드오프 복원 주입을 그와 충돌 없이 함께 수행해야 한다.

## 범위
포함:
- `plugins/autopilot/hooks/hooks.json`에 PreCompact 훅과(필요 시) SessionStart 복원 단계 추가
- 핸드오프 캡처·복원 스크립트(autopilot hooks 디렉토리)
- 대화형 세션과 loop 헤드리스 실행을 구분해 loop을 제외하는 식별 로직

비-목표 / 제외:
- loop의 이터간 `.loop/notes.md` 인계 메커니즘 변경(건드리지 않는다)
- 자동 컴팩션 임계값(PCT override) 변경 — 별도 결정 사안
- 외부 상태(이슈·브랜치·원격) 생성
- `rules/**`, `milestones/**`, `CLAUDE.md` 변경

## 검증
이 SPEC의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약
- 핸드오프 문서는 구조화된 형식으로 최소 다음 필드를 포함한다: 작업(task), 완료한 것(completed), 현재 상태(current_state), 보존할 제약(constraints), 만진 파일(files_touched), 미해결 질문(open_questions), 다음 단계(next_steps).
- 훅은 세션과 컴팩션을 절대 차단하지 않는다 — 타임아웃·실패 시 graceful passthrough.
- 기존 `session-start.sh`의 using-autopilot 라우팅 주입과 공존한다(둘 다 동작).
- loop 작업 공간(헌법이 `CLAUDE.md`로 복사된 환경) 또는 `claude --print` 비대화 실행을 식별 신호로 구분해 제외한다.
- 핸드오프 산출물은 autopilot 자기 상태 디렉토리에 두고 git 추적 제외를 고려한다.

## 위험
- 대화형 세션과 loop 헤드리스 실행을 신뢰성 있게 구분하지 못하면 loop에 잘못 적용될 수 있다 — 식별 신호를 구현 단계에서 명확히 해야 한다.
- PreCompact 훅에서 요약을 위해 별도 모델 호출을 쓰면 비용·지연이 생긴다 — 타임아웃과 폴백(원시 덤프) 경로가 필요하다.
