# 리뷰 불필요 시 사유를 PR 댓글로 남기기

## 무엇을 만들 것인가
PR 리뷰 워크플로(codex·claude)가 변경을 **코드 리뷰 대상이 아니라고 판정해 리뷰를 게시하지
않을 때**, 침묵하는 대신 **왜 리뷰하지 않았는지 사유를 PR에 사람이 읽을 수 있는 댓글로**
남긴다.

- 트리거: 리뷰 산출에서 실제로 리뷰된 청크가 하나도 없을 때(모든 청크의 적격성이
  `reviewed` 가 아닌 경우 — 예: 문서 전용 변경으로 correctness 위험 없음 → skip/unavailable).
  현재 이 경우 두 워크플로는 "게시할 리뷰 없음"으로 **조용히 종료**한다.
- 동작: 그 종료 직전에, **그 리뷰어 식별 라벨**(기존 헤더 컨벤션 `🤖 Codex 리뷰` /
  `🤖 Claude 리뷰`)을 단 **issue 레벨 일반 PR 댓글**로 "리뷰를 게시하지 않은 사유"를 남긴다.
  사유 문구는 리뷰 산출이 낸 reason(예: "문서 전용 변경으로 correctness 위험 없음")을 사람이
  읽을 수 있게 담는다.
- 멱등성: **리뷰어당 댓글 1개를 upsert** 한다 — 숨은 식별 마커로 그 리뷰어의 기존 사유 댓글을
  찾으면 본문(현재 head SHA·사유)을 갱신하고, 없으면 새로 만든다. 매 push·재실행마다 새 댓글이
  쌓이지 않는다.
- 두 워크플로(codex·claude)에 **대칭**으로 적용한다.

정상 리뷰가 게시되는 경우(리뷰된 청크가 있어 findings/approve/comment 를 게시)에는 이 사유
댓글을 만들지 않는다. 기존 리뷰 제출(createReview)·false-green 가드·자기 thread resolve
경로는 바꾸지 않는다 — 이 댓글은 "리뷰된 청크 없음" 종료 분기에서만 추가된다.

## 목적 (왜)
지금은 문서 전용 같은 "리뷰 불필요" 변경에서 리뷰어가 아무 흔적도 남기지 않아, PR을 보는
사람이 "왜 리뷰가 없지? 리뷰어가 고장났나?"를 알 수 없다(#337에서 실제로 발생). 리뷰를 건너뛴
이유를 명시적으로 남겨, 침묵을 "의도된 skip"으로 읽을 수 있게 한다.

## 완료 조건
- 리뷰된 청크가 하나도 없어(모든 청크 적격성 ≠ `reviewed`) 리뷰를 게시하지 않는 경우, 그
  워크플로(codex 또는 claude)는 그 리뷰어 라벨을 단 issue 레벨 PR 댓글로 사유를 남긴다.
- 그 사유 댓글 본문은 산출된 reason(왜 리뷰 대상이 아닌지)과 대상 head SHA 를 사람이 읽을 수
  있게 포함한다.
- 같은 PR·같은 리뷰어에 대해 사유 댓글은 **항상 최대 1개**다 — 이미 있으면 새로 만들지 않고
  본문을 갱신(upsert)한다(매 push·재실행마다 누적되지 않는다).
- 리뷰된 청크가 하나라도 있어 정상 리뷰(findings/approve/comment)를 게시하는 경우에는 사유
  댓글을 만들지 않는다.
- codex 와 claude 워크플로 모두 동일한 동작을 한다(라벨·마커는 리뷰어별로 구분).
- 사유 댓글 추가는 기존 리뷰 제출·false-green 가드·자기 thread resolve 동작을 바꾸지 않는다
  (그 경로들이 타지 않는 "리뷰된 청크 없음" 분기에서만 동작).

## 범위
포함:
- `.github/workflows/codex-review.yml` — merge 잡의 "리뷰된 청크 없음" 종료 분기에 사유 댓글
  upsert 추가.
- `.github/workflows/claude-review.yml` — 동일 대칭 추가.

비-목표 / 제외:
- 정상 리뷰 경로(createReview·인라인 findings·approve/comment 판정)의 동작 변경.
- false-green 가드(청크 결과가 0개일 때 job 실패) 변경 — 그건 "산출물 자체 없음"이라 별개다.
- 리뷰 모델/프롬프트가 skip·unavailable 을 판정하는 기준 변경.
- skip 과 unavailable 을 서로 다른 댓글 양식으로 분기하는 것(산출 reason 을 그대로 노출하면
  충분 — 별도 양식 분기는 비목표).

## 검증
이 SPEC 의 인수 바는 위 **완료 조건**이다. 각 조건이 관찰 가능하게 충족되면 충족된 것으로
본다. 검증을 실행하는 진입 명령은 SPEC 이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로
정의한다.

## 제약
- 사유 댓글은 **issue 레벨 일반 PR 댓글**로 남긴다(formal review 가 아님 — reviewDecision 에
  영향 주지 않는다).
- 리뷰어 식별은 기존 헤더 라벨 컨벤션(`🤖 Codex 리뷰` / `🤖 Claude 리뷰`)을 따르고, upsert
  식별은 기존 숨은 마커 컨벤션(`<!-- ... -->`)을 재사용해 리뷰어별로 스코프한다.
- 게시·갱신은 merge 잡이 이미 쓰는 토큰/식별(App 토큰 또는 기본 토큰)로 수행한다 — 새 권한·새
  토큰을 도입하지 않는다.
- 워크플로/스크립트 수정은 **머지 후 효력**(변조방지 — 도입 PR 자신은 base 코드로 리뷰됨).
  기존 `.github/scripts` hermetic 계약 테스트를 깨지 않는다(공유 로직을 건드리면 그 테스트도
  갱신).

## 위험
- 사유 댓글이 매 push 마다 누적되면 PR 이 지저분해진다 — 리뷰어당 1개 upsert(마커 기반)로
  방지한다(완료 조건).
- "리뷰된 청크 없음" 분기가 정상 리뷰 경로보다 먼저 return 하므로, 사유 댓글은 그 분기 안에서만
  추가해 정상 리뷰·thread resolve 동작과 섞이지 않게 한다.
