# loop 스킬: persona verification + lateral unstuck

## 무엇을 만들 것인가
<!-- WHAT/HOW 방어선: 무엇을 만들지만 적고 구현 방법·파일·라이브러리·클래스명은 제약으로 이동. -->

autopilot `loop` 스킬의 워커 헌법·위임 양식·운영 안내에 두 가지 가산 기능을 추가한다. 두 기능 모두 워커의 행동(프롬프트·헌법) 차원이며, bash 드라이버는 변경하지 않고 새 런타임·엔진·의존성을 도입하지 않는다. 페르소나 정의는 선행 SPEC이 저작하는 단일 출처를 **참조**하며 복제하지 않는다.

1. **페르소나 기반 적대적 검증 (loop측).** 워커가 완료 직전 자체 검토(구조 검증과 완료 결정 사이)에 이를 때, 변경이 비자명하면(diff 규모 또는 관여 수용기준 수가 임계 이상) 세 적대적 사고 렌즈로 변경을 점검한다. 렌즈는 **발견만 보고**하고, 완료·수정·의심점 기록 결정은 워커가 한다. 이는 기존 구조 검증을 약화하지 않고 그 위에 가산된다.

2. **정체 시 lateral-thinking 회복.** 워커가 *워커-판단* 정체(같은 에러 반복, 정체, 변경 진동, 반복 실패)로 에스컬레이션하려 할 때, 곧장 차단 보고하지 않고 먼저 **정확히 한 번** 측면사고 회복 이터를 시도한다 — 적대 렌즈로 근본 원인 가설을 재구성한 뒤 최소 변경으로 한 차례 재시도. 그 시도가 기존 진전 정의(테스트 통과, 에러 신호 변화, 근본 원인 이해 갱신 중 하나)에 해당하는 진전을 내면 정상 루프를 잇고, 무진전이면 기존과 동일하게 차단 에스컬레이션한다. 단, 안전성에 직결되는 정지 조건(범위 이탈, 테스트 약화·삭제, 비밀 노출, 평가·수용기준 편집)은 회복 시도 없이 즉시 에스컬레이션한다. 회복은 드라이버가 강제하는 기존 정지 한계(증상 수정 연속, 진동 토글 등) 안에 머문다.

## 수용 기준 (EARS)
<!-- EARS 5패턴과 언어 규칙은 references/ears-patterns.md. 각 기준은 관찰 가능하고 독립 검증 가능해야 함. -->

**페르소나 적대적 검증**

- When 워커가 비자명한 변경(diff 규모 또는 관여 수용기준 수가 임계 이상)의 완료 직전 자체 검토에 이르면, 워커는 완료 결정 전에 세 적대 렌즈별로 태그된 발견 항목을 얻을 수 있어야 한다.
- When 적대 렌즈 발견이 미해결 의심을 가리키면, 워커는 조용히 완료로 전이하지 않고 인계 기록의 의심점 영역에 그 의심을 기록해야 한다.
- While 적대 렌즈 검증이 수행되는 동안, 위임된 보조 검토자는 발견만 보고해야 하며 최종 완료·차단 결정을 내리지 않아야 한다.
- The 적대 렌즈 검증은 기존 구조 검증(존재·실질·연결·런타임)을 약화하거나 우회하지 않고 그것에 가산되어야 한다.
- The loop 스킬은 페르소나 정의를 자체 복제하지 않고 선행 spec 스킬의 단일 출처 카탈로그를 참조해야 한다.

**정체 시 lateral-thinking 회복**

- When 워커가 워커-판단 정체(같은 에러 반복, 정체, 변경 진동, 반복 실패)를 감지하면, 차단 에스컬레이션 전에 정확히 한 번의 측면사고 회복 이터를 시도해야 한다.
- When 회복 이터가 진전(테스트 통과 또는 에러 신호 변화 또는 근본 원인 이해 갱신)을 내면, 워커는 정상 루프를 잇고 에스컬레이션하지 않아야 한다.
- If 회복 이터가 무진전이면, 워커는 본 기능 도입 이전과 동일한 표준 보고로 차단 에스컬레이션해야 한다.
- If 안전성 직결 정지 조건(범위 이탈, 테스트 약화·삭제, 비밀 노출, 평가·수용기준 편집)이 성립하면, 워커는 회복 시도 없이 즉시 에스컬레이션해야 한다.
- The 회복 시도는 연속 증상-수정 커밋을 2회로 만들지 않고 진동 토글을 완성하지 않아 드라이버의 기존 정지 한계 안에 머물러야 한다.
- The 회복 시도는 한 정체 에피소드당 한 번으로 제한되어야 한다.
- When 회복 이터를 시도하면, 워커는 그 시도와 진전·무진전 판정을 task 메모리(인계·노트)에 기록해 다음 콜드스타트가 볼 수 있게 해야 한다.

**불변(가산성·안전 보장)**

- The bash 드라이버가 강제하는 기존 정지(증상-수정 연속, 진동, 범위 이탈, 테스트 약화, 비밀 노출)는 본 변경 후에도 동일하게 동작해야 한다.

## 범위
포함:
- autopilot `loop` 스킬 헌법의 완료 직전 자체 검토에 적대 렌즈 절 추가(비자명 변경 임계로 발동, 선행 SPEC의 페르소나 카탈로그 참조)
- autopilot `loop` 스킬 위임 양식에 적대 렌즈 검증 질문 추가(발견만 보고, 최종결정 금지)
- autopilot `loop` 스킬 헌법의 조기 정지·근본원인 단계에 에스컬레이션 전 1회 측면사고 회복 삽입(안전 정지는 즉시 에스컬레이션로 명시)
- autopilot `loop` 스킬 위임 양식에 측면사고 회복 양식 추가(가설 재구성·읽기 우선·최소 변경·발견만 보고, 페르소나 카탈로그 재사용)
- autopilot `loop` 스킬 운영 안내에 에스컬레이션 전 1회 회복과 그 경계 명시
- 위 변경에 대응하는 loop 스킬 계약 테스트의 가산 assert와 기존 드라이버 정지 회귀 가드 유지

비-목표 / 제외:
- bash 드라이버(loop 실행 스크립트) 로직 변경 — 기존 정지 게이트는 수렴 천장으로 불변 유지
- 페르소나 카탈로그의 저작·정의(선행 spec 스킬 SPEC 소관)
- 무거운 Ouroboros 차용(SPEC 자가진화, event-sourcing replay, 모델·비용 티어링, 다중모델 합의 게이트)
- 무제한·반복 측면사고 재시도
- 검증 진입 명령(테스트·lint·빌드)의 SPEC 내 선언

이 SPEC의 인수 바는 위 **수용 기준 (EARS)**이다. 각 기준이 관찰 가능하게 충족되면 충족된 것으로 본다. 검증을 실행하는 진입 명령은 SPEC이 아니라 프로젝트 규칙(`rules/`)이 단일 출처로 정의한다.

## 제약 (있을 때만)
- 철학 불변: 경량·무인프라(SQLite/데몬 없음), 사람 게이트, 워커에게 SPEC 불변, Claude Code 네이티브(헌법·위임 양식 + subagent 위임). 새 런타임·엔진·의존성 금지.
- bash 드라이버는 변경하지 않는다. 회복 경계는 새 드라이버 변수가 아니라 기존 드라이버 정지 한계와 워커 메모리로만 보장한다.
- 보조 검토자·회복 양식은 발견만 보고하고 워커가 결정한다(중첩 dispatch 금지).
- 페르소나 카탈로그는 선행 SPEC(`spec-persona-adversarial-review-clarity-score`)이 저작한 단일 출처를 참조한다. 이 의존이 `depends_on`의 근거다.
- 본 변경은 `plugins/` 워치 디렉터리를 건드리므로, 기본 브랜치 머지 시 같은 머지에서 `plugins/autopilot/.claude-plugin/plugin.json`과 `.claude-plugin/marketplace.json`의 autopilot 버전을 MINOR(가산·하위호환)로 동반 상향해야 한다(선행 SPEC이 아직 미릴리스면 같은 0.8.0, 이후면 다음 MINOR). 버저닝 규칙의 단일 출처는 `rules/engineering/versioning.md`다.

## 위험 (있을 때만)
- 측면사고 회복이 무제한 반복되면 정지 한계에 근접·우회할 수 있다 → 에피소드당 1회 + 드라이버 정지 한계 내부 유지로 완화.
- 회복이 안전 정지를 지연시키면 위험 변경이 통과할 수 있다 → 안전 직결 정지는 회복 없이 즉시 에스컬레이션으로 명시해 완화.
- 페르소나 카탈로그를 loop가 복제하면 표류한다 → 선행 SPEC 단일 출처 참조로 완화(`depends_on`).
- 적대 렌즈 검증이 항상 켜지면 이터 비용이 증가한다 → 비자명 변경 임계로만 발동해 완화.
