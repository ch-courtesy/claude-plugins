## 대조 (분리된 변수별)

| 비교 | 무엇을 분리 | 결과 |
|---|---|---|
| **S1 → S2** | 동시성 (순차 vs 병렬, 그 외 동일) | 벽시계 **69,987 → 17,725ms = 3.95× 단축**. 총 토큰 거의 불변(127k↔128k). |
| **S3 vs S4** | 배리어 (무배리어 pipeline vs 단계 배리어) | 동일 작업·동일 토큰(~263k)인데 **pipeline 34,752 vs barrier 41,648ms — pipeline이 ~16.6% 빠름** (≈6.9s). |
| **S0 vs S2** | 팬아웃 자체 (모놀리스 vs 병렬 팬아웃) | 모놀리스가 토큰 **~4배 적음**(33k vs 128k, 에이전트별 컨텍스트 오버헤드 부재)이나 벽시계는 더 느림(22.5k vs 17.7k)이고 N 증가 시 병렬화 불가. |
| **단일단계(S2) vs 2단계(S3)** | verify 단계 추가 | 토큰·시간 약 2배(128k→263k, 17.7k→34.8k). 그러나 **subcommand 오류 0건 → verify가 정정한 건 cosmetic purpose 1건뿐**. 이 난이도에선 검증 단계가 비용만 추가. |

## 한 줄 요약

- **동시성이 핵심 레버**: 같은 토큰으로 벽시계 ~4배. 독립 작업이면 `parallel()`/`pipeline()`이 거의 공짜 속도.
- **토큰 비용 ∝ 에이전트 수**: 총 토큰은 에이전트별 컨텍스트(시스템 프롬프트 등) 오버헤드가 지배 → 1/8/16 에이전트가 ~33k/128k/263k로 거의 선형. 출력 토큰 자체는 작음(3~7k).
- **무배리어 > 배리어**: 다단계면 `pipeline()`이 `parallel()`+배리어보다 항상 빠르거나 같음(여기선 17%). 단계 시간 편차가 클수록 격차 커짐.
- **품질은 작업 난이도에 종속**: 쉬운 추출 작업에선 팬아웃이 품질을 떨어뜨리지 않았고 verify 단계의 한계 효용도 0에 가까움. 검증 패턴의 값은 더 모호·고위험 작업에서 나온다.
