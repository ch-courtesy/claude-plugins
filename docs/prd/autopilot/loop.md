# 역PRD — autopilot `loop` 스킬

> **문서 성격**: 현재 구현에서 제품 요구사항을 역추출한 재구현 기준서(역PRD). 구현 방법(HOW)은 싣지 않는다.
>
> **근거 소스 범위**: 이 리포지토리 `plugins/autopilot/skills/loop/`의 `SKILL.md`와 `references/` 하위 모듈 전체(워커 헌법, 셸 드라이버, 운영 가이드, 상태 출력 형식, 차단 처리, 이터 내 위임 brief). 드라이버 구현부에서는 사용자 가시 동작(서브커맨드·플래그·출력·산출물 경로·오류 동작)만 추출했다.
> **기준 플러그인 버전**: autopilot `0.38.1` (작성 시점 스냅샷 — 이후 스킬 변경 시 본 문서와 드리프트가 생길 수 있다).

## ① 개요·배경·목적

`loop`은 **단일 SPEC 파일을 격리 작업 공간에서 자율 구현하는 최소 실행기**(랄프 루프)다. 실행 정체성은 스펙 파일의 절대 경로이며, 스펙 디렉토리 아래 전용 워크트리를 작업 공간으로 만들고, 그 안에서 매 이터레이션마다 새 에이전트 프로세스를 띄워 "스펙 → 구현 → 검증 → 기록"을 반복한다.

배경: 자율 구현은 ⑴ 무인으로 오래 돌 수 있어야 하고 ⑵ 폭주(scope 이탈·테스트 약화·증상 땜질 반복)를 기계적으로 차단해야 하며 ⑶ 세션 기억 없이도 이터 간 연속성이 보장돼야 한다. loop은 이를 격리 워크트리 + 객관 게이트 + 디스크 기반 기억(노트·신호)으로 해결한다.

목적(존재 이유):

- 어떤 도구가 만든 스펙이든 **임의의 스펙 파일 경로 하나**를 받아 로컬에서 자율 구현을 끝까지(완료·차단·정지) 수행한다.
- 워커(에이전트)와 드라이버(루프 제어)의 책임을 분리한다 — 드라이버는 신호 파일의 이름·내용을 파싱하지 않고 "신호 디렉토리가 비었는가"만 본다. 의미 해석은 워커·호출자 컨벤션이다.
- 구현 이후의 통합·PR·머지는 수행하지 않는다(호출 레이어 책임).

## ② 사용자·호출 시나리오

| 시나리오 | 호출자 | 흐름 |
|---|---|---|
| 단일 SPEC 자율 구현 | 사람 또는 상위 호출자(execute-task·workflow-task의 워커 등) | `start <spec-path>` 포그라운드 실행 → 종료 후 신호 디렉토리 내용 직접 검사 |
| 비차단 실행 | 호출 세션 | loop을 백그라운드 프로세스로 직접 띄우지 않고, **백그라운드 서브에이전트가 loop을 포그라운드로** 실행하게 한다(서브에이전트 턴 종료 시 백그라운드 프로세스가 강제 종료되어 산출물 없이 실패하는 문제 회피 — 통제 실험으로 확인된 제약) |
| 진행 관찰 | 호출 세션 | 실행 중 디스크 아티팩트(이터 로그·신호 디렉토리)를 폴링 — `logs`, `status`, `paths`로 조회 |
| 종료 상태 판정(기계) | execute-task 등 호출 레이어 | `status --json`으로 구조화 상태를 받아 신호 이름의 정확 일치 멤버십으로 판정 |
| 차단 해소 후 재개 | 사람 | 차단 신호 본문을 읽고 원인 보정 → 신호 파일 삭제 → `start` 재시작 |
| 실행 정지/정리 | 사람 또는 오케스트레이터 | `stop`(작업 공간 유지) / `cleanup`(terminal 후 워크트리 제거) |

## ③ 기능 요구사항 (동작 정의)

### 정체성·작업 공간

- 항상, 실행 단위의 정체성은 **스펙 파일의 절대 경로**다. 상태 표시용 12자 키는 그 절대 경로의 sha256 앞 12자로 파생한다.
- `start`할 때, 시스템은 호출 위치와 무관하게 스펙 디렉토리 아래 **전용 워크트리**(`<spec_dir>/.worktree`)를 detached HEAD로 새로 생성해야 한다 — 보조 워크트리 안에서 호출돼도 그 워크트리를 재사용하지 않는다. 같은 스펙의 재기동이면 기존 전용 워크트리를 재사용한다. 전용 워크트리 생성에 실패하면 대체 위치로 폴백하지 않고 0이 아닌 코드로 중단한다.
- 항상, 작업 공간 안에는 워커 헌법 사본(`CLAUDE.md`)과 런타임 메타 영역(`.loop/`: 기준 커밋, 스펙 경로, 노트 `notes.md`, 이터 로그 `iterations/<n>.log`, 신호 디렉토리 `signals/`)이 있어야 하며, 이들과 lock은 git 추적에서 제외된다.
- 워크트리는 별도 브랜치 ref를 만들지 않는다 — 정리는 워크트리 제거만으로 끝나고, 미커밋·미통합 작업은 reflog에 남아 git GC 정책을 따른다.
- 스펙 파일이 git 저장소 안에 있지 않으면 오류로 중단한다.
- 후속 명령(`status`/`logs`/`cleanup`/`paths`)은 어느 디렉토리에서 호출되든 `start`가 기록한 실제 작업 공간 경로를 해석해 같은 작업 공간을 보아야 한다.

### 동시성 lock

- `start`할 때, 시스템은 **워크트리 생성 전에** 스펙 디렉토리의 lock을 원자적으로 획득해야 한다(동시 두 start 중 한쪽만 성공). 이미 활성 실행이 있으면 거부한다.
- 활성 판정은 드라이버 프로세스뿐 아니라 워커(자식 실행기) 생존까지 본다 — 드라이버가 죽고 워커만 남은 orphan도 "실행 중"으로 보고 두 번째 start를 거부한다.
- stale lock(관련 프로세스 모두 비활성)은 다음 `start`/`stop`에서 경고와 함께 자동 정리한다.
- 정상 종료 시 lock을 해제하되, 워커 프로세스가 살아남아 있으면 lock을 유지해 orphan 워커를 보호한다.

### 이터레이션 루프 (드라이버)

- `start`는 **포그라운드(동기)**로 실행되며 루프 종료까지 블로킹한다. 종료 후 신호 검사·후속 판단은 호출자 몫이다.
- 매 이터레이션은 **새 에이전트 프로세스**다. 입력은 작업 공간의 헌법(`CLAUDE.md`), 스펙 본문, 디스크 상태, 노트이고 출력은 코드 변경·분류 prefix 커밋·노트 갱신·(필요 시) 신호 파일이다. 이터별 출력은 이터 로그로 보존된다.
- 이터 종료 후, 신호 디렉토리가 비어 있지 않으면 드라이버는 정상 종료(exit 0)한다 — **파일 이름·내용은 파싱하지 않으며**, 작업 공간을 보존하고 신호 파일 목록과 정리 방법을 안내한다. 통합·PR 등 후속은 수행하지 않는다.
- 신호가 없으면 객관 게이트를 검사하고, 통과하면 다음 이터로 진행한다.
- 드라이버는 스펙 내용을 검증하지 않는다(특정 스펙 도구의 마커·placeholder 규약에 비결합) — 스펙 미흡 판단은 워커가 차단 신호로 표현하고 호출자가 본문을 보고 판단한다.

### 객관 게이트 (위반 시 halt)

이터 후 드라이버가 기계적으로 검사하며, 위반 시 **halt**한다: 미커밋 변경 자동 stash + 표준 에러 메시지 + exit 1, **신호 파일은 만들지 않는다**(워커 신호 의미 공간 불침범).

- 이터 상한 도달(기본 30, 플래그/환경 변수로 조정).
- 시간 상한 도달(기본 120분, 플래그/환경 변수로 조정).
- 에이전트 프로세스 비정상 종료 연속(기본 3회; rate limit·네트워크·인증 의심).
- **테스트 약화** — 이터 시작 시점 대비 기존 테스트 파일의 변경(삭제·수정) 감지. 테스트 파일 식별은 기본 휴리스틱(테스트 디렉토리·파일명 패턴) 또는 SPEC frontmatter `test_paths` override를 따르고, `test_sweep_paths`에 매칭되는 파일은 합법적 정리(rename/cleanup/delete)로 보아 비교에서 제외한다. `test_sweep_paths`가 선언됐으나 매칭 파일이 없으면 경고한다.
- **의존성 변경** — 의존성 매니페스트(주요 생태계 매니페스트 파일들)의 내용 변경 감지.
- **scope 위반** — 기준 커밋 이후의 변경 파일(커밋·미커밋 포함)이 SPEC frontmatter `scope.include` 패턴 밖이거나 `scope.exclude`에 걸리면 위반 파일 목록과 함께 halt.
- **suppressor 신규 추가** — 진단 억제 주석(noqa·@ts-ignore·eslint-disable·#pragma warning disable 류)의 추가 감지.
- **secrets 의심** — secret 스캐너가 설치된 경우에만 활성화되는 선택 게이트.
- **fix:symptom streak** — 최근 커밋 2개 연속 `fix:symptom` prefix.
- **변경 파일 진동** — 최근 4커밋의 변경 파일 집합이 두 상태로 토글.

### 워커 계약 (헌법 — 작업 공간 최상위 규칙)

워커 헌법은 작업 공간 `CLAUDE.md`로 복사되어 사용자 지시·SPEC·도구 설명보다 우선하며, 워커는 이를 수정하지 않는다. 핵심 요구사항:

- **Iron Laws**: ⑴ production 코드 전 실패 테스트 확인(TDD) ⑵ fresh verify(직전 실행 0 exit) 없이 완료 선언 금지 ⑶ root cause 조사 없이 fix 금지.
- **작업 매체**: 기억은 코드·git history·작업 공간 파일뿐. 노트(`.loop/notes.md`)는 계획·DoD·교훈·인계·차단·완료를 큐레이션하는 단일 기록 영역. terminal 의도는 신호 디렉토리에 파일을 만들어 표현하며, 권장 컨벤션은 `DONE`(본문=완료 요약)과 `BLOCKED`(첫 줄 `category:`, 이어서 사유·시도·필요 결정; category 권장값 `config-gap`·`spec-gap`·`architecture-gap`·`environment-gap`·`other`). 드라이버는 파일 이름·내용을 파싱하지 않는다 — 컨벤션은 워커 사이의 표준 어휘다.
- **한 이터 6단계**: 계획(스펙으로 실행 계획을 형성할 수 없으면 즉시 `spec-gap` 차단) → RED(실패 테스트) → GREEN(최소 구현) → 검증 → 분류·기록 → 결정(완료/차단/인계). refactor·test-only 이터는 RED/GREEN 생략 가능.
- **커밋 분류**: `fix:root`/`fix:symptom`/`feat`/`refactor`/`test`/`chore` prefix. `fix:symptom` 후에는 계획 재검토와 workaround/정의 보정/revert/block 중 하나를 기록. revert는 HEAD 단일 커밋만, 광범위 재구성은 `architecture-gap` 차단.
- **4-Level Verifier**(완료 전제): Existence(수용 기준 대응 변경 존재) · Substantive(stub/mock/TODO 아님) · Wired(실제 호출처 연결) · Runtime(검증 0 exit). 추가로 scope 내 변경·`fix:symptom` 누적 없음.
- **Self-Review**: 완료 직전 Completeness·Quality·Discipline·Testing 점검. 의심이 있으면 완료 대신 노트의 의심점에 기록하고 다음 이터로.
- **적대 렌즈 검증**: 비자명 변경(이터 diff 100줄 이상 또는 관여 수용기준 2개 이상)이면 완료 결정 전 세 적대 렌즈(contrarian·minimalist·constraint-auditor — 정의는 spec 스킬의 페르소나 카탈로그를 복제 없이 참조)로 점검. 렌즈는 발견만 보고하고 결정은 워커가 한다. 4-Level·Self-Review를 약화하지 않고 가산.
- **근본 원인 추구 4 Phase**: 조사(에러·재현·최근 변경·계층 격리·데이터 역추적) → 패턴 분석(작동 예제와의 차이) → 단일 가설·최소 검증 → 실패 테스트 먼저 쓰고 단일 fix. fix 3회 실패면 조기 정지. 우회 불가피 시 `fix:symptom`으로 분류하고 증상·미규명 범위·우회·후속 조사 정보를 기록.
- **조기 정지(워커 판단)**: 같은 에러 3회, 변경량 진동, 지표 trade-off, scope 밖 수정 필요, 수용 기준 해석 흔들림, 동일 영역 fix 3회 실패. 진전의 정의는 테스트 통과·에러 신호 변화·root cause 이해 갱신.
- **측면사고 회복**: 워커-판단 정체로 차단하기 직전, 에피소드당 **정확히 1회** 적대 렌즈로 root cause 가설을 재구성해 최소 변경 1회를 재시도한다. 진전이면 정상 루프, 무진전이면 표준 차단. 안전 직결 정지(scope 이탈·테스트 약화·비밀 노출·평가 기준 편집)는 회복 없이 즉시 차단. 시도·판정은 노트에 기록.
- **절대 금지**: 평가·수용 기준·CI·품질 게이트 수정, 테스트 삭제·skip·약화, 설계·명세 문서 수정, scope 밖 수정, 새 의존성 임의 추가, 보안·권한·과금 영역 수정.
- **에스컬레이션**: 트리거(모호/상충 기준, scope 밖, architecture 변경, 평가 기준 오류, 조기 정지, 금지 위반 필요, 보안·권한·과금) 시 차단 신호 생성(작업·이터·트리거·현재 상태·문제·시도·가설·필요 결정 포함) 후 추가 작업 금지.
- **노트 운영**: 이터 시작 시 계획→최근 메모→인계→git log 순으로 읽고, 종료 시 인계 메모→DoD 갱신→Self-Review→분류 커밋→신호 판정 순으로 처리. 실패한 접근의 무근거 재시도 금지.
- **이터 내 위임**: 보조 에이전트는 독립 검토·가설 검증에만 쓰고(스펙 부합 검증, 코드 품질 검토, 적대 렌즈 점검, 측면사고 재구성, 병렬 가설 검증의 표준 brief 제공), 핵심 결정·합성·patch 작성은 메인 책임. 위임 brief는 자기완결이어야 한다.

### 상태·관찰 명령

- `status [<spec-path>]`: 인자가 있으면 해당 스펙 한 줄, 없으면(또는 `list`) 저장소 작업트리를 스캔해 전체 실행을 열거한다(중앙 registry 없는 best-effort 열거). 표 컬럼: KEY(12자 키) · STATE · FILES(신호 디렉토리 파일명 그대로, 쉼표 구분) · ITERS(이터 로그 수) · LAST-UPDATE(최신 이터 로그 시각, UTC) · SPEC(스펙 경로). STATE 값: `running`(드라이버 또는 워커 활성 — orphan 포함) · `stale`(lock 있으나 모두 비활성) · `terminal`(신호 디렉토리 비어있지 않음) · `idle`(그 외).
- `status --json [<spec-path>]`: 기계 판독용 구조화 출력. 단일 스펙이면 JSON object 1줄(기록 없으면 `state:"absent"`), 전체면 JSON array 1줄(없으면 `[]`). 필드는 `key`/`state`/`signals`(파일명 배열, raw fact)/`iters`/`last`/`spec`. 호출 레이어는 컬럼 위치·부분 문자열 일치에 의존하지 않고 `signals` 배열에서 자기 신호 이름을 **정확 일치 멤버십**으로 찾는다.
- `logs <spec-path> [--iter N]`: N 지정 시 해당 이터 로그 본문, 미지정 시 노트 전문 + 이터 로그 목록 + 신호 파일들의 본문 dump(의미 해석 없이 그대로).
- `paths <spec-path>`: 해당 스펙의 계산된 경로(스펙·스펙 디렉토리·작업 공간·메타 영역·lock)와 작업 공간 경로의 출처(기록 메타/기본값)를 출력하는 단일 출처. 진단·문서 교차 검증용.
- `env` / `gates` / `deps`: 각각 환경 변수와 기본값, 객관 게이트 목록과 frontmatter override, 필수·선택 의존성과 현재 설치 상태를 self-emit하는 단일 출처. 지침 문서는 이를 중복 열거하지 않고 가리킨다.

### 정지·정리

- `stop <spec-path>`: 워커 프로세스 트리(드라이버·자식·자손, orphan 포함)를 종료 전 스냅샷해 완결 종료한다 — 정상 종료 요청 후 대기, 미종료분은 강제 종료로 에스컬레이션. **전 프로세스 사망을 확인한 후에만** lock을 해제하고 정상 정지를 선언한다. 생존 프로세스가 남으면 lock을 유지한 채 0이 아닌 코드로 실패를 보고하고 수동 조치를 안내한다(생존 중 "정상 정지" 선언 금지). 작업 공간은 유지한다. 활성 실행이 없으면 오류, stale이면 lock 메타만 정리한다.
- `cleanup <spec-path> [--force]`: 신호 디렉토리가 비어 있지 않음을 확인한 후 워크트리와 lock·메타를 제거한다. 실행 중이거나 신호가 비어 있으면 거부하며 `--force`로만 강제(실행 중이면 워커 트리 강제 종료 후 정리). 작업 공간 경로가 전용 워크트리 형식이 아니면 안전을 위해 거부한다.
- 드라이버가 SIGTERM/SIGINT를 받으면 워커 트리를 완결 종료하고 exit 130으로 종료한다(orphan 방지).

### 차단 처리 (호출자 운영 절차)

- 차단 해제의 정식 절차: 신호 파일 본문을 읽고 원인을 보정한 뒤 그 파일을 삭제하고 재시작.
- category별 운영 조치: `config-gap`(도구·자격증명·환경 변수 보정 후 재시작) · `spec-gap`(스펙 보정 후 재시작) · `architecture-gap`(본 실행 정지, 별도 architecture 작업 후 scope 조정 또는 정리 후 새 실행) · `environment-gap`(일시 문제면 대기 후 재시작, 영구면 대역/스펙 조정) · `other`(본문 직접 판단).
- 드라이버 halt(게이트 위반·비정상 종료 streak)는 차단 신호를 만들지 않는다 — 진단은 최근 이터 로그, 미커밋 변경은 stash 목록에서 복구, 스펙·노트 보정 후 재시작.

## ④ 인터페이스 (호출 형태·입력·출력·산출물)

### 호출 형태

`Skill(skill="loop", args="<subcommand> [<args>]")`. 스킬은 명시된 subcommand만 실행하며 다른 subcommand를 자동 추론하지 않고, subcommand의 exit code를 그대로 던지지 않고 사용자에게 요약한다.

| subcommand | 인자·플래그 | 역할 |
|---|---|---|
| `start` | `<spec-path> [--max-iterations N] [--wall-clock-minutes N]` | 검증→lock→작업 공간 준비→이터 루프(포그라운드) |
| `status` | `[--json] [<spec-path>]` | 상태 조회(없으면 전체) |
| `stop` | `<spec-path>` | 실행 정지(작업 공간 유지) |
| `list` | — | 전체 실행 열거 |
| `cleanup` | `<spec-path> [--force]` | terminal 후 작업 공간 정리 |
| `logs` | `<spec-path> [--iter N]` | 노트·이터 로그·신호 본문 조회 |
| `env` / `gates` / `paths <spec-path>` / `deps` | — | 환경 변수·게이트·경로·의존성 self-emit |

### 입력

- 스펙 파일 경로(임의 도구가 만든 임의 스펙 수용 — 단 git 저장소 안에 있어야 함).
- SPEC frontmatter(드라이버가 읽는 필드): `scope.include`/`scope.exclude`(scope 게이트), `test_paths`(테스트 식별 override), `test_sweep_paths`(테스트 정리 화이트리스트).
- 환경 변수: 이터 상한(기본 30) · 시간 상한(기본 120분) · 비정상 종료 연속 허용(기본 3). 플래그가 환경 변수보다 우선.

### 출력·산출물

- 스펙 디렉토리: lock 파일(실행 중에만), 작업 공간 경로 메타, 워커 PID 메타(orphan 감지용).
- 작업 공간(`<spec_dir>/.worktree`): 헌법 사본 `CLAUDE.md`, `.loop/`(기준 커밋·스펙 경로 메타·`notes.md`·`iterations/<n>.log`·`signals/`), 그리고 워커의 코드 변경 커밋들(detached HEAD 위).
- 종료 코드 계약: `0` 정상 종료(신호 디렉토리 비어있지 않음 — 워커 terminal 의도) · `1` halt(게이트 위반·비정상 streak·환경/lock 오류) · `2` 사용법 오류 · `130` 시그널 종료.
- 신호 의미(DONE/BLOCKED/category)는 워커·호출자 컨벤션이며 드라이버 출력은 raw fact만 담는다.
- 작업 공간·lock·신호 외의 파일은 만들지 않는다.

## ⑤ 비기능 요구사항·제약

- **보안**: 루프는 무인 동작을 위해 권한 확인을 생략한 에이전트 실행을 사용한다. 따라서 작업 공간에 secrets·자격증명·SSH key를 두지 않고, 스펙에 secrets를 쓰지 않으며, 신뢰하지 못한 외부 스펙은 받지 않는다.
- **격리·무브랜치**: 작업은 전용 detached HEAD 워크트리 안에서만 일어나고 메인 작업트리·브랜치 네임스페이스를 오염시키지 않는다. 런타임 메타는 git 추적에서 제외된다.
- **결정 경계**: 드라이버는 기계적 판정(프로세스·해시·패턴 비교)만 하고 의미 판단(신호 해석·스펙 품질)을 하지 않는다. 이 비대칭이 워커 컨벤션의 단일 출처를 헌법에 유지시킨다.
- **강건성**: stale lock 자동 정리, orphan 워커 감지·보호, 어느 cwd에서 호출해도 동일 작업 공간 해석, 정지 시 거짓 성공 금지(사망 미확인이면 실패 보고).
- **의존성**: 필수 — bash·git·YAML 파서·에이전트 CLI·sha256 해시 유틸. 선택 — secret 스캐너(설치 시에만 해당 게이트 활성화). 설치 상태는 self-emit 명령으로 확인 가능해야 한다.
- **이식성**: macOS·Linux 양쪽에서 동작(도구 가용성 차이를 폴백으로 흡수).
- **프로젝트별 헌법 override는 미지원**(명시적 제약).

## ⑥ 비-목표 (Out of scope)

- SPEC 작성·품질 검증 — spec 스킬과 호출자의 책임. 드라이버는 스펙 내용을 검사하지 않는다.
- 구현 후 통합·PR 생성·리뷰·머지 — 호출 레이어(execute-task 등)의 책임. loop은 작업 공간 보존과 신호 노출까지만 한다.
- 다중 SPEC 오케스트레이션·의존성 해제·동시성 관리 — workflow-task의 책임.
- 신호 파일의 의미 해석 — 워커·호출자 컨벤션(드라이버는 비었는지만 판정).
- 원격 상태(이슈·브랜치 push·PR) 생성.
- 프로젝트별 헌법 커스터마이징.

## ⑦ 성공 기준

- 스펙 경로 하나로 시작한 실행이 사람 개입 없이 완료(DONE)·차단(BLOCKED)·기계적 정지(halt) 중 하나로 끝나고, 그 결과가 디스크 아티팩트(신호·노트·로그·커밋)만으로 판별 가능하다.
- 객관 게이트가 폭주를 차단한다: scope 밖 변경·기존 테스트 약화·의존성 변경·suppressor 추가·secrets·증상 땜질 연속·진동·상한 초과가 발생한 이터에서 루프가 즉시 정지하고 미커밋 변경이 보존(stash)된다.
- 동일 스펙의 동시 실행이 불가능하고(lock), 정지·정리 후 메인 작업트리와 브랜치 네임스페이스에 잔류물이 없다.
- 호출 레이어가 `status --json`만으로(텍스트 파싱 없이) 실행 상태와 신호를 정확히 판정할 수 있다.
- 차단 신호 본문에 호출자가 다음 행동(category별 보정→신호 삭제→재시작)을 결정할 정보가 충분히 담긴다.
- 매 이터가 새 프로세스임에도 노트·git history만으로 작업 연속성이 유지된다(실패 접근의 무한 반복 없음).
